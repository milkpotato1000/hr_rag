# 청킹을 바꾸면 모델이 읽는 원문은 어떻게 달라질까?

규정집에 “생일 특별휴가를 신청하면 누구의 승인을 받아야 하나요?”라고 묻고 청킹 방식만 바꿨습니다. 두 실행 모두 BM25, 리랭커 끔, 최종 5개, 예산 4,000자, 청크 최대 400자·겹침 80자입니다. 원문 파싱과 검색은 실제 설치 패키지를 사용했고, 이 두 답변은 시험 어댑터가 생성한 합성 예시입니다.

| | 고정 청킹 | 재귀 청킹 |
| --- | --- | --- |
| BD-03 승인 문장이 처음 전달된 순위 | 1위 | 1위 |
| 해당 청크의 원문 문자 범위 | [640, 1040) | [513, 851) |
| 해당 청크가 걸친 페이지 | 1~2쪽 | 1쪽 |
| 저장된 합성 답변 | 합성 예시 · 팀장 | 합성 예시 · 팀장 |

두 청크에는 모두 “팀장의 승인을 받아야 한다”가 들어 있습니다. 고정 청크는 다음 페이지의 BD-04까지 포함합니다. 이번 질문에서는 경계가 달라져도 필수 근거 순위가 유지됐습니다. [양쪽 전달 문맥과 인용 전문](fixture-comparison.json)

과거 실제 실행 S8과 S11도 새 설치본으로 열었습니다. 같은 PDF에서 S8은 신청 기한에 “3영업일 전”, S11은 승인권자에 “팀장”이라고 답했습니다. 청킹·검색·리랭커와 질문이 함께 바뀌어 답변 차이를 특정 설정 효과로 해석할 수 없습니다. [두 실제 답변 재생](historical-comparison.json)

## 설치 검증

새 venv의 wheel에서 CLI 비교 결과와 Python 재생 결과가 일치했습니다. 비교 전후 네 입력 폴더의 모든 파일 해시가 같았습니다. 브라우저에서 두 합성 실행과 두 실제 실행을 각각 선택해 변경 항목·원문 범위·답변을 확인했습니다. 같은 비교를 다시 열 때 결과가 같았고 서버 작업 수는 0이었습니다. 미등록 ID는 unknown_artifact, 변경된 파일은 stale_file_hash로 거부했습니다. 부분 실패·미실행·여러 설정 변경과 기존 단일 재생·생성 모델 비교도 검사했습니다. 추가 실제 모델 호출은 0회입니다.
