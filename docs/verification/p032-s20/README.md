# Codex와 Claude Code의 첫 PDF 검색 실습

새 dev 체크아웃에서 README의 공통 명령을 실행했습니다. Python 3.13.15가 빌드 도구와 PDF 리더를 전용 가상환경에 설치했고, 설치된 패키지의 출처 기록과 빌드한 wheel의 경로·SHA-256이 일치했습니다. 복제는 이 Mac의 dev Git 저장소에서 했습니다. 설치 검증에서는 lock의 해시와 일치하는 의존성 wheel을 준비해 오프라인으로 사용했습니다. [소스 SHA](setup.json) · [wheel 설치 출처](wheel-origin.json)

**“생일 특별휴가는 사용 며칠 전까지 신청해야 하나요?”**에 대한 BM25 전달 청크는 5개였습니다. 2위 청크의 PDF 1쪽 BD-03에서 다음 문장을 확인했습니다.

> 생일 특별휴가는 사용 3영업일 전까지 휴가 시스템에서 신청하고 팀장의 승인을 받아야 한다.

결과는 검색된 원문이며 모델 생성 호출은 0회였습니다. 같은 소스로 기존 수동 설치·PDF 검색 명령도 실행했고 다섯 청크의 본문·순위·페이지가 일치했습니다. 이어서 설치된 CLI로 로컬 모델 설정과 BM25 검색 구성을 만들고 통합 미리보기까지 확인했습니다. [첫 실행 출력](installed.log) · [전달 청크와 수동 경로 대조](verified.json)

공백이 있는 경로에서 정상 설치했습니다. 기존 출력 폴더를 다시 지정하면 결과와 PDF를 보존한 채 중단했습니다. 첫 시험에서 기존 pip 환경이 빈 wheel 폴더에 의존성을 보충하는 동작을 발견해 명시적 오프라인 모드의 pip 설정을 격리했습니다. 수정 후 빈 폴더 시험은 빌드 의존성 단계에서 실패했고, 올바른 wheel 폴더와 새 출력 이름으로 같은 근거를 재현했습니다. 실패 기록도 원래 위치에 보존됐습니다.

Codex CLI 0.160.1과 Claude Code 2.1.332는 각각 version/help를 실행했습니다. 두 도구에 줄 요청 문구가 동일한지 확인하고 그 공통 절차를 직접 실행했습니다. 각 제품에서 로그인 후 프롬프트를 보내는 대화형 세션은 이번 검증 범위 밖입니다. [도구별 확인 기록](tool-checks.json) · [두 요청과 실행 방법](../../../README.md#codex-또는-claude-code로-첫-검색하기)
