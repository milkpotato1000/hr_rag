# BD-03을 장·절·조항 경로로 찾기

대상 질문은 “생일 특별휴가는 사용 며칠 전까지 신청해야 하나요?”였다. 같은 PDF·400자·겹침 80자·BM25 후보 상한 20·최종 5·예산 4,000자에서 두 방식 모두 **신청 기한과 승인 요건을 함께 담은 문장을 1위로 전달**했다.

| 항목 | 기존 구조 설정 | 규정집 계층 프로필 |
| --- | --- | --- |
| 전체 청크 | 155 | 177 |
| 인식된 제목 | 목차 6개와 본문 장 6개 | 본문 장 6개, 절 15개, 조항 57개 |
| 1위 청크의 정규화 원문 범위 | [433, 810) | [668, 961) |
| BD-03의 제목 경로 | 제1장 | 제1장 생일 특별휴가와 포인트의 구분 [BD] → 제1절 적용 기준 [BD-S1] → BD-03 신청 기한과 승인 |
| PDF 1쪽 신청 기한·승인 문장 [684, 734) | 완전 포함 | 완전 포함 |

규정집 프로필의 1위 청크는 BD-03 제목 줄에서 시작한다. 목차는 원문에 남고 제목 경로는 비어 있다. 새 프로필로 검색 순위는 같았고, 읽는 사람이 해당 근거의 소속 절과 조항을 확인할 수 있게 됐다. 제목 경로는 메타데이터이며 모든 청크 본문과 페이지별 문자 범위를 원문과 대조했다.

2만 자 조항과 5만 자 절을 포함한 합성 문서에서 기준 구간의 연속성, 400자 상한, 최대 80자 겹침, 제목 경계에서 겹침 차단을 검사했다. 문서와 장이 바뀔 때 경로가 초기화되는지, 제목이 없는 문서의 재귀 분할, 참조 문장과 목차 중복도 확인했다. 새 설치본에서 이전 S6의 세 저장 산출물을 재생했고, 기본 설정으로 다시 만든 청크 본문·위치·ID가 기존 결과와 일치했다. 24개 회귀 시험이 통과했다. 실습에 사용한 모델 호출은 0회다.

브라우저에서 ‘structure · 규정집 계층’을 선택해 PDF snapshot으로 청크를 만들었다. BD-03의 3단계 제목 경로와 293자 길이를 확인했고 ‘원문 보기’에서 1쪽의 정규화 위치 668로 이동했다.
