# 검색 설정 하나씩 바꾸기

설치 실습 폴더에서 `rag-lab pipeline-setup`으로 generation-setup의 모델 프로필, 청킹과 검색 방식을 선택합니다. 출력된 pipeline_preview 명령은 실행 계획을 보여주고, serve 명령은 ‘문서에서 답변까지’에 해당 설정을 미리 선택합니다. [설치본의 예제 명령](../../../rag_package/resources/sample/HANDBOOK.md#신청-기한의-근거는-몇-위에-들어올까)

| 검색 | 임베딩 | 리랭커 |
| --- | --- | --- |
| BM25 | 사용 안 함 | 끔 |
| Dense | E5-small | 끔 |
| Hybrid RRF | E5-small | 끔 |
| Hybrid RRF | BGE-M3 | 끔 |
| Hybrid RRF | BGE-M3 | mMiniLM |
| Hybrid RRF | BGE-M3 | BGE 리랭커 v2-m3 |

배포 wheel을 별도 가상환경에 설치한 뒤 같은 PDF·승인권자 질문·handbook-v1 400/80·후보 12개·최종 3개·예산 1,700자로 여섯 구성을 검사했습니다. 기존 실험에서 준비한 네 모델의 실제 파일과 저장된 해시를 대조했습니다. 서버에서 만든 여섯 UI 미리보기의 전체 계획이 각각 설치 CLI 결과와 일치했고, 원래 생성 프로필과 입력 모델 프로필은 보존됐습니다. 검색 구성만 달라지는 여섯 경우에 같은 생성 프로필을 사용합니다. [모델과 revision·설정별 결과](verified.json)

브라우저에서는 Hybrid RRF·BGE-M3·mMiniLM이 선택된 화면을 확인했습니다. 후보 12개·최종 3개·1,700자가 표시됐고 미리보기의 전송 여부는 false였습니다. 검색·리랭커 역할을 뒤바꾼 입력, 미준비 프로필, 후보 수보다 큰 K, 예산 0, 기존 출력 폴더는 거부했습니다. 공백이 있는 경로와 기존 직접 작성 설정도 검사했습니다. [검증 코드](practice.py) · [회귀 결과](regression.log)

이번 검증의 모델 추론·다운로드·유료 호출은 0회입니다. 실제 근거 순위 변화는 [S4 검색과 리랭킹 실측](../p032-s4/README.md), 두 실행의 해석 방법은 [S12 저장 실행 비교](../p032-s12/README.md), 같은 질문에 대한 실답변과 근거는 [S13 고정·재귀 비교](../p032-s13/README.md)에서 확인할 수 있습니다.
