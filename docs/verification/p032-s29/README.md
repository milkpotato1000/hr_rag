# 선택 API로 보낸 질문과 저장된 인용 확인하기

“생일 특별휴가를 신청하면 누구의 승인을 받아야 하나요?”를 동일한 규정집과 BM25 상위 5개 청크로 두 번 실행했다. 독립 설치한 CLI가 실제 HTTPS 요청을 전송했고, 로컬 시험 서버가 받은 청크 ID를 인용해 고정 답변 “팀장”을 반환했다.

| 확인 항목 | OpenAI Chat 형식 | Anthropic Messages 형식 |
| --- | --- | --- |
| 요청 경로 | /v1/chat/completions | /v1/messages |
| 시스템 지시 | messages의 system 역할 | 별도 system 필드 |
| 정상 실행 | POST 1회, 인용 1개 저장 | POST 1회, 인용 1개 저장 |
| 시험 서버가 지정한 입력/출력 토큰 | 111 / 12 | 108 / 13 |
| 키 누락 | 전송 0회, missing_api_key | 전송 0회, missing_api_key |
| 인증 거부 | 전송 1회, http_401 | 전송 1회, http_401 |

각 요청에서 모델명과 인증 방식, 사용자 메시지, 문맥 전체를 대조했다. 인용된 청크는 1~2쪽에 걸치지만 “생일 특별휴가는 사용 3영업일 전까지 휴가 시스템에서 신청하고 팀장의 승인을 받아야 한다.”라는 문장 전체의 위치는 1쪽이다. 두 API 결과와 기존 Qwen 4B 저장 결과에서 질문·청크 순서·원문·답변·인용이 일치했다. 미리보기, 저장 결과 재열기, 결과 비교의 추가 전송은 모두 0회였다.

임시 인증서를 시험용 CLI 프로세스에만 신뢰하도록 지정했다. 더미 인증값이 저장 파일에 없는지 확인하고 시험용 개인 키를 폐기했다. 실제 공급자의 계정 접근권·요금·답변 품질은 미측정이다. [요청별 관측과 원문 인용](verified.json) · [설치본 회귀 시험 18개](installed-regression.log)

사용할 모델 ID와 키 환경변수 이름으로 프로필을 만든 뒤 같은 입력에서 미리보기 → 명시 실행 → 저장 재열기를 따라갈 수 있다. [설치 사용자용 명령](../../../rag_package/resources/sample/HANDBOOK.md#답변-모델을-고르고-규정집으로-미리보기)
