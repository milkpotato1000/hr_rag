# 규정집 1쪽의 신청 기한은 어디에서 끊겼나?

“생일 특별휴가는 사용 며칠 전까지 신청해야 하나요?”를 같은 BM25 설정으로 검색했다. 세 방식 모두 1위에 신청 기한이 있었다. 차이는 그 다음에 나오는 **팀장 승인까지 한 청크에서 읽을 수 있는지**였다.

| 청킹 방식 | 전체 청크 | 기한 구절 첫 순위 | 승인까지 한 문장인 첫 순위 | 해당 청크의 원문 범위 | 최종 5개에 완전한 문장 포함 |
| --- | ---: | ---: | ---: | --- | --- |
| 고정 | 121 | 1 | 2 | [640, 1040) | 예 |
| 재귀 | 147 | 1 | 1 | [513, 851) | 예 |
| 구조 | 155 | 1 | 1 | [433, 810) | 예 |

**원문 기준**은 PDF 1쪽 BD-03의 “생일 특별휴가는 사용 3영업일 전까지 휴가 시스템에서 신청하고 팀장의 승인을 받아야 한다.”이다. 추출한 원문의 문자 위치에서 신청 기한과 행위는 [684, 716), 전체 문장은 [684, 734)다. 바로 앞에는 ‘BD-03 신청 기한과 승인’, 바로 뒤에는 ‘접수 확인과 승인 통지를 별도 상태로 표시한다’가 있다. [고정한 원문 구간](target.json)

고정 방식의 1위 청크 [320, 720)는 “신청하고 팀”에서 끝난다. 80자 오버랩 덕분에 2위 청크가 640에서 다시 시작해 문장 전체를 담았다. 재귀와 구조에서는 1위 청크 하나에 두 조건이 들어갔다. 이번 질문은 세 방식 모두 청크 둘을 이어 붙일 필요가 없었다. 후보 상한은 20개, 전달 상한은 5개·4,000자였다. [청크별 경계·주변 원문·순위·페이지](boundaries.json)

**구조 방식의 제목 인식**도 확인했다. 감지한 12개는 목차의 ‘제1장’~‘제6장’과 본문의 같은 6개 장 제목이다. 원문에서 ‘제…절’로 시작하는 15개 줄과 ‘BD-03’은 제목 경로에 들어가지 않았다. 구조 방식이 장 단위 경계를 바꾼 결과 재귀와 전체 분할이 달랐다. BD-03 전체 문장이 1위였다는 한 사례로 다른 조항에서도 같은 성능을 기대할 수는 없다.

## 재현과 확인

새 wheel을 독립 환경에 설치해 init 샘플과 고정된 PDF reader로 snapshot을 만들었다. 설치된 HANDBOOK의 셸 명령을 그대로 실행하고, 저장 결과로 재생한 HTML과 비교 JSON을 확인했다. 브라우저에서도 세 청크를 선택하고 같은 질문으로 ‘저장 청크 비교 · 답변 미리보기’를 눌러 fixed·recursive·structure의 preview 3행을 확인했다. 청킹·검색·생성 모델 호출은 모두 0회였다. 청킹 회귀 19건, 설치 리소스 회귀 3건이 통과했다.
