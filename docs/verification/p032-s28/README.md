# 원문 한 벌로 두 가지 청킹 후보 비교하기

교육휴가 PDF 1쪽의 추출 원문 202자를 여섯 단위로 나눴다. 기존 방식은 후보마다 원문을 한 벌씩 보냈다. 새 옵션은 원문을 한 번 보내고 각 후보의 마지막 단위 번호만 제시한다. 설치본에서 두 후보를 복원하고 조각마다 원문의 문자 위치와 텍스트가 이전 실험과 같은지 대조했다.

| 후보 | 마지막 단위 번호 | 두 청크의 원문 범위 | 제1조가 나뉘는 방식 |
| --- | --- | --- | --- |
| 1 | 3, 6 | [0, 141), [141, 202) | 신청 대상 제목과 연 1일 규정이 첫 청크에 함께 들어간다. |
| 2 | 2, 6 | [0, 103), [103, 202) | 제목은 첫 청크에, 대상과 연간 일수는 둘째 청크에 들어간다. |

각 후보의 ID와 순서, 시스템 지시, 허용 출력 ID(enum), 모델 digest, thinking, seed, 출력 상한은 동일하다. 바뀐 것은 사용자 메시지의 원문 표현이다. 위 표의 제1조 해석은 모델 입력에 넣지 않았다. [실제 입력·후보별 복원 원문](frozen.json)

## Qwen 4B 실측

| 입력 방식 | 사용자 메시지 UTF-8 바이트 | 모델이 보고한 입력 토큰 | 출력 토큰 | 유효한 선택 |
| --- | ---: | ---: | ---: | --- |
| 이전 · 후보별 원문 | 1,015 | 435 | 4,096 | 없음 · 잘림 |
| 이번 · 원문 한 벌과 경계 번호 | 655 | 297 | 4,096 | 없음 · 잘림 |

새 입력에서 모델이 읽은 토큰은 138개 줄었다. 이번 호출도 출력 상한에 도달해 완결된 후보 ID를 얻지 못했다. 내부에서 어떤 내용에 토큰을 썼는지는 이 기록으로 알 수 없다. 실제 선택 청크가 없어 제목·본문 보존과 BM25 전달 순위의 사후 검증은 미실행이다. 요청 1회, 재시도 0회이며 모델 언로드와 소유 서버 종료를 확인했다. [실제 응답 요약](review.json) · [기존 실행](../p032-s18/review.json)
