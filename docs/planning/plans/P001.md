# P001 — 합성 HR 문서와 검색 평가 기반 구축

> 준비: 준비 완료
> 실행: 미착수
> 우선순위: 10
> 선행: 없음
> 승인 근거: 2026-10-22 사용자 지정 HR RAG 기획 대화 + AGENTS.md의 plan 준비 검토·dev 등록 위임 + 본 카드 기획 준비 검토

## 목적

Dense·BM25·Hybrid·reranker를 같은 정답으로 비교할 수 있도록, 외부 서비스 없이 재현 가능한 합성 HR 문서와 검색 평가 계약을 먼저 구현한다. 제품 방향은 [프로젝트 기획](../project-brief.md)을 따른다.

## 기획 준비

공유 대화의 검색 비교와 근거 없는 질문 평가를 첫 독립 작업으로 구체화했다. 입력·출력, 실패 정책, 독립 기대값, 완료 조건을 아래에 고정한다. 실제 HR 데이터·모델·계정·GPU 선택 없이 수행 가능하고 선행 작업이 없어 plan이 준비 완료로 등록한다. 문서 개수와 스키마, CLI 경로는 이 카드에서 정한 초기 구현 계약이다.

## 범위와 계약

Python 3.9 이상과 표준 라이브러리만으로 로컬 평가 CLI 및 테스트를 만든다. 모델 추론과 검색 엔진 구현, 네트워크 접근, 의존 패키지 설치는 범위에 포함하지 않는다.

1. `data/synthetic/chunks.jsonl`: 적어도 12개의 독립 청크. 필드는 `chunk_id`, `document_id`, `version`, `title`, `text`, `source`, `synthetic`이다. ID·버전·본문·제목은 비어 있지 않은 문자열이고 `synthetic`은 true, `source`는 `synthetic://`로 시작한다. 생일 휴가, 연차, 재택근무 등 최소 3개 주제와 혼동 가능한 비관련 근거를 포함하고 모두 가상 규정임을 명시한다. 파일 전체가 고정된 첫 corpus 버전이며 다중 유효 버전 처리는 후속 작업이다.
2. `data/synthetic/queries.jsonl`: 적어도 10개 질문. `query_id`, `question`, `answerability`(answerable 또는 unanswerable), `relevance`(청크 ID에서 0~3 정수로의 매핑)를 가진다. 최소 2개는 근거 없음 질문이다. 답할 수 있는 질문은 관련성 1 이상인 근거가 있고, 근거 없음 질문의 매핑은 비어 있다. 생일 휴가의 조건 질문과 여러 근거가 필요한 질문을 포함한다.
3. 검색 순위 입력은 `query_id`, 순서가 있는 고유 `chunk_ids` 목록의 JSONL이다. corpus·질문 ID 중복, 존재하지 않는 참조, 잘못된 필드 타입과 등급(불리언 포함), 중복 순위 ID, 질문 누락·중복·알 수 없는 질문, 빈 파일·잘못된 JSON은 오류다. 실패는 stderr와 nonzero exit로 알리며 결과 파일을 남기지 않거나 기존 결과를 보존한다. 정상 입력의 빈 검색 목록은 허용한다.
4. `python3 scripts/evaluate_retrieval.py --chunks data/synthetic/chunks.jsonl --queries data/synthetic/queries.jsonl --rankings <경로> --k 5 10 20 --output <경로>`가 query별 및 macro 평균 Recall@K·Precision@K·MRR@K·nDCG@K를 JSON으로 출력한다. K는 양의 고유 정수다. 반환 순위가 K보다 짧으면 부족분은 비관련으로 취급하고 Precision 분모는 K를 유지한다. 관련성 1 이상을 relevant로 보고 MRR은 top K 첫 relevant의 역수, 미검색은 0이다. nDCG는 gain `2**rel - 1`, discount `log2(rank+1)`, 전체 qrels의 이상 순위 top K로 정규화한다.
5. unanswerable은 위 네 검색 지표의 query별 값 null로 기록하고 macro 평균에서 제외한다. 별도로 질문 수, 검색 결과가 있는 비율, 빈 결과 비율을 보고하며 이를 답변 보류 정확도로 부르지 않는다. answerable이 0개인 입력은 허용하고 macro 지표를 null로 출력한다.
6. 결과에 corpus·질문·순위 파일의 SHA-256, K, 평가기 버전, answerable/unanswerable 분모를 포함한다. 같은 입력에는 같은 지표가 나온다. 타임스탬프 등 비결정 필드가 필요하면 지표와 분리한다. 원문 수정 시 hash가 바뀌고 존재하지 않는 청크 참조는 검출된다.

## 검증 계획

`python3 -m unittest discover -s tests -v`로 네트워크 없이 검증한다. 구현 함수를 재사용해 기대값을 만들지 않는다. 예를 들어 관련성 `{a:3,b:1}`와 순위 `[x,b,a]`, K=2에서 Recall=0.5, Precision=0.5, MRR=0.5, nDCG=`(1/log2(3))/(7+1/log2(3))`이다. 같은 예의 K=5에서는 Recall=1, Precision=0.4, MRR=0.5, nDCG=`(1/log2(3)+7/log2(4))/(7+1/log2(3))`이다.

빈 순위, K보다 짧은 순위, 관련 문서가 첫 번째·K번째·K밖인 경우, 복수 등급, 근거 없음만 있는 입력, JSON/타입/참조 오류를 검증한다. 같은 fixture를 두 번 실행해 결과를 비교하고 수정한 corpus의 hash 변화를 확인한다. 실패 경로에서 기존 결과 파일을 덮어쓰지 않는지 검사한다.

평가 CLI 사용법과 데이터 스키마를 README 또는 개발 문서에 기록한다. 테스트 명령·실제 출력·CLI 결과·실패 사례는 `docs/verification/p001/`에 저장하며, 실패 후 수정은 기존 실패 기록을 남기고 재검증한다. 계약 검사와 큐를 함께 확인한다.
