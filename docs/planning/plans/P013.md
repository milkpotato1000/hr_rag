# P013 — Project B 내부 기본 LLM 답변 평가기와 검증 정답

> 준비: 초안
> 실행: 미착수
> 우선순위: 68
> 선행: P007, P019, P021, P022, P023
> 승인 근거: 2026-10-29 사용자 Project B 설계 제공 및 별도 모듈 계획 반영 요청. 2026-10-29 후속 요청으로 P016 원문 재작성 → P007 청킹 실험 이후 기본 평가기를 수행하도록 순서 정정. 상세 실행 계약 준비 전.

## 목적과 외부 선행

2026-11-05 후속 정책은 [P023](P023.md)으로 선행한다. 질문10개·기존57개를 필수38/보충19로 구분하고 [질문 범위별 채점 정책](../specs/P023-scoring-policy.md)을 적용한다. 핵심 Correctness P/R/F1은 필수 정답과 핵심 범위 생성으로 계산하고, 허용된 참 보충은 분모/가산에서 제외한다. 전체 생성 사실에 대한 Faithfulness/Neutral/Contradiction rate는 그대로 유지하며 추가 사실 오류·미확정·관련성 문제를 별도로 표시한다. 구체 분모/일대일 매칭/0분모/보류/고정 예시는 해당 정책을 따른다. 기존 전부 필수 reference 채점 초안과 다른 부분은 이 정책이 우선이며 P013은DRAFT다. 새 run004의 버전/hash와 실제 정답 승인·나머지 준비 게이트 확인 후 착수한다. gt01 기존5개 사람 승인/판단 위임을 새 전체 사람 승인으로 확대하지 않는다.

2026-11-04 사용자 보고서 개선/중복 정리 요청을 [P021](P021.md)로 선행한다. run001의 사람 미승인 상태를 유지하며, P021 개정 패킷의 실제 검토·승인 후 정답 입력을 고정한다. 기존 패킷 승인 요청을 개정본 승인으로 자동 이전하지 않는다.

2026-11-05 사용자 원자화 결정은 후속 [P022](P022.md)로 반영한다. gt01-c02의3분리와 전체 후보 전수 검수에서 분리10개·조건 복원2개·유지33개를 확인했으며 새 후보 제안은57개다. P021의45개 병합 계약/이력은 보존한다. P022의 새 검토본·구신ID/근거 매핑을 인계받고 그 버전의 실제 사람 승인 후 P013 정답을 고정한다. 현재 run002 승인이나 개정 실행 완료로 해석하지 않는다.

2026-11-04 후속 결정: 정답 후보의 작성자는 Codex로 정하고 원문 기반 작성 → 사람 검토·명시 승인 → 버전 고정으로 진행한다. Qwen 정답 초안 생성을 필수 단계에서 제외한다. Qwen3-8B의 Claim Extraction 성능은 고정 답변·별도 기대 클레임을 사용하는 독립 검증으로 분리한다. 기존 P019/P021 패킷과 Qwen 이력은 보존하며 이 결정은 그 후보의 자동 승인이나 작성자 소급 변경을 뜻하지 않는다. [분리 검증 계약 초안](../specs/P013-claim-extraction-validation-draft.md)을 따른다.

2026-10-30 연속 진행 요청: [P019](P019.md)에서 평가 모델 사전검증과 사람 검토용 정답/판정 초안을 먼저 마련한다. P019 완료는 사람 승인이나 P013 READY를 대신하지 않는다. 이 자료의 실제 사람 승인과 상세 실행 계약 확정 후 본 카드를 준비 완료로 전환한다.

RAG가 저장한 최종 답변·실제 전달 문맥을 별도 모듈에서 평가한다. Claim Extraction 결과를 공통 사용해 LLM Faithfulness와 승인 Ground Truth 기반 Answer Correctness(Factual P/R/F1)를 계산한다. [B 내부 평가 모듈 설계](../../architecture/project-b-generation-evaluation.md)를 따른다.

P007 완료와 P016의 고정 원문/추출본·후보 청크 인계를 먼저 확인한다. **별도 설치형 하네스 완료** 근거도 확인하되 하네스 프로젝트의 후속 버전 개발 전체를 기다리는 게이트로 확대하지 않는다. 준비 검토에 실제 저장소·완료 commit/tag·설치/호환 검증 근거를 남기기 전 READY로 전환하지 않는다. 하네스 작업을 HR RAG 제품 코드/P번호로 만들지 않으며 존재하지 않는 완료 증거를 참조하지 않는다.

## 예정 범위

- dev `evaluation/project_b/`에 독립 모듈. Naive/Hybrid/청킹 단계의 버전 고정 run export를 읽고 생성 경로/정답 입력을 분리한다.
- P016에서 검증한 source-v4 원문 PDF/추출본을 기준으로 Codex가 질문·기준 답변·reference claims 후보를 작성하고 원문 span/hash/시행일과 작성·변경 이력을 저장한다. 실제 사람 검증·명시 승인 후 정답 버전을 고정한다. Qwen 초안 생성·재생성을 정답 준비의 필수 실행으로 요구하지 않는다. P007의 고정 청킹 후보·검색 설정을 실행 기준선으로 받아 원문 버전/hash를 일치시킨다. 검색용 qrels/원문 대응표와 Codex 검토는 사람 승인을 대신하지 않는다.
- 한 번 추출한 원자 claims를 Faithfulness/Correctness에서 재사용한다. 누락·추가·중복·예외/수치 보존 검사와 trace를 제공한다.
- 정답 원자화는 [P022 전수 검수 규칙](../reviews/P022-atomicity-audit.md)을 따르며 자격/일수/제외·기한/경로·복수 기록 대상을 구분한다. P022 개정본의 단위에 맞춰 정답 매칭과 고정 답변 추출 기대값을 준비하고, 대상·조건을 보존한 관계/조건부 작업을 무의미한 파편으로 쪼개지 않는다.
- Qwen의 추출 성능은 원문으로 기준 정답을 생성하는 작업과 분리해 검증한다. 사전 고정한 답변과 사람이 검토한 기대 클레임을 준비하고 Qwen에는 질문/답변만 전달한다. 누락·추가·중복·조건/부정/숫자/기한 손실·오류 답변의 무단 수정, 구조·인용 실패를 별도 보고한다. 답변·기대값·모델/prompt·실행 상한을 동결하고 추출 P/R/F1을 Correctness P/R/F1과 구분한다.
- Faithfulness는 실제 전달 문맥에 대한 claim 지지 비율이다. 제외된 검색 청크/정답을 premise로 넣지 않는다. Correctness는 승인 reference와의 의미 대응·누락을 평가하고 Python이 수치를 계산한다.
- 2026-11-05 사용자 요청: 생일휴가 합성 예시에서 근거 청크 전체/일부와 답변 클레임 전체/일부를 조합해 평가기를 검증한다. 동일 질문·정답3개를 고정하고 ①근거/답변 모두 완전 ②근거만 누락 ③답변만 누락 ④근거·답변 함께 누락을 비교한다. 근거 누락만으로 Correctness를 낮추거나, 답변에 없는 정답을 Faithfulness 분모에 추가하지 않는다. [상황별 검증 계약](../specs/P013-evaluator-scenarios-draft.md)과 [고정 입력/기대값](../specs/P013-evaluator-scenarios-draft.json)을 따른다. 평가기 단독 검증·Qwen 추출 단독 검증·실제 RAG E2E를 분리하며 이 예시를 실제 HR 정답 승인으로 승계하지 않는다.
- 2026-11-04 사용자 요청: Neutral rate·Contradiction rate를 필수 결과로 추가한다. 전체 평가 대상 고유 생성 claim 수 T와 지지/근거 부족/모순 수 E/U/C로 Faithfulness=E/T, Neutral rate=U/T, Contradiction rate=C/T를 계산한다. 모든 판정이 유효하고 T>0일 때만 확정 비율을 제공하며 합은1이다. 판정 보류/실패가 있으면 세 비율 모두 null/incomplete, T=0이면 null/no_claims다. JSON·읽기 보고서에 라벨별 개수·전체 분모·유효 판정 수/coverage·보류/실패 사유를 함께 제공한다. 상세 계약·검증 예시는 [준비 초안5.1](../specs/P013-evaluation-draft.md#51-neutralcontradiction-rate-필수-보고-계약)을 따른다. 이 변경은 P013 READY/사람 정답 승인이 아니다.
- 추출/검증/매칭/집계를 교체 가능한 경계로 구현한다. Qwen3-8B를 평가 역할의 우선 후보로 검토하되 현재 생성 Qwen3-4B는 유지한다.
- CLI·결과 artifact·근거/실패/산식 보고와 학습 가이드, UI의 평가 결과 진입 범위를 준비 검토에서 확정한다. P016 원문과 P007 청킹 후보에서 기존 Naive 생성 방식의 평가 기준선을 확보한 후 P014로 이어간다.

## 준비 시 확정

2026-10-29 [상세 준비 초안](../specs/P013-evaluation-draft.md)에 생성 trace 연결점, 독립 artifact, 사람 정답/판정 검토 절차, 산식·실패 정책 제안과 남은 준비 게이트를 정리했다. P007 구현과 독립적으로 준비하며 현재는 초안이다. 이 문서 추가는 P007 계약 변경이나 P013 구현 착수를 뜻하지 않는다.

외부 하네스 완료, 실제 승인 정답 확보 절차/검토자·초기 corpus/질문 수·holdout, schema/모델 revision·환경/메모리·라이선스·호출량·timeout/재시도 상한, 추출·매칭·0분모/보류/실패·부분일치/중복·macro/micro 산식, 사람 기준 평가기 정확도 판정·반복/비용 측정, 구체 UI/API와 독립 복사 범위를 고정한다. 미확정 상태에서 다운로드·모델 실행/대량 sweep을 시작하지 않는다.
