# P013 — Project B 내부 기본 LLM 답변 평가기와 검증 정답

> 준비: 초안
> 실행: 미착수
> 우선순위: 68
> 선행: P007
> 승인 근거: 2026-10-29 사용자 Project B 설계 제공 및 별도 모듈 계획 반영 요청. 2026-10-29 후속 요청으로 P016 원문 재작성 → P007 청킹 실험 이후 기본 평가기를 수행하도록 순서 정정. 상세 실행 계약 준비 전.

## 목적과 외부 선행

RAG가 저장한 최종 답변·실제 전달 문맥을 별도 모듈에서 평가한다. Claim Extraction 결과를 공통 사용해 LLM Faithfulness와 승인 Ground Truth 기반 Answer Correctness(Factual P/R/F1)를 계산한다. [B 내부 평가 모듈 설계](../../architecture/project-b-generation-evaluation.md)를 따른다.

P007 완료와 P016의 고정 원문/추출본·후보 청크 인계를 먼저 확인한다. **별도 설치형 하네스 완료** 근거도 확인하되 하네스 프로젝트의 후속 버전 개발 전체를 기다리는 게이트로 확대하지 않는다. 준비 검토에 실제 저장소·완료 commit/tag·설치/호환 검증 근거를 남기기 전 READY로 전환하지 않는다. 하네스 작업을 HR RAG 제품 코드/P번호로 만들지 않으며 존재하지 않는 완료 증거를 참조하지 않는다.

## 예정 범위

- dev `evaluation/project_b/`에 독립 모듈. Naive/Hybrid/청킹 단계의 버전 고정 run export를 읽고 생성 경로/정답 입력을 분리한다.
- P016에서 검증한 source-v4 원문 PDF/추출본을 기준으로 질문·답변·reference claims 초안과 원문 span/hash/시행일을 저장하고 실제 사람 검증·승인 상태를 관리한다. P007의 고정 청킹 후보·검색 설정을 실행 기준선으로 받아 원문 버전/hash를 일치시킨다. 검색용 qrels/원문 대응표는 사람 승인 정답을 대신하지 않는다. 기존 Codex 검토를 사람 승인으로 표시하지 않는다.
- 한 번 추출한 원자 claims를 Faithfulness/Correctness에서 재사용한다. 누락·추가·중복·예외/수치 보존 검사와 trace를 제공한다.
- Faithfulness는 실제 전달 문맥에 대한 claim 지지 비율이다. 제외된 검색 청크/정답을 premise로 넣지 않는다. Correctness는 승인 reference와의 의미 대응·누락을 평가하고 Python이 수치를 계산한다.
- 추출/검증/매칭/집계를 교체 가능한 경계로 구현한다. Qwen3-8B를 평가 역할의 우선 후보로 검토하되 현재 생성 Qwen3-4B는 유지한다.
- CLI·결과 artifact·근거/실패/산식 보고와 학습 가이드, UI의 평가 결과 진입 범위를 준비 검토에서 확정한다. P016 원문과 P007 청킹 후보에서 기존 Naive 생성 방식의 평가 기준선을 확보한 후 P014로 이어간다.

## 준비 시 확정

외부 하네스 완료, 실제 승인 정답 확보 절차/검토자·초기 corpus/질문 수·holdout, schema/모델 revision·환경/메모리·라이선스·호출량·timeout/재시도 상한, 추출·매칭·0분모/보류/실패·부분일치/중복·macro/micro 산식, 사람 기준 평가기 정확도 판정·반복/비용 측정, 구체 UI/API와 독립 복사 범위를 고정한다. 미확정 상태에서 다운로드·모델 실행/대량 sweep을 시작하지 않는다.
