# P010 — Hybrid 검색 고도화 학습

> 준비: 초안
> 실행: 미착수
> 우선순위: 80
> 선행: P008
> 승인 근거: 2026-10-29 사용자 현실적인 PDF → 청킹 실험 → P013 평가기 우선 요청. 기존 NLI 비교와 평가 UI 후 Hybrid를 수행하며 상세 실행 계약 준비 전.

## 목적

Naive RAG의 BM25/Dense 단독 검색을 기준으로 두 결과를 결합하는 Hybrid 검색을 학습한다. P015/P007의 고정 원문·선정 청킹과 P013/P014/P008의 평가 기준선을 확보한 뒤 수행한다. 예정 폴더는 `3. Hybrid RAG/`이며 이전 단계의 필요한 코드/데이터/테스트만 복사·선별하고 출처·hash를 기록한다.

## P011 결과에 따른 기반 선택

2026-10-28 추가 사용자 요청으로 [P011](P011.md) LangChain 리팩터링·품질/속도 비교를 먼저 수행한다. `docs/verification/p011/adoption-decision.json`의 판정·검증 근거·기준/후보 hash를 준비 검토에서 확인한다. ADOPT_LANGCHAIN이면 검증된 후보를, KEEP_DIRECT이면 기존 직접 구현을 기반으로 복사·선별한다. INCONCLUSIVE이면 기존 직접 구현을 유지하며 재실험 필요 여부를 plan이 검토한다. P011 완료를 LangChain 채택 성공으로 간주하지 않는다. 준비 검토 문서에 선택된 구현·원본 commit/path/hash를 명시하기 전에는 준비 완료로 전환하지 않는다.

2026-10-29 P011은 dev `150884f`에서 ADOPT_LANGCHAIN으로 완료됐고 P012도 완료됐다. 하네스는 별도 프로젝트에서 관리한다. P010 준비 시 P011 판정·P012 UI/래퍼 및 P007/P008 결과의 최신 출처·hash를 함께 확인한다.

2026-10-29 최신 순서: P015 원문 재작성 → P007 청킹 실험 → P013 기본 LLM 평가기 → P014 NLI 비교 → P008 답변/UI 비교 → P010. NLI 채택 성공 자체는 선행이 아니다. P007/P008에서 선택한 corpus·청킹 설정·평가기 버전을 고정해 BM25/Dense/Hybrid를 비교한다.

## 예정 범위와 준비

- 기존 모델·원문·청크·질문·문맥 예산·ID-only 답변 계약을 고정하고 검색 결합만 바꾼다.
- BM25, Dense, Hybrid를 비교한다. 현재 프로젝트의 RRF 방향을 출발점으로 후보 수·상수·동점/중복 ID·검색 결과 부족/실패 처리·최종 top-k와 분량 예산을 준비 검토에서 확정한다.
- 검색된 근거, 실제 전달 근거, 모델이 선택한 인용, 답변의 조건 누락/오답/보류를 구분한다. 검색 성능 개선을 답변 개선으로 단정하지 않는다.
- 관찰된 14질문과 별도 확인 질문을 구분하고 비용/지연·재현 조건을 기록한다. P009에서 남은 q03/q07 조건 누락, q08 과도 보류, q09 선택 인용의 주장 미지원은 회귀 관찰 사례로 유지한다. 인용 JSON/원문 일치 통과만으로 의미 품질을 통과 처리하지 않는다.
- 첫 비교 corpus의 경로·버전·hash·qrels를 준비 검토에서 명시한다. 수작성 15청크 기준선과 source-v2 자동 생성 20청크를 혼합하거나, 작은 합성 corpus의 결과를 현실적인 PDF 전체 성능으로 일반화하지 않는다.
- reranker는 별도 후속 비교 후보이며 Hybrid와 동시에 추가하지 않는다. 원문/청킹은 P015/P007에서 확정한 버전을 유지해 검색 결합 효과와 분리한다.
- CLI/UI 연결·실제 모델 평가량·독립 복사 실행·회귀와 증거 기준을 상세화한 후 준비 검토한다. 이번 요청만으로 초안을 준비 완료로 바꾸거나 구현하지 않는다.
