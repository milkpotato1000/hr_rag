## 목적과 준비

실제 로컬 검색을 한 번 실행하고 선택 문맥으로 실제 LLM을 한 번 호출해 한국어 답변·원문 인용 또는 보류를 반환한다. 제품은 계속 `1. Naive RAG/`다. P003 완료 커밋 74b3c35a551671e1387904a0715ea5f8a1625a0c의 실제 runtime·색인·모델 lock·53개 회귀·장애 증거를 검토했다. [준비 검토](../reviews/P004-readiness.md)를 근거로 준비 완료로 등록한다.

Naive 흐름은 입력→질문 임베딩/검색→문맥 선택→LLM→응답 검증이다. Agent 도구 선택·재검색·query rewrite·reranker·fusion·실제 담당자 메시지 전송은 없다. P003 Dense가 기본이며 P002 BM25를 비교 선택지로 유지한다. 기존 고정 corpus·질문·관련성 정답은 변경하지 않는다.

## 모델과 실행 범위

기존 project-local Ollama에 qwen3:4b를 추가 다운로드한다. 공식 [모델 배포](https://ollama.com/library/qwen3:4b)의 Q4_K_M·약2.5GB·Apache2.0을 참고하며 전체 digest·실제양자화·template/parameters·license와 runtime 버전을 lock에 기록한다. 기존 P003 임베딩 lock·데이터는 보존한다. 생성 모델 메타데이터는 별도 generation-lock.json에 기록해 기존 임베딩 runtime-lock과 색인 정합성을 불필요하게 바꾸지 않는다. 설치 명령은 scripts/setup_generation.py로 제공하고 기존 로컬 runtime start/status/stop을 재사용한다. 모델 전환·유료API·원격실행·전역설치는 하지 않는다.

POST /api/chat에 stream=false, think=false, JSON schema format을 사용한다. 기본 options는 temperature=0, seed=42, num_ctx=8192, num_predict=1024다. API 지원은 실제 모델과 runtime에서 검증하고 요청한 설정과 실제 모델 정보를 증거에 남긴다. 결정적 sampling설정만으로 바이트 재현성을 주장하지 않는다. [공식 chat API](https://docs.ollama.com/api/chat)를 따른다.

## 입력·문맥·출력 계약

제품 내부 `scripts/ask.py`가 --question, --retriever dense|bm25(기본dense), --top-k(기본5), --index-dir(P003 default), --max-context-chars(기본8000), --timeout-seconds(기본120)를 받는다. 정상 stdout은 결과JSON 하나이며 진단은stderr다. 코어함수는 UI에서도 재사용할 수 있게 분리한다. CLI의 실행장애는 status=error 결과와 nonzero exit로 표시한다. 비어 있는 질문·잘못된 숫자·미지원 검색기·stale색인은 실패한다. 실행예:

```sh
.venv/bin/python scripts/ask.py --question "생일 휴가는 누구나 입사 직후부터 사용할 수 있나요?"
.venv/bin/python scripts/ask.py --question "퇴직금 계산식은 어떻게 되나요?" --retriever bm25
```

검색은 question과 corpus만 사용한다. query_id·relevance·answerability·평가용기대답을 운영경로에 전달하지 않는다. top-k후보에서 순서대로 전체청크 단위로 문맥예산에 맞는 것을 선택한다. 청크본문 중간을 잘라 조건을 잃지 않는다. 선택·제외청크와 이유를 trace에 기록하고 모델에는 선택문맥만 전달한다.

시스템프롬프트와 문맥조립 양식은 버전관리한 파일로 둔다. 문서내용은 자료로 구분하고 문서에 없는 규칙·숫자를 만들지 말 것, 근거부족은 보류할 것, 문서의 부재로 제도부재를 단정하지 말 것을 지시한다. 모델이 참고한 chunk_id·원문을 함께 반환하도록 요청한다.

모델 출력은 status(answered 또는 abstained), answer(비어있지 않은문자열), citations(배열)의 JSON이다. citation은 chunk_id와 quote(해당청크 text에 실제 포함된 비어있지 않은 원문부분문자열)를 가진다. answered에는 적어도 한 인용이 필요하고 모든 인용이 실제 전달문맥에 있어야 한다. source·title·version·document_id는 모델출력을 믿지 않고 corpus에서 보강한다.

잘못된JSON·유형·상태·본문·인용은 그대로정답으로 노출하지 않는다. 응답검증 실패는 abstained와 명시적reason으로 보류하며 trace에 validation문제를 남긴다. abstained의 최종 citations는 빈 배열로 두고 모델의 원응답·검증 사유는 trace에서 구분한다. 모델이 abstained면 고정된 “제공된 문서만으로 확인할 수 없어 답변을 보류합니다. 인사 담당자 확인이 필요합니다.” 안내를 반환한다. 인용이 유효해도 답변의 의미가 지지된다고 자동판정하지 않는다.

문맥이 없으면 LLM을 호출하지 않고 abstained(reason=no_context)로 끝낸다. provider연결·timeout·HTTP·Ollama 응답 envelope JSON 파싱 실패 등 실행장애는 error로 구분하고 “문서에 근거없음”으로 숨기지 않는다. 무한재시도·자동재검색·수정LLM호출은 없다.

최종 결과는 status, answer, citations, reason, trace를 가진다. trace에는 입력질문·검색기·원래검색후보(id/score)·선택문맥(id/본문/출처)·제외이유·prompt버전/hash·모델digest·corpus/index hash·설정·validation·retrieval/context/generation/total시간을 남긴다. 내부thinking전문은 수집하지 않는다. 가상자료만 사용하는이번범위에서 실제 전달prompt를 추적가능하게 하되 인증정보를 포함하지 않는다.

## 검증과 평가

- 단위테스트는 fake provider와 고정검색결과로 프롬프트문맥·정답분리·전체청크예산·정상인용·unknown/검색했지만전달안한청크·조작source·없는quote·빈본문·JSON/타입오류·보류·no_context의 모델미호출·timeout/HTTP/stale실패를 확인한다.
- P003의 실제 Ollama/Qdrant와 qwen3:4b로14질문을 실행한다. 고정top-k·프롬프트·모델조건을 기록하고 질문당 trace와 최종출력을 보관한다. 고정queries는 runtime정답에사용하지 않고 평가실행기가 질문텍스트만 ask경로로 전달한다.
- 답변 기대내용은 실제 모델출력을 보기 전에 원문에서 별도 rubric파일에 작성한다. 필요한사실·금지오답·정답출처·복수근거조건을 질문별로 기록한다. q01은 입사3개월경과·수습제외, q02는 생일달근무일·이월/현금불가, q03은 자격·사용3영업일전신청/팀장승인·생일달사용조건, q07은 입사1개월/보안교육·직무제외·주2일/전주금요일승인, q10은 재택/휴가일식대미지원, q12~14는 문서로확인불가보류를 포함한다. 나머지도 원문과대조한다.
- 구조인용유효성은 코드로 검사하고, 사실정확성·조건누락·근거충실성은 rubric에따라 질문별의미검토를 남긴다. Codex가 원문과 대조한 검토는 그 사실을 명시하고 사람이 검토했다고 표기하지 않는다. 자동키워드점수를 의미정확도로 부르거나 생성모델자기평가를 독립정답으로 쓰지 않는다.
- live smoke에서 적어도 q01 또는 q10의 실제근거있는답변 하나와 q13의정확한보류를 확인한다. 전부보류하거나 가짜provider만 통과해서완료할 수 없다. 어려운질문의실패는 지우지않고 개선전후를남긴다. 전체14개를맞혔다고요구하지않는다.
- answerable11개 정확/부분/오답/과도보류/장애와 unanswerable3개 적정보류/허구답변/장애를 분리집계한다. 인용구조유효와 의미지지, 단일실행품질과보편성능을구분한다. 첫실패·프롬프트수정·재검증이력은보존한다.

코드·프롬프트·lock·rubric·실제결과·명령·회귀·시간/모델정보와 의미판정근거를 docs/verification/p004/에 커밋한다. P001~P003 회귀와 큰단계단독복사 실행을유지한다.
