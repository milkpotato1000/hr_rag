# P025 — 공통 LLM provider 설정과 로컬·API adapter 기반

> 준비: 초안
> 실행: 미착수
> 우선순위: 6
> 선행: P024
> 승인 근거: 2026-11-27 공개 모델 기본·선택 LLM API RAG 패키지 목표. 본 카드는 준비 검토 전 초안이며 실행 허가가 아니다.

## 목적

P024의 비실행 예시를 실제 검증 가능한 설정과 LLM 호출 경계로 옮긴다. 생성·추출·판정 역할에 같은 인터페이스를 쓰면서 모델/provider를 선택하고 기존 실행 동작은 보존한다. [패키지 로드맵](../rag-package-roadmap.md)의 첫 제품 코드 증분이다.

## 기획 준비

P024 산출물과 dev의 실제 Ollama/LangChain 호출 위치·설정·출력 schema·오류 처리를 조사하고 구현 경로를 확정한다. 해당 시점의 공식 API 문서·지원 기능을 확인해 최초 adapter를 한정한다. 로컬 Ollama와 선택 API 경계를 정의하되 모든 상용 API가 같은 protocol이라고 가정하지 않는다. 공통 코드 위치·의존성·호환 CLI·테스트 entrypoint·exact 모델 ID/digest 정책을 READY에서 고정한다.

P013의 사용자 보류는 독립 유지한다. offline fixture/transport 시험과 live 모델/API 실행은 구분한다. 이후 실호출이 필요하면 선택 모델·문서 전송 범위·키 설정·비용/호출 상한·시간·중지 조건을 별도 명시해 기존 보류를 조용히 재개하지 않는다.

## 범위와 계약 초안

- 모델 사용 모드 local/api와 역할 generation/evaluation을 분리한 설정 검증. API 키는 환경변수 참조만 저장하고 출력/로그에서 제외한다. 미지원 provider·빠진 필수값·잘못된 옵션은 설명 가능한 오류로 반환한다.
- 모델 카탈로그는 HF 원본 ID/revision, runtime 모델 태그/digest, 양자화, 라이선스 링크, 검증 상태를 구분한다. 기본 임베딩·리랭커는 공개 모델 유지. 과거 artifact의 모델 identity를 새 generic ID로 바꾸지 않는다.
- 호출 입력 messages/schema/출력 예산과 결과 content/usage/finish status/모델 식별/시간·실패 메타데이터의 공통 계약. JSON 지원·thinking·usage 부재 등 capability 차이는 명시한다. API 실패 시 다른 provider로 자동 fallback하지 않는다.
- adapter 선택만으로 파일 다운로드·서버 시작·API 요청을 실행하지 않는다. dry-run은 설정 해석과 유효성만 확인한다. 현재 호환 경로의 회귀를 보존한다.
- transport를 대체한 fixture로 역할 routing, JSON 성공/실패, timeout, rate limit, usage 미제공, 잘못된 응답, 비밀값 비출력 검증. 가짜 응답을 실모델 성공/품질로 기록하지 않는다.

새 UI·Drive connector·대규모 모델 sweep·P013 실제 추론 재개는 제외한다. 구체 구현 경계가 정해지기 전 본 초안을 자동 실행하지 않는다.

## 검증 계획

기존 동작 회귀 범위와 독립 fixture 기대값·실행 명령·증거 경로를 준비 검토에서 확정한다. offline PASS와 real provider 미검증 상태를 구분하고 부작용 없는 설정 확인을 검증한다.
