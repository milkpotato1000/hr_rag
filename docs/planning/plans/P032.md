# P032 — 실제 모델과 단일 규정집의 RAG 통합 검증

> 준비: 준비 완료
> 실행: 진행 중
> 우선순위: 24
> 선행: P031
> 승인 근거: 사용자 최종 goal의 실제 사용 가능한 RAG 패키지 및 모델·청킹·검색·리랭커 선택 비교와 준비 검토·dev 직접 등록 위임. S1/S2a 완료 이후 현재 추가 READY는 S2b 실제4방식 청킹과 E5 검색 비교만 허용한다. LLM 청킹·답변 생성·S3 문서 연결은 후속 결정·계약 전 미착수다. P013 재개 권한이 아니다.

## 목적

tiny/fake로 검증한 연결을 실제 사전학습 embedding/reranker와 선택된 생성 모델로 검증한다. 기존 단일 HR 규정집을 고정하여 원문→청킹→검색→선택 리랭커→근거 답변을 재현하고, 각 선택 축의 결과·실패·자원·품질 한계를 학습 자료로 연결한다. 최소 사례 성공을 전체 모델/문서/환경의 성공으로 표시하지 않는다.

## 준비와 범위

[통합 검증 설계](../specs/P032-live-rag-validation-design.md)를 따른다. P031 최종 준비 도구와 설치물을 확인한 뒤 단계별 입력/정확 모델/요청·시간·자원 상한·중단 조건을 검토한다. 로컬/API 선택과 사용자 문서 접근은 실행 범위에 맞는 실제 설정이 필요하다. P013 recovery runner·8B 평가·NLI·grant는 사용하지 않는다.

P031 완료266bbcbfcf7a897eef98977063898a6e24e9671a 이후 [S1 실행 계약](../specs/P032-s1-execution-contract.md)과 [준비 검토](../reviews/P032-s1-readiness-20261128.md)의 범위만 착수한다. owned worker 감시·회수 보완 및 독립 검증, 새 원문 fact/qrels 매핑, 고정 공개 모델4개의 준비·CPU 검색/리랭킹 비교를 포함한다. 생성/LLM 청킹/API/Drive는 실행하지 않는다. S1 증거는 아래 전체 완료 조건의 일부이며 S1 종료 시 전체 C2/C3를 체크하지 않는다. [직접 인계](../handoffs/P032.md)를 따른다.

실제 mMiniLM 첫 smoke 중단의 후속은 [legacy buffer 계약](../specs/P032-s1-legacy-buffer-contract.md)과 [후속 준비 검토](../reviews/P032-s1-legacy-buffer-readiness-20261128.md)를 정확 채택한 뒤 수행한다. 확인된 고정 mMiniLM revision의 결정적 위치 buffer만 별도 검증하며, 기존 실패를 포함한 누적73workers/500pairs와 원래2시간 deadline을 지킨다. 이 예외가 아닌 원래 S1 조건은 유지하며 S2/S3는 여전히 미착수다.

S1 완료 전달3ce2ed8c95f9259f1184c67e52373c7411e331b5를 확인한 후 [S2a 청킹 사전 준비](../specs/P032-s2a-chunking-preparation.md)와 [준비 검토](../reviews/P032-s2a-readiness-20261128.md)를 추가 READY로 확정했다. 규칙3종의 실제 경계와 semantic/LLM preview·작업량만 모델 호출0으로 준비한다. 이 예외를 제외한 실제 S2/S3 모델 실행·생성 route/Drive 선택 대기는 유지한다. 새 정확 채택 전에는 후속 작업을 실행하지 않는다. 전체 C1~C3 완료 기준은 그대로다.

S2a 완료17ea6305bb483409b9cd593d62e2e64c50c10625 이후 [S2b 실제4방식 청킹 비교 계약](../specs/P032-s2b-nonllm-chunking-contract.md)과 [준비 검토](../reviews/P032-s2b-readiness-20261128.md)를 추가 READY로 확정했다. 기존 규칙3종+실제 E5 semantic을 동일 v3/Hybrid로 비교하며 최대45worker/1896항목·첫실제호출부터1시간·단일worker/4GiB/normal pressure를 적용한다. 새 runner·독립 시험·입력 동결을 커밋하고 정확 채택한 범위에서만 실행한다. LLM/생성/API/Ollama/Drive/평가기·기존 grant는 실행하지 않으며 전체 완료 기준을 바꾸지 않는다.

## 완료 조건

<!-- CHECKLIST:START -->
- [ ] C1: 고정 규정집·질문·근거와 실제 모델 identity/준비 결과를 연결하고 사전 점검·실행·실패·자원 기록을 재현 가능하게 남긴다.
- [ ] C2: 지원 모델/청킹/검색/리랭커 선택 축을 분리해 실제 실행 결과와 비교·출처·답변 검토 증거를 제공하고 실패한 축을 숨기지 않는다.
