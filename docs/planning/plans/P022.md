## 목적과 입력

현재 run002에서 독립적으로 확인할 사실이 묶인 항목과 조건이 문장에 드러나지 않는 항목을 개정한다. P021의 기존 병합/45개 계약을 소급 변경하지 않고 후속 카드로 관리한다. [전수 검수](../reviews/P022-atomicity-audit.md)와 [45개 항목별 제안](../reviews/p022/run002-atomicity-audit.json)을 따른다.

입력은 `evaluation/project_b/preparation/artifacts/run002/packet.json`, 패킷 SHA `e6a264387d3dd169168bcf1733156bf91bd4bdf76fc8bb70f5a704e3bc7a2b0e`와 source-v4 canonical SHA `1c6867d284d136b2eb1cf6f9a707506480946988eaa155ae46b13ce25e2eb298`다. 질문10개·정답 후보45개·판정 후보18개·사람 미승인 상태를 유지하는 버전에서 출발한다. P021 완료와 입력 hash/원문 연결을 실제 확인한 후 정확한 버전을 채택한다.

## 예정 범위

- gt01-c02를 재직 기간 요건·대상자의 연간1일·수습 제외3개로 분리한다. 기한/경로, 승인 주체/기한, 자격/일수, 복수 기록 항목 등 나머지9개도 제안에 따라 분리한다. 분리10개 + 조건 복원2개 + 유지33개를 전수 대조한다. 제안 기대 수는57개다.
- 대상·조건·부정·금액/단위·연간/주간·원문의 기한 표현을 보존한다. 일수/금액 주장의 ‘대상자’를 모든 직원으로 일반화하지 않는다. 의미 있는 조건부 작업/관계는 단어 수준으로 쪼개지 않는다.
- P013의 Codex 원문 기반 후보 작성 결정을 따라 Codex가 새 문장·원문 근거를 재확인한다. Qwen의 정답 생성/추출 호출을 필수로 요구하지 않는다. 기존 Qwen 초안·Codex 수정·실패 이력을 보존하고 새 출처를 구분한다.
- 구claim ID→새claim ID 일대다 매핑, 이유·신구 문장·원문 조항/페이지/인용/span/hash, 후보 수를 기록한다. 제안 JSON의 proposal_id를 기존 제품 ID로 무검증 사용하지 않는다. 정확한 최종 ID/패킷 schema와 새 run 경로는 READY 검토에서 고정한다.
- 새 패킷 JSON에서 질문→정답 클레임→근거 원문 HTML을 생성한다. run001/run002는 원본 그대로 보존하고 새 보고서에서 이전 버전·변경 내역으로 연결한다. 기술/실험 로그는 기존 접힘 방식을 유지한다.
- 모든 새 후보의 승인 상태는 null/미승인이다. 실제 사람 승인 대상은 새 패킷 hash와 항목이다. 기존 승인 요청·검토 화면 열기·이 정책 결정을 새 데이터 승인으로 승계하지 않는다.
- gt09/10의 미명시·claim0, 판정 후보18개의 원문/라벨·ID, 원문 PDF/canonical, 검색/생성 설정, 모델/서버를 변경하지 않는다. 질문 범위·필수/선택 정답 구분·가중치 정책도 변경하지 않는다.

## 검증과 준비 게이트

준비 시 P021 완료 근거·고정 입력·ID/새 버전/schema/재생 경계·단독 복사/검증 명령·화면 확인 방법을 확정한다. DRAFT에서 제품을 수정하거나 P021 완료 체크를 대신 닫지 않는다. 실제 원문과 제안 의미가 충돌하면 조용히 수정을 확장하지 말고 plan에 근거를 기록한다.

dev는10질문/45개 구ID를 전수 대응하고 57개 새 후보의 조건/예외·중복·원자성·정확한 인용/span/hash와 answer/HTML 일치를 검사한다. source quote만 공유한다는 이유로 새 독립 사실을 다시 병합하지 않는다. 문맥 조건을 반복 표기한 것을 별도 가산 사실로 중복 계산하지 않는다. source-v4의 추가 규정을 임의로 정답 목록에 보태지 않는다.

구ID의 소실/충돌·잘못된 원문 위치·조건 일반화·ID/HTML 불일치·승인 자동 이전은 실패다. 모델 없는 새 버전 재생·기존 준비 모듈 회귀·실제 좁은 화면/키보드/접힌 로그/근거 보기 확인을 수행한다. 입력 원본과 기존 실패 증거를 보존하고 시각 검증 미실행을 PASS로 대체하지 않는다.

결과는 P013에 새 패킷·원문·매핑 hash, 새 후보 수/승인 대상, 원자화 규칙을 인계한다. P013의 고정 답변 추출 기대값도 같은 원자화 규칙으로 검토하되 기존 run을 재작성하지 않는다. 분모 변경 전후 점수를 동일 평가 버전으로 비교하지 않는다. 대상 원격은 personal의 plan/dev이며 main 승격은 범위 밖이다.
