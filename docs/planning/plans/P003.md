## 런타임 계약

1. Ollama v0.40.8의 공식 macOS tar 배포를 큰 단계 내부 .runtime/ollama에 확보한다. URL은 https://github.com/ollama/ollama/releases/download/v0.40.8/ollama-darwin.tgz 이고 배포 파일 SHA-256은 29fce20c736f62aa8885b1e83552c5fd8dcc63edc5ffc1b47f2de591a06cde44이다. 검증 후 풀고 archive 경로 탈출을 거부한다. 라이선스·URL·검증 hash·실제 버전을 작은 runtime-lock.json에 기록한다. OS/서명·실행 제한이 있으면 실제 오류를 진단하고 가짜 임베딩으로 대체 완료하지 않는다.
2. 격리된 Python 3.12 환경 .venv와 qdrant-client==1.19.1을 사용한다. 설치된 uv를 사용할 수 있고 필요한 Python 3.12 배포 다운로드도 허용한다. Python 실제 patch와 전이 의존성을 잠금 파일에 고정한다. 캐시·다운로드 Python은 .runtime 아래 두어 다른 프로젝트 환경을 바꾸지 않는다. 기존 루트·P002의 Python 3.9 표준 라이브러리 실행 경로도 보존한다.
3. 임베딩 모델은 Ollama bge-m3:567m으로 정한다. BAAI 원 모델은 MIT 라이선스이며 모델 가중치는 약 1.2GB다. 최초 pull 후 전체 digest·양자화·모델 정보·라이선스·임베딩 차원(예상 1024)을 lock에 기록한다. 이후 기존 lock의 digest가 달라지면 자동으로 덮어쓰지 않고 재색인 필요를 알린다. 실제 모델 정보가 선택 계약과 다르면 피드백·재검토한다.
4. OLLAMA_MODELS와 PID·로그·색인·캐시는 .runtime 안에 둔다. 기본 endpoint는 http://127.0.0.1:11434이고 로컬 loopback만 사용한다. 기존 사용자의 서비스를 종료하거나 덮어쓰지 않는다. 자체 서비스는 실제 PID·실행파일·endpoint 소유를 확인해 stop하며 launch agent나 상시 시스템 서비스를 설치하지 않는다.
5. setup_runtime.py는 설치·검증·모델 확보를 담당하고 runtime.py start/status/stop은 자체 서비스 수명주기를 담당한다. 시작·준비 확인에는 제한 시간을 두고 실패 원인을 출력한다. 이미 일치하는 설치는 재사용한다. 다운로드·모델·venv·Qdrant 데이터·PID·로그는 Git에서 제외하고 코드·설정·작은 lock·검증 증거만 커밋한다.

공식 근거는 [Ollama release](https://github.com/ollama/ollama/releases/tag/v0.40.8), [embed API](https://docs.ollama.com/api/embed), [BGE-M3 모델](https://ollama.com/library/bge-m3), [원 모델 카드](https://huggingface.co/BAAI/bge-m3), [Qdrant client](https://github.com/qdrant/qdrant-client), [PyPI 배포](https://pypi.org/project/qdrant-client/1.19.1/)다. 2026-10-22 확인했다.

## 검색·색인 계약

- P001 입력 검증과 평가기를 재사용한다. 문서 임베딩 입력은 title + LF + text, 질문 입력은 question 원문이다. BGE-M3의 Dense 임베딩만 사용하고 sparse·multi-vector·query 확장·LLM·reranker·hybrid는 사용하지 않는다.
- POST /api/embed를 model·input·truncate=false와 함께 호출한다. 네트워크 timeout·HTTP 오류·깨진 JSON·응답 개수·차원·유한 값·0벡터를 검증한다. silent truncation이나 임의 mock fallback은 없다.
- QdrantClient(path=...)의 로컬 영속 색인, cosine 거리, chunk_id로부터 고정 UUID를 생성해 point ID로 사용한다. payload에 원 chunk_id·document_id·version·title·text·source·synthetic을 유지한다. qrels와 answerability는 색인·검색 입력에 넣지 않는다.
- index manifest에 corpus byte SHA-256, 임베딩 digest·차원·텍스트 구성 버전·거리·client 버전·point 수를 남긴다. index 생성 후 닫고 새 프로세스에서 재열어 검색하는 것을 검증한다. corpus·모델·설정이 바뀌면 기존 색인으로 묵시 검색하지 않고 재생성을 요구한다. 기존 index 경로 덮어쓰기 대신 새 경로에 생성한다.
- 후보는 전체 N을 조회한 뒤 score 내림차순·정확한 동점은 chunk_id 문자열 오름차순으로 정렬해 top-k를 고른다. cosine 0·음수도 포함한다. BM25의 양수 점수 필터를 Dense에 이식하지 않는다. 빈 검색 가능성·검색 결과 존재는 근거 충분성 판정이 아니다.
- top-k·K 검증과 질문당 한 행, score·rankings 일치, hash·분모·평가 의미는 P002를 따른다. Dense·BM25 원점수는 직접 크기 비교하지 않는다. 시간은 index 준비·질문 임베딩·벡터 검색을 분리한다.

## 실행 인터페이스

제품 폴더에서 다음 흐름으로 실행할 수 있어야 한다. start 상태 확인 후 index·search를 수행하며 README에 종료 명령도 적는다.

```sh
python3 scripts/setup_runtime.py
.venv/bin/python scripts/runtime.py start
.venv/bin/python scripts/build_dense_index.py --chunks data/synthetic/chunks.jsonl --index-dir .runtime/index-v1
.venv/bin/python scripts/run_dense_baseline.py --chunks data/synthetic/chunks.jsonl --queries data/synthetic/queries.jsonl --index-dir .runtime/index-v1 --top-k 20 --k 5 10 20 --output-dir /tmp/hr-rag-dense-new
.venv/bin/python scripts/runtime.py status
.venv/bin/python scripts/runtime.py stop
```

index・結果出力先は新規パスのみ許可する。入力・モデル・色引き・評価・出力失敗は stderrとnonzero exitで示し、ユーザーの既存ファイルを保全する。未完の新しい結果を成功として公開しない。

Dense結果は rankings.jsonl、scores.jsonl、metrics.json、run.jsonを持ち、P001で直接再評価できる。runはモデル・runtime・設定・hash・環境と分離した時間を記録する。BM25も同じデータ・top-k・Kで再実行し、数値比較と具体的な検索差を根拠付きで記録する。品質改善を前提にしない。

## 検証と証拠

ネットワークなしの単体・統合テストと、実際のOllama/BGE-M3/Qdrantを使った検証を分ける。テスト用HTTPサーバー・既知ベクトルは故障と独立期待値のためだけに使い、live実行と呼ばない。

既知ベクトル a=[1,0], b=[0,1], c=[1,1]、query=[1,0]なら順位は[a,c,b]、cosineは[1,1/sqrt(2),0]で誤差1e-6以内とする。手計算式から期待値を作り検索実装関数を再使用しない。候補順変更・同点・再open・unknown payload・重複point・stale manifest・不正ベクトル・HTTP失敗とtimeout・JSON不正・出力保全を検証する。

実際の15chunk・14queryを一度以上埋め込み・索引化・再open・評価する。lockと最終モデルdigest・色引きmanifest・chunk対応・P001再評価一致を照合する。基準のcorpus・質問hashとP001/P002既存回帰を保持する。実行記録と失敗後再検証を docs/verification/p003/にコミットする。時間や小規模検索品質を一般化しない。
