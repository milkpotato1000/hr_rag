## 목적과 범위

현재 Python 직접 연결 Naive RAG와 LangChain 기반 Naive RAG를 같은 조건에서 비교한다. 검색 알고리즘·모델·프롬프트를 개선하는 과제가 아니라 실행 구성을 바꾸는 리팩터링이다. 실제 품질 유지 여부를 판정한 후 P010 Hybrid의 구현 기반을 정한다. 비교 완료와 LangChain 채택 성공은 다른 결과다.

사용자 원문: “현재 Naive RAG를 랭체인 기반으로 리팩토링하는 작업을 plan에 요청해줘. 기존 구현은 비교용으로 남겨두고, 검색 결과랑 답변 품질, 속도 차이도 비교할 수 있게. 이 내용을 먼저 수행해보고, 품질 저하 없으면 랭체인 기반으로 계속 이어가자 다음 로드맵.” 전달 출처는 dev 채팅 `01a1618d-8c93-7122-9902-7c839eed66a1`이다.

[상세 비교·판정 계약](../../architecture/langchain-naive-comparison.md)은 이 카드의 완료 조건에 포함된다. P001~P006/P009의 계약·실행 로그·과거 실패 증거를 수정하지 않는다. P010/P007/P008은 이번 구현 범위가 아니며 초안을 유지한다.

## 보존과 구현 위치

- 기준 커밋은 dev `58e8eb793b95c524c256c0206e37aa15ff99c6ff`다. 착수 HEAD가 전진했으면 기존 Naive 제품 파일의 diff/hash를 먼저 확인한다. 모델·데이터·응답 계약 변경이 있으면 이 기준과 섞지 말고 영향 검토를 plan에 남긴다.
- 기존 `1. Naive RAG/`의 제품 코드·데이터·프롬프트·lock·테스트·web을 바이트 기준으로 보존한다. 기존 UI/CLI/API는 계속 직접 구현 기준선이다. 루트 README/LEARNING_GUIDE/stage-manifest의 비교 진입 안내 추가만 허용하며 해당 파일의 원본 hash도 기록한다.
- 후보는 같은 Naive 단계의 `1. Naive RAG/variants/langchain/`에 둔다. 이전 커밋의 필요한 소스/데이터/테스트를 복사하고 원본 커밋·상대 경로·최초 복사 hash·현재 hash를 manifest로 기록한다. 런타임 import·symlink로 부모 소스를 참조하지 않는다. 복사 대상에서 variants 자체·가상환경·가중치·캐시를 제외해 재귀 복사를 막는다.
- 후보 안에 복사한 기존 `scripts/rag.py` 직접 실행 경로를 그대로 보존하고 `scripts/rag_langchain.py`를 추가한다. 비교 UI의 direct 선택은 이 동일 hash 사본을 사용한다. 원래 폴더의 실행과 동등함을 별도로 검증한다. 새 큰 단계 `2.`를 LangChain 때문에 만들지 않는다.
- 원본 색인·모델 저장소를 덮어쓰지 않는다. 비교용 색인은 동일 corpus·벡터·payload·ID·설정으로 확보하고 일치 증거를 남긴다. live DB를 무단 복사하거나 다른 프로세스의 lock을 삭제하지 않는다. 원본/사본과 로컬 모델 재사용·독립 실행 조건은 상세 계약을 따른다.

## LangChain 구성

`langchain-core==1.7.0`을 후보의 격리 환경에만 도입한다. 현재 Python 3.12.14와 기존 직접 의존성 pin을 유지하고 전이 의존성·라이선스·해시를 lock/환경 보고서에 고정한다. 추가 패키지 설치는 이 로컬 구현 범위에 포함한다. 기존 pin과 충돌하면 강제 업그레이드하지 말고 근거를 plan에 전달한다.

검색 → 전체 청크 선택/불변 snapshot → 기존 메시지 구성 → 무문맥 분기 또는 생성 → 검증/원문 조립을 `RunnableLambda`/`RunnableSequence`/`RunnableBranch` 등의 명시 단계로 연결한다. 전체 `rag.ask`를 단일 Runnable로 감싼 것만으로 완료하지 않는다. 기존 순수 함수/경계 어댑터를 재사용하며 단계별 입출력/오류/호출 횟수를 검사 가능하게 한다.

기존 BM25Index·DenseIndex·Generator를 어댑터로 연결해 토큰화·점수/동점·임베딩 입력·Qdrant·실제 `/api/chat` payload를 보존한다. 내장 BM25Retriever/VectorStore/ChatOllama로 일괄 교체하지 않는다. provider 교체나 점수 변화 실험은 별도 새 요구다. 자동 retry/fallback, 응답 수정 LLM, 새 Agent/LangGraph, memory, Hybrid/reranker, 프롬프트/청킹 변경은 넣지 않는다. LangSmith 등 외부 trace 전송은 끄고 로컬 증거만 저장한다.

## 실행 계약 보존

- 현재 BGE-M3/Qwen 이름뿐 아니라 digest·runtime·template·sampling·system-v3·ID-only schema를 고정한다. Qwen request는 stream=false, think=false, temperature=0, seed=42, num_ctx=8192, num_predict=1024를 유지한다.
- chunk ID/순서/점수, 선택/제외 근거·이유·분량, 실제 전달 메시지·요청별 enum/options, 생성 시도/실제 전송 횟수를 대조한다. no_context는 생성 0회, 일반 경로는 최대 1회다. 상태/에러 분류·timeout·stale index·모델 변경 감지·원문 byte 일치를 보존한다.
- 응답 JSON은 status/answer/citations/reason/trace와 기존 trace 필드를 유지한다. 후보에는 구현 식별자/비교 run ID/버전/추가 timing만 명시적으로 확장한다. 시간·새 run ID·로컬 경로 차이를 제외한 계약 필드는 자동 비교한다. 응답 텍스트/인용 ID의 모델 선택 차이는 의미 평가에서 별도로 다룬다.
- 요청별 schema/allowed IDs/snapshot을 격리하며 동시·연속 요청에 이전 문맥이 섞이지 않는 회귀를 수행한다. 정답/rubric 파일을 검색·모델 입력에 넣지 않는다.

## 비교 화면과 실제 평가

후보 CLI `--implementation direct|langchain`, 후보 `/api/ask`의 implementation 선택과 UI 비교를 제공한다. 기존 직접 UI 기본 포트8000은 유지하고 후보 UI는 기본8001 loopback에서 연다. 후보 기본 선택은 판정 전 direct다. 잘못된 implementation은 입력 오류로 처리하며 몰래 fallback하지 않는다.

비교 버튼은 같은 질문·retriever·K·문맥 예산의 두 요청을 직렬 실행한다. 각 결과에 direct/langchain·corpus·설정·순서·시간을 표시하고 한쪽 실패도 보존한다. 후보 두 경로는 같은 서버의 실행 lock으로 직렬화한다. 화면의 수동 1회 비교는 정식 벤치마크와 구분한다. 후보 UI에서 source-v2가 필요하면 사전 등록된 corpus ID만 허용하고 임의 파일 경로 입력은 받지 않는다.

검색 순위/점수·전달/제외 문맥·답변/인용·보류/오류·시간의 A/B 차이와 결과 JSON 내보내기를 제공한다. 기존 P005의 오류 처리·로컬 요청 제한·좁은 화면·요청 경합 동작을 회귀 검증한다. 최종 보고서는 실제 모델 반복 비교와 원문 rubric 검토를 포함한다. 자세한 고정 질문·횟수·판정·속도 측정은 상세 계약에 따른다.

## 판정과 후속 인계

결과는 `ADOPT_LANGCHAIN`, `KEEP_DIRECT`, `INCONCLUSIVE` 중 하나다. 검증된 비교 범위에서 계약 보존·의미 품질 유지·실행 안정성을 모두 충족하면 사용자의 조건부 위임에 따라 LangChain을 후속 기반으로 선택한다. 저하가 관찰되면 KEEP_DIRECT, 비교 불완전/판정 불확실이면 INCONCLUSIVE이며 둘 다 기존 구현을 기본으로 유지한다. 속도/추가 의존성/자원 비용은 별도 공개하고 품질 통과 근거와 섞지 않는다.

P011을 완료하려면 구현·비교·실패 보존·판정 근거가 모두 있어야 한다. 패키지 설치 실패나 벤치마크 미실행을 INCONCLUSIVE 완료로 덮지 않는다. 유효한 비교를 수행했으나 의미 평가의 불확실성이 남는 경우만 그 판정을 사용할 수 있다. P010 준비 검토에서는 커밋된 판정 파일과 원본/후보 경로·hash를 확인하고 후속 기반을 명시한다. 현재 카드만으로 P010을 자동 실행하지 않는다.
