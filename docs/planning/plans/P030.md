# P030 — 범용 의미·LLM 청킹과 경계 비교 연결

> 준비: 준비 완료
> 실행: 진행 중
> 우선순위: 22
> 선행: P020
> 승인 근거: 사용자 최종 RAG 패키지 goal의 청킹 방식 선택·비교 및 앞선 LLM 청킹 포함 요청. 2026-11-28 Hybrid→리랭커 우선 순서를 보존해 후속 설계로 등록한다. 준비 검토를 거쳐 READY로 확정하며 정확 채택 후 이 범위만 구현한다.

## 목적

임의 지원 문서에서 고정·재귀·구조·의미·LLM 청킹을 선택하고 같은 원문/질문으로 경계·중복·필수 근거 회수·비용을 비교한다. 기존 고정 HR 실험의 성과를 범용 패키지 지원으로 오해하지 않도록 실제 adapter와 화면을 연결한다. P013/P014 평가기 실험 보류는 유지한다.

## 준비 근거와 범위

[연결 설계](../specs/P030-model-chunking-design.md)를 따른다. 기존 P007/P017의 순수 경계 알고리즘과 원문 interval 검증을 선별 재사용하고 frozen HR runtime/예산/ledger/GT는 보존한다. P010 공개 임베딩과 공통 LLM provider를 재사용하며 paid API 선택은 LLM 역할에만 해당한다. P020 완료 d8724cb6b356703c8fa0d09b6d86d8e3782fdc98의 fact/span·후보·UI 계약을 대조했다. [실행 계약](../specs/P030-model-chunking-contract.md)과 [준비 검토](../reviews/P030-readiness-20261128.md)를 우선한다.

단순히 enum에 두 이름을 더하거나 fixed 경계를 semantic/LLM으로 표시하지 않는다. 실제 모델 adapter 연결, 새 chunk artifact와 모델 없는 재생/색인, 원문 위치 보존, 다섯 방식 비교·UI·설치 실습이 필요하다. 실제 모델·문서·API 실험은 별도 실행 범위를 정한 뒤 수행하며 이번 READY는 보류된 평가 실험을 재개하지 않는다.

## 확정한 결정과 검증

- 원문 단위화/긴 단위/공백·제목 처리, 의미 거리와 길이·오버랩 정책, query-independent LLM 경계 ID schema를 고정한다.
- 모델 경계 artifact를 저장하고 build/load/ask/compare/replay에서 암묵 모델 호출이 일어나지 않도록 versioned pipeline을 정한다.
- LLM chunking 전용 역할·요청/시간/단위 상한·입력 token 검증과 미지원 길이 처리·재시도/부분실패 정책을 준비한다. 기존 P025 generation/evaluation 설정을 조용히 변경하지 않는다.
- 청킹 변경으로 chunk qrels가 달라지는 문제를 source fact/span 비교로 구분하며 다른 chunk fingerprint의 qrels를 재사용하지 않는다.
- 기존 자료·실험/예산 불변, 모든 코드/알고리즘/단계 선별 출처와 P020 회귀·독립 설치·허용 화면 검증을 준비한다.
