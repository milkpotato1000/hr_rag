# P027 — Google Drive 문서 링크 수집과 버전 snapshot 연결

> 준비: 초안
> 실행: 미착수
> 우선순위: 8
> 선행: P026
> 승인 근거: 사용자의 문서 저장소 Google Drive 가정 및 2026-11-27 지원 웹하드 문서 링크 입력형 패키지 목표. 준비 검토 전 실행 불가.

## 목적

사용자가 권한을 가진 Google Drive 문서 링크를 넣어 P026 일반 문서 snapshot에 연결한다. 기존 Drive fixture를 실제 API 연결로 오인시키지 않으며 다른 웹하드는 동일 connector 계약의 후속 확장이다.

## 기획 준비

[Drive 다운로드 공식 안내](https://developers.google.com/workspace/drive/api/guides/manage-downloads)와 [resource key](https://developers.google.com/workspace/drive/api/guides/resource-keys)를 2026-11-27 확인했다. PDF 같은 blob은 files.get alt=media, Google 문서는 files.export 경로가 다르고 canDownload·resource key를 고려해야 한다. 구체 지원 링크/파일 형식·OAuth 최소 범위·credential 저장/갱신·페이지네이션·변경/삭제 정책·요청 상한과 private data 공개 방지를 READY에서 확정한다.

## 범위 초안

읽기 전용 connector protocol, 링크 분석→metadata/권한→다운로드 또는 export→hash/version snapshot→일반 ingestion. 링크의 임의 호스트로 credential을 보내지 않고 공식 API만 사용한다. 접근 실패/미지원/빈파일/너무 큼/개정 중/중복/삭제를 구분한다. 새 버전을 이전 index와 조용히 섞지 않는다. 사용자 요청 없는 공유·권한 변경·쓰기·삭제는 지원하지 않는다.

기본 인증은 사용자가 제공한 본인 접근권한이며 코딩 도구 connector 인증이 배포 패키지로 자동 이전된다고 설명하지 않는다. private 문서를 공개 저장소/테스트 fixture로 넣지 않는다. 최초 지원은 단일 문서 링크, 폴더 순회/shortcut/shared-drive/Google 문서 export의 정확 포함 범위는 준비 검토에서 고정한다. 실제 계정 접근이 필요하기 전까지 fake HTTP와 합성 metadata로 검증 가능한 코드부터 설계한다.

## 검증 계획

정상/권한거부/만료 token/resource key/개정 경쟁/잘못된 링크/허용크기/부분다운로드 등 transport fixture와 P026 snapshot 연결을 검증한다. 실제 Drive E2E는 지정한 파일/계정 권한으로 따로 확인하고 fixture 성공과 구분한다.
