## 구현 범위

1. 고정 크기 + overlap: 우선 문자 단위로 크기 200/400/800, overlap 0/20%를 분리해 비교한다. 첫 비교에 고정한 값이며 최적 설정이 아니다.
2. 문단/문장 경계를 우선하는 재귀 분할: 구분자 우선순위·긴 문장 fallback·overlap 의미를 고정한다.
3. 제목/섹션 기반 분할: 제목과 본문 연결·긴 섹션 분할·예외 조건의 부모 제목 보존을 관찰한다. PDF에서 제목을 정확히 추출하지 못한 문제는 청킹 효과와 분리한다.
4. 임베딩 기반 의미 분할: 기존 로컬 BGE-M3로 인접 문장 의미 변화에 따라 경계를 선택하는 후보를 비교한다. 문장 경계 규칙·거리/threshold·최소/최대 크기·동점·추가 임베딩 비용을 확정한다. 구조 기반을 자동 semantic 알고리즘으로 부르지 않는다.
5. LLM 기반 분할: 생성 모델이 원문의 문장/문단 경계 후보 ID를 선택하고 Python이 원문 slice로 청크를 만든다. 임베딩 유사도 기반 분할과 별도 방법으로 비교하며 아래 원문 보존·호출/실패 계약을 따른다.
6. 한 번에 한 변수: parser/canonical corpus·질문·embedding·retriever·title enrichment를 고정한다. 다른 검색기 비교는 별도 실험으로 표시한다. 비교 전 실험 설정과 질문 분할을 저장한다.
7. 학습용 tuning 질문과 확인용 holdout을 구분한다. 기존14개는 이미 관찰된 tuning 자료이며 holdout이라고 부르지 않는다. 작은 합성 세트의 일반화 한계를 남긴다.

## LLM 기반 청킹의 범위와 검증

- 문서 처리 시점의 query-independent 분할이다. 질문·검색 결과·정답·rubric은 모델 입력에 넣지 않는다. 모델이 원문을 요약/재작성하거나 제목·설명·사실을 추가한 텍스트를 청크로 저장하지 않는다. 문서 안의 지시문은 자료로 취급하며 도구/외부 작업을 실행하지 않는다.
- Python이 canonical text에 대응하는 문장/문단 후보 ID와 offset을 먼저 고정한다. 모델은 구조화된 경계 ID만 반환하고 Python이 ID 존재·중복·순서·범위를 검증한 뒤 연속 원문 [start,end) slice를 만든다. 문서 전체 coverage·누락/재배열 없음·페이지/source map 일치를 검증한다. overlap을 적용하면 기본 분할 뒤 별도 규칙으로 확장하고 중복 통계를 분리한다.
- 긴 문서는 전체 prompt와 출력 여유가 입력 한도 안에 들도록 window를 정한다. 고정 window는 최대1200자/20단위이며 전체35개다. 경계 합치기·길이·긴 단위 처리 규칙은 상세 계약을 따른다. 입력을 조용히 자르거나 window별 원문을 빠뜨리지 않는다. tokenizer 기반 수치와 실제 관측/추정 분량을 구분한다.
- 기존 로컬 Qwen 런타임의 제한된 경계 선택 호환 검증을 마쳤다. P013 평가 모델 선정과 독립적이며 답변 생성 모델을 자동 교체하지 않는다. 모델/digest·prompt/schema·sampling/seed·window/길이·재시도·전체 호출/시간 상한은 고정 spec을 따른다. LLM 최대219요청(준비3회 포함)/120분,embedding 최대32000item(준비2item 포함)/30분이며 먼저 도달한 한도에서 중단한다. 새 모델 다운로드/교체는 포함하지 않는다.
- 잘못된 JSON/ID·누락·크기 위반·timeout·입력 초과를 독립 fixture로 검증하고 원응답·검증 실패·재시도 이력을 남긴다. 상한 내 재시도 후 실패하면 해당 실행을 실패로 표시하고 기존 산출물을 보존한다. 임의로 fixed 청킹으로 바꿔 LLM 성공으로 보고하지 않는다. 결정적 후처리를 허용할 경우 규칙·개입 여부를 별도로 기록해 순수 모델 경계와 구분한다.
- 고정 입력/모델/설정의 반복 실행에서 선택 경계 집합의 일치율과 청크 수·길이 변동을 측정한다. 독립 검증한 산식·반복 횟수·고정된 후보 경계 집합을 사전에 정하고 결과를 전부 보존한다. 캐시 재사용을 새 추론 반복으로 세지 않는다. seed/낮은 temperature만으로 완전한 결정성을 보장한다고 설명하지 않는다.
- manifest에 원문 hash·후보 경계 map·모델/digest·설정/prompt hash·원응답/검증/최종 경계·청크 hash와 실행별 소요시간·호출 수·관측 입력/출력 토큰·재시도/실패를 연결한다. 로컬 실행은 호출/토큰/시간을 비용 지표로 제시하고 측정하지 않은 금전 비용은 만들어내지 않는다. 저장 artifact 재생과 모델 재실행을 구분한다.
- 같은 원문·검색기·질문·평가 기준에서 다른 네 방식과 검색 품질/구축 비용을 비교한다. LLM의 우수성은 완료 조건이 아니다. 품질 개선이 없거나 처리 비용이 큰 결과도 보존해 학습 결론으로 남긴다.

## P007부터 사용하는 학습 UI

2026-10-29 사용자 요청으로 CLI/보고서와 함께 원문·청크·검색 비교 화면을 이 카드에서 제공한다. P013/P014 평가기를 선행으로 요구하지 않는다. 기존 `1. Naive RAG/`의 UI/기본 corpus/포트는 보존하고 P012의 익숙한 화면 구성·스타일·접근성·로컬 보안 경계를 `2. Document Chunking/`으로 복사·선별해 독립 실행한다. 제품 화면에서는 “원문”, “청킹 실험”, “검색 비교” 등 학습 목적을 표시하며 내부 P번호를 조작 조건으로 노출하지 않는다.

- **원문 확인:** P016의 고정 snapshot/corpus 버전과 가상 자료·Drive fixture 상태를 표시한다. 통합 규정집 목차·장/절 선택, PDF 페이지 보기, 같은 페이지의 추출 텍스트를 제공한다. 청크/검색 결과에서 document ID·페이지·canonical 범위로 역추적한다. PDF 좌표 강조는 검증된 매핑이 있을 때만 사용하고, canonical offset을 PDF 좌표로 가장하지 않는다.
- **청크 관찰/설정:** 방식·크기·overlap 등 해당 알고리즘의 유효 설정을 선택하고 경계/겹침, 청크 수·길이·중복 통계를 본다. 미지원 조합/잘못된 설정은 명시 오류다. 선택 설정을 실제 청킹 CLI와 같은 코어에 전달하고 manifest/run ID에 연결한다. 가짜 화면용 청크나 하드코딩 지표로 완료 처리하지 않는다.
- **LLM 실험 표시:** 방식 선택에서 “임베딩 기반 의미 분할”과 “LLM 기반 분할”을 구분한다. 모델 분할 진행·호출량/시간·실패/재시도·캐시/재실행 여부를 표시하고 결과에서 원문 경계·반복 일관성을 확인한다. 명시 실행 없이 방식 선택만으로 모델을 호출하지 않는다. 새 답변 생성이나 답변 평가 점수로 표시하지 않는다.
- **색인 상태:** 설정별 생성 전·처리 중·실패·준비 상태를 보여준다. corpus/청킹 hash와 색인 버전이 일치할 때만 검색한다. 실패 시 기존 성공 결과는 버전/이전 실행 표시와 함께 보존하고, 새 설정 결과로 오인되지 않게 한다. 중복 실행을 막고 화면 이동/연결 종료가 작업 취소를 보장하는지 실제 동작대로 안내한다.
- **검색 A/B:** 같은 질문·고정 corpus·같은 검색기/임베딩·K·비교 예산에서 청킹 설정 A/B를 비교한다. 순위·청크 본문·원문 위치·점수·근거 회수/중복·지연을 제공한다. 서로 다른 실행/설정/색인의 결과를 한 실험으로 섞지 않는다. BM25/Dense 비교는 별도 실험 축이며 청킹 효과로 해석하지 않는다.
- **평가 표시:** 검토된 검색 정답이 있는 질문에는 fact/span 회수율과 준비 계약에서 확정한 지표·분모를 보여준다. 임의 사용자 질문/정답 없음/미실행/오류는 N/A와 사유로 표시한다. 검색 점수 자체를 정답률로 부르거나 답변 Faithfulness/Correctness로 표시하지 않는다. holdout 정답 공개 시점과 tuning 구분은 실험 계약을 따른다.
- **결과와 사용성:** CLI와 같은 run artifact를 저장/다운로드하고 설정·입력 버전을 함께 제공한다. loading/empty/error, 키보드 탐색, 390px/1200px 화면과 실제 PDF→추출→청크→검색 코어 연결을 검증한다. 원본 PDF 제공은 manifest에 등록된 파일로 제한하고 임의 로컬 파일 경로나 HTML 스크립트를 실행하지 않는다.

P007의 LLM 호출은 문서 청킹에 한정한다. 새 답변 생성 비교/LLM·NLI 답변 평가 실행은 포함하지 않는다. “답변 평가”를 구현 완료처럼 표시하거나 임시 점수를 넣지 않는다. P008은 이 화면 위에 실제 전달 문맥·답변·인용·보류·평가기 결과를 추가하며 원문/청킹/검색 화면을 다시 만들지 않는다.

## 평가 설계

- 정답은 바뀌는 청크 ID가 아니라 검증한 동일 버전 원문 fact/span에 고정한다. P006의 평가 방식을 계승하되 P016의 새 원문 위치·인용·정책 대응을 바탕으로 검색 정답을 다시 검토한다. 각 전략의 chunk→source map으로 근거 회수 여부를 계산한다. 동일 사실의 중복 검색으로 점수를 올리지 않는다.
- 필수 근거 회수율: 질문별 필요한 fact 중 top-k의 원문 span 합집합이 해당 fact의 evidence_sets 하나에 속한 span 전체를 덮은 fact의 비율. 청크 경계에서 나뉜 근거를 여러 청크가 함께 회수하는 경우를 처리한다. 부분 coverage와 전 필수 근거 회수 성공률을 별도 관찰한다. 집합 간 OR/집합 안 AND이며 다른 집합의 일부를 섞어 성공 처리하지 않는다. 고정 검색 dataset과 상세 산식을 따른다.
- 청크별 Precision@K/Recall@K/MRR/nDCG는 전략별 qrels를 source 기준으로 다시 생성·검토한 뒤 보조 지표로 사용한다. 청크 분모가 달라져 숫자만 직접 비교하면 오해할 수 있음을 명시한다. MRR 하나로 복수 근거 회수를 평가하지 않는다.
- 같은 K 비교와 같은 전달 분량 예산 비교를 따로 한다. 큰 청크가 단지 더 많은 텍스트를 가져온 효과를 구분한다. 문자와 토큰 수를 혼용하지 않는다.
- 근거 없는 질문은 Recall 분모에서 분리한다. 청크 수·길이 분포·중복 범위·색인 크기·문서 임베딩/색인 시간·질문 검색 시간·상위 결과별 원문을 함께 저장한다.
- 전체 모델 답변 생성 없이 검색 평가를 먼저 수행한다. 좋은 검색 수치가 좋은 답변을 보장하지 않으므로 선정 후보와 고정 원문/청크·질문/검색 설정을 P013에 먼저 인계하고, P013/P014 이후 P008에서 실제 생성·답변 품질·평가 점수 UI까지 검증한다. P013의 정답 준비에 검색 결과를 정답으로 사용하지 않는다.
- 비교값을 좋게 만들려고 질문/정답/실패 기록을 수정하지 않는다. 원문·정답 자체의 결함은 새 버전으로 분리한다.
