# P007 — 청킹 방식·크기·겹침과 검색 품질 실험

> 준비: 초안
> 실행: 미착수
> 우선순위: 67
> 선행: P015
> 승인 근거: 2026-10-29 사용자 원문 재작성(P015) → 청킹 실험(P007) → 평가기(P013) 순서 변경. 상세 실행 계약 준비 전

## 목적과 고정 입력

[P015](P015.md)에서 만든 현실적인 가상 PDF의 동일 snapshot·canonical text·page map을 고정하고, 질문·임베딩·검색기를 유지한 채 청킹만 바꿔 query→top-k 품질과 비용을 비교한다. 작업 위치는 `2. Document Chunking/`이다. P015의 문서/추출·정책 대응표를 재사용하며 **원문 재작성은 이 카드에서 수행하지 않는다**. 결함이 있으면 원문 버전 수정과 실험 재시작을 구분한다.

2026-10-29 요청에 따라 Hybrid 선행을 제거했다. P011 ADOPT_LANGCHAIN/P012의 완료 기반에서 필요한 검색·청킹 코드만 복사·선별해 출처 commit/path/hash를 기록한다. BM25 또는 Dense 단독 검색기를 고정한 각 실험군으로 비교하며 Hybrid·P013/P014를 기다리지 않는다. 기존 Naive와 source-v2는 보존한다.

P007에서는 검색용 fact/span 정답·질문·tuning/holdout과 청킹 실험을 담당한다. P015 정책 대응표는 그 준비 근거이며 P013의 사람 승인 Ground Truth를 대신하지 않는다. PDF를 다시 작성하거나 답변 품질 평가기를 선구현하지 않는다. 지표·그리드·계산/자원 상한·복사 범위는 P015의 실제 산출물로 준비 검토한 뒤 확정한다.

## 예정 범위

1. 고정 크기 + overlap: 우선 문자 단위로 크기 200/400/800, overlap 0/20%를 분리해 비교한다. 초기 후보값이지 최적 설정이 아니다.
2. 문단/문장 경계를 우선하는 재귀 분할: 구분자 우선순위·긴 문장 fallback·overlap 의미를 고정한다.
3. 제목/섹션 기반 분할: 제목과 본문 연결·긴 섹션 분할·예외 조건의 부모 제목 보존을 관찰한다. PDF에서 제목을 정확히 추출하지 못한 문제는 청킹 효과와 분리한다.
4. 의미 기반 분할: 기존 로컬 BGE-M3로 인접 문장 의미 변화에 따라 경계를 선택하는 후보를 비교한다. 문장 경계 규칙·거리/threshold·최소/최대 크기·동점·추가 임베딩 비용을 확정한다. 구조 기반을 자동 semantic 알고리즘으로 부르지 않는다.
5. 한 번에 한 변수: parser/canonical corpus·질문·embedding·retriever·title enrichment를 고정한다. 다른 검색기 비교는 별도 실험으로 표시한다. 비교 전 실험 설정과 질문 분할을 저장한다.
6. 학습용 tuning 질문과 확인용 holdout을 구분한다. 기존14개는 이미 관찰된 tuning 자료이며 holdout이라고 부르지 않는다. 작은 합성 세트의 일반화 한계를 남긴다.

## 평가 설계

- 정답은 바뀌는 청크 ID가 아니라 검증한 동일 버전 원문 fact/span에 고정한다. P006의 평가 방식을 계승하되 P015의 새 원문 위치·인용·정책 대응을 바탕으로 검색 정답을 다시 검토한다. 각 전략의 chunk→source map으로 근거 회수 여부를 계산한다. 동일 사실의 중복 검색으로 점수를 올리지 않는다.
- 필수 근거 회수율: 질문별 필요한 fact 중 top-k의 원문 span 합집합이 필수 span 전체를 덮은 fact의 비율. 청크 경계에서 나뉜 근거를 여러 청크가 함께 회수하는 경우를 처리한다. 부분 coverage와 전 필수 근거 회수 성공률을 별도 관찰한다. 대체 가능한 근거/원문 사실 정의는 구현 전 확정한다.
- 청크별 Precision@K/Recall@K/MRR/nDCG는 전략별 qrels를 source 기준으로 다시 생성·검토한 뒤 보조 지표로 사용한다. 청크 분모가 달라져 숫자만 직접 비교하면 오해할 수 있음을 명시한다. MRR 하나로 복수 근거 회수를 평가하지 않는다.
- 같은 K 비교와 같은 전달 분량 예산 비교를 따로 한다. 큰 청크가 단지 더 많은 텍스트를 가져온 효과를 구분한다. 문자와 토큰 수를 혼용하지 않는다.
- 근거 없는 질문은 Recall 분모에서 분리한다. 청크 수·길이 분포·중복 범위·색인 크기·문서 임베딩/색인 시간·질문 검색 시간·상위 결과별 원문을 함께 저장한다.
- 전체 모델 답변 생성 없이 검색 평가를 먼저 수행한다. 좋은 검색 수치가 좋은 답변을 보장하지 않으므로 선정 후보와 고정 원문/청크·질문/검색 설정을 P013에 먼저 인계하고, P013/P014 이후 P008에서 생성·답변 품질·UI까지 검증한다. P013의 정답 준비에 검색 결과를 정답으로 사용하지 않는다.
- 비교값을 좋게 만들려고 질문/정답/실패 기록을 수정하지 않는다. 원문·정답 자체의 결함은 새 버전으로 분리한다.

## 준비 시 확정할 항목

실제 fixture 크기에서 차이가 드러나는 그리드, 문장 경계/구조 추출 규칙, 의미 분할 설정, source coverage와 관련성 grade/대체근거 산식, holdout 구성, 정답 검토 방법, manifest·CLI·보고서 스키마를 고정한다. 각 산식은 독립 작은 fixture와 중복/경계/부분 근거 예제로 검증한다.
