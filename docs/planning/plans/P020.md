# P020 — Hybrid 이후 리랭킹 자체 성능 평가

> 준비: 초안
> 실행: 미착수
> 우선순위: 85
> 선행: P010
> 승인 근거: 2026-11-04 사용자 “리랭킹 자체 성능 평가도 별도 P카드로 플랜에 확실히 반영해줘. Hybrid 이후에 진행하는 걸로.” 계획 등록 요청. 모델·입력·실행 예산을 준비 검토한 뒤 구현 인계한다.

## 목적과 순서

P010 Hybrid 검색 완료 후, 검색 후보를 재정렬하는 리랭커의 효과를 최종 답변 생성과 분리해 평가한다. 기존의 후속 후보를 본 카드로 명시적으로 등록한다. P013 답변 평가기와 P014 평가 방식 비교, P008 답변 비교 UI, P010 Hybrid의 선행 순서는 유지한다.

학습 질문은 “필요한 근거를 검색 후보 안에는 찾았는데, 리랭킹이 그것을 최종 top-k에 더 잘 올려주는가?”다. 검색 후보 밖의 누락과 후보 안의 순위 오류를 구분한다. 리랭킹 성능 개선을 최종 답변 개선으로 자동 해석하지 않는다.

## 범위와 비교 계약

- P010에서 확정한 원문·청크·질문·정답 근거·Hybrid 설정과 결과 snapshot을 고정한다. 동일한 질문별 후보 N개를 재정렬 전/후에 사용하고, 후보 ID·본문·원문 위치의 집합이 보존되는지 검증한다. 원문/청킹/검색기를 동시에 바꾸거나 재검색하지 않는다.
- 기준선은 Hybrid 원래 순위, 비교군은 같은 후보에 Cross-Encoder reranker를 적용한 순위다. 최초 모델과 정확 revision·한국어 적용 범위·라이선스·환경은 준비 검토에서 고정한다. 여러 모델 sweep은 별도 범위/예산 없이는 실행하지 않는다.
- 후보 수 N과 최종 K를 분리한다. 먼저 후보 N개가 포함한 필수 근거 회수율을 보고하여 리랭킹이 개선할 수 있는 범위를 드러낸다. 같은 후보에서 같은 K의 재정렬 전후를 질문별 paired 비교한다.
- 주 지표는 nDCG@K와 MRR@K이며, Recall@K·Precision@K·필수 fact/span 회수율·전체 필수 근거 회수 성공률을 함께 보고한다. 각 지표의 qrels 관련성 등급/임계값·할인/정규화·분모·미검색/0분모 처리를 READY 계약에서 명시한다. 여러 근거가 필요한 질문을 첫 정답 위치인 MRR만으로 평가하지 않는다.
- P007의 고정 원문 fact/span 및 chunk→source 매핑을 계승하고, 여러 청크에 나뉜 근거와 중복 근거를 처리한다. 청크별 관련성 정답(qrels)과 답변용 Reference Claims는 서로 다른 입력이다. LLM이 출력한 점수를 검색 정확도로 쓰지 않고, 고정 qrels와 실제 순위로 Python이 지표를 계산한다.
- 같은 K 비교와 같은 실제 전달 분량 예산 비교를 분리한다. 재정렬 후 문맥 선택에서 제외된 근거를 따로 기록하여 순위 개선과 전달 근거 개선을 구분한다. 근거 없는 질문은 Recall 분모와 분리하고 처리 정책을 표시한다.
- 후보당/질문당 지연, 총 검색+리랭킹 지연, 메모리 측정 범위, 모델 로딩 포함 여부와 cold/warm 조건을 기록한다. 품질 향상과 추가 비용을 함께 판단한다.
- 질문별 개선/악화/변화 없음, 조건·예외·숫자·유사 조항 혼동 사례를 원문/순위와 함께 보여주는 비교 보고서 및 학습 가이드를 만든다. 기존 검색 비교 UI의 재사용/연결 범위는 준비 검토에서 고정한다.
- 구현은 예정된 `3. Hybrid RAG/` 내 별도 실험 모듈로 구분하고 P010 기준선 artifact를 보존한다. 별도 큰 번호 폴더는 이번 카드만을 위해 만들지 않는다. P013 답변 평가기로의 입력 인계는 가능하게 하되 실제 답변 재생성·추가 LLM 평가를 본 카드의 검색 지표로 혼합하지 않는다. 해당 실행은 별도 명시한 범위/예산이 있어야 한다.

## 준비 검토와 착수 조건

P010 완료 commit·후보 snapshot/hash·선택 설정과 qrels 버전을 확인한다. 모델 revision/다운로드 크기·라이선스·입력 길이·긴 청크 처리·batch·N/K·메모리/시간/총 호출 한도·timeout/재시도·동점 정렬 규칙을 고정한다. 입력을 조용히 잘라 비교하거나 실패 질문을 제외하고 성공 지표만 보고하지 않는다. 오류·미실행·지원 불가와 낮은 순위 성능을 별도 상태로 보존한다.

학습에 이미 노출된 질문은 개발 세트로 명시한다. 독립 검증 세트가 있으면 튜닝 전에 분리·동결하고, 열람 후 독립 holdout이라고 다시 부르지 않는다. 지표 향상 자체를 완료의 필수 조건으로 삼지 않는다. 악화나 효과 없음도 재현 가능한 실험 결과로 완료할 수 있으며, 기본 채택 여부와 근거를 별도로 기록한다.

현재 카드는 계획 등록이며 구현 착수 계약이 아니다. 위 입력·예산·검증 기준을 확정한 준비 검토와 정확한 plan SHA 채택 후 dev가 실행한다.

## 검증 계획

- 손으로 순위와 기대값을 계산한 독립 fixture로 MRR/nDCG/Precision/Recall을 검증한다. 다중 근거·중복·동점·후보 부족·관련 근거 없음·K 경계 사례를 포함한다.
- 전후 후보 집합/본문/hash 동일성, 결정적인 동점 처리, 정답·평가 라벨의 모델 입력 유출 방지, 원문/색인/기존 결과 보존을 확인한다.
- 실제 모델 실행과 mock 오류 테스트를 구분한다. 입력 초과·timeout·부분 실패·재실행/누적 예산을 검증하고 실패 이력을 보존한다.
- 저장된 순위만으로 모델 재호출 없이 지표/보고서를 재현한다. 전체 질문 수와 지표별 유효/제외 수·이유를 보고하고 증거를 `docs/verification/p020/`에 보관한다.
