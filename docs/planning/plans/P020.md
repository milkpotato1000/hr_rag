> 선행: P010
> 승인 근거: 2026-11-04 리랭킹 자체 평가를 별도 카드로 Hybrid 이후 배치한 요청과 2026-11-28 사용자 “평가기 실험은 보류하고 Hybrid·리랭커 구현부터 진행하자. 그 순서로 플랜 반영해서 dev에 전달해줘.” 및 프로젝트 준비·직접 인계 위임.

## 목적과 순서

P010의 동일 질문·원문·청크·검색 후보 N개를 고정하여 none과 공개 HF 리랭커 두 모델의 순위·검색 지표·비용을 비교한다. 후보 밖 검색 누락과 후보 안 순위 오류를 구분한다. 선택한 리랭킹 결과의 문맥으로 최종 답변 생성까지 연결한다. P013/P014 평가기 실험과 P008을 기다리지 않고 독립 구현하되 보류된 평가기·모델 실험을 재개하지 않는다.

## 확정 범위와 계약

[실행 계약](../specs/P020-reranker-package-contract.md), [준비 검토](../reviews/P020-readiness-20261128.md), [직접 인계](../handoffs/P020.md)를 따른다. [기존 설계/SDK 조사](../specs/P020-reranker-design.md)는 근거이며 충돌 시 실행 계약이 우선한다. 기준 dev/personal-dev는 P010 완료 `3d99353b5aef3b683b24d0f7fa06b8a757dc1f83`이다.

- BGE reranker v2 m3 및 mMARCO mMiniLM CrossEncoder의 실제 local SDK adapter·격리 worker·정확 profile을 구현한다. none/모델 선택, 후보 N/최종 K/문자 예산, 전후 순위/근거/지연을 CLI/UI에서 연결한다.
- immutable 후보·재정렬·비교 artifact와 모델 없는 report/replay를 제공한다. qrels의 P/R/MRR/nDCG, 필수 fact/span 회수율·전체 필수 근거 충족, 실패·무정답·미판정 분모를 분리한다. 여러 근거가 필요한 질문을 MRR만으로 판단하지 않는다.
- 원문·질문·청킹·retrieval 후보를 고정해 paired 비교한다. 관련성 라벨을 worker 입력에 넣지 않는다. 후보 밖 정답을 Recall/IDCG 분모에서 빼지 않는다. 같은 K와 예산 후 실제 전달 근거를 구분한다.
- `3. Hybrid RAG/`와 설치 패키지·학습 가이드를 확장한다. 이전 단계/HR LangChain/GT/실패/보류와 기존 schema를 보존한다. 별도 큰 번호 폴더를 새로 만들지 않는다.
- 검증은 수기 score fixture·실제 SDK tiny 무작위 classifier·가짜 generation transport·독립 설치/허용 화면으로 수행한다. 사전학습 가중치 다운로드/로드·실제 LLM/API/Drive/개인키·평가기 호출0. 한국어 실모델 품질 비교와 채택 결정은 후속 live 계약에서 검증하며 이번 구현 완료로 갈음하지 않는다.

2026-11-04의 실제 성능·지연/메모리 비교 요구는 유지한다. 이번에는 실행 가능한 제품과 오프라인 검증을 전달하고 라이브 품질은 미검증으로 명시한다. 학습에 노출된 질문을 독립 holdout으로 다시 부르지 않는다. 성능 개선 자체를 완료 조건으로 강제하지 않으며 악화·효과 없음도 재현 가능한 결과로 기록한다. main 승격이나 공개 배포 채널 추가는 이번 범위가 아니다.
