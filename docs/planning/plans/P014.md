# P014 — Project B 내부 NLI 평가기와 LLM 평가 비교

> 준비: 초안
> 실행: 미착수
> 우선순위: 68
> 선행: P013
> 승인 근거: 2026-10-29 사용자 Project B 기본 평가기 다음에 NLI 비교를 진행하도록 계획 요청. 상세 실행 계약 준비 전.

## 목적과 범위

[P013](P013.md)의 동일 답변/추출 claims/실제 전달 문맥/승인 정답을 고정하고 NLI adapter를 추가해 LLM 평가기와 비교한다. [B 내부 평가 모듈 설계](../../architecture/project-b-generation-evaluation.md)를 따른다. 예정 위치는 같은 dev `evaluation/project_b/`이며 새 RAG 단계 번호를 만들지 않는다.

- 첫 실험은 ClaimVerifier만 바꾼다. Correctness matcher의 LLM↔NLI 교체는 별도 비교 축으로 검증한다. 생성 모델/청킹/검색/추출을 동시에 바꾸지 않는다.
- 사용자 제안 mDeBERTa-v3-base-mnli-xnli를 초기 후보로 검토한다. 한국어 HR의 부정/예외/수치·다중 청크/길이 초과·모순 fixture, 실제 tokenizer/label mapping/threshold와 의미 동등성 매칭 정책을 고정한다.
- 사람 검증 세트에서 claim 분류 정확도·혼동행렬·라벨별 P/R/F1, Faithfulness 점수 오차/일치도, Correctness 매칭/점수 정확도, 추론 시간·메모리·실패 유형을 비교한다. LLM과 NLI의 일치만으로 정답을 확정하지 않는다.
- 평가기의 길이 잘림·판정 불능·모델 오류를 보존한다. 여러 청크 결합은 실제 전달 문맥 안에서만 수행한다. Ground Truth/생성 결과를 평가에 유리하게 수정하지 않는다.
- 두 방식을 교체 가능한 형태로 유지하고 실제 결과에 따라 기본 평가기를 선택한다. NLI 성능 우위는 완료 조건이 아니다. 비교가 유효하게 완료되면 결과/한계를 P010·P008에 인계한다.

## 준비 시 확정

P013 데이터/claims/run/평가기 버전·승인/holdout·성능 기준, NLI 모델 revision·라이선스·환경/pin·입력 한도·다중 청크/상충 판정, 방향성/부분 매칭·threshold, 검증기와 matcher의 분리 실험 범위·모델 호출/자원 상한·반복/순서·측정도구·UI 비교 범위를 준비 검토에서 확정한다. 그전에는 초안을 유지한다.
