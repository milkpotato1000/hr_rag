# P024 — 공개 모델 기본·선택 LLM API 학습 경로와 설정 안내

> 준비: 준비 완료
> 실행: 완료
> 우선순위: 5
> 선행: 없음
> 승인 근거: 2026-11-27 사용자 API/로컬 모드를 분리한 학습 자료 구성 및 RAG 패키지 목표, 후속 HF 인기 공개 모델 기본·유료 LLM API 선택 요청. 프로젝트의 준비 검토·dev 직접 등록 위임 적용.

## 목적

학습자가 기본 공개 모델 경로와 선택 API 경로에서 무엇이 바뀌는지 알고, 같은 RAG 실험 흐름의 설정을 이해하도록 제품 학습 자료를 구성한다. 전체 방향은 [패키지 로드맵](../rag-package-roadmap.md)을 따른다. 첫 증분은 문서와 비실행 설정 예시다. 지원하지 않는 API 실행을 가능하다고 안내하지 않는다.

## 기획 준비

[준비 검토](../reviews/P024-readiness.md)와 [인계](../handoffs/P024.md)를 읽는다. P013 로컬 실행 보류와 별개로 수행 가능하다. 기존 HR 샘플·완료한 기능을 설명하되 P013 전체 완료나 모델 메모리 검증을 주장하지 않는다. 기존 계획/아티팩트는 보존한다.

## 범위와 계약

1. dev가 `docs/learning/rag-package/README.md`와 관련 안내를 작성한다. 기존 제품 README에서 한 곳 이상 연결한다. 주 독자는 초보 학습자이며 한국어 설명, 선택표, 한 개 공통 흐름도, 단계별 실험 질문·고정할 변수·관찰할 지표를 포함한다.
2. 기본 공개 모델/Ollama와 선택 LLM API 두 경로를 같은 흐름으로 설명한다. API는 생성·추출·판정 등 LLM 역할만 교체 가능하도록 설계하며 임베딩/리랭커는 공개 모델 기본 유지. HF 카탈로그는 후보와 이미 실행 검증한 모델을 구분한다. 라이선스·원본 HF ID·runtime/양자화/digest의 차이, 메모리 한계를 설명한다. BM25·RRF·규칙 청킹은 모델 아님을 명시한다.
3. `docs/learning/rag-package/examples/`에 JSON 형식의 비실행 local/api 설정 예시 2개를 둔다. `example_only: true`, source, llm.generation/evaluation, chunking, embedding, retrieval, reranker, evaluation 항목을 동일하게 보여준다. 모드 차이는 LLM 설정에 집중한다. provider/model 미결 값은 명확한 placeholder로 표시하고 실제 지원 목록으로 오인시키지 않는다. 키 자체 대신 `api_key_env` 이름만 적는다. 이 예시를 현재 CLI에 넣으라는 실행 명령을 만들지 않는다. 후속 adapter 카드에서 실제 schema 확정 예정이다.
4. Claude Code/Codex 각각에 복사할 작업 요청 예시를 제공하되 공통 저장소 규칙과 plan→dev를 따른다. 현재 실행 가능한 명령은 실제 저장소에서 확인한 것만 인용한다. 서버 시작·모델 다운로드·API 호출·P013 재개를 자동 유발하는 요청을 기본 실습으로 두지 않는다.
5. 기능 표에 기존 구현, 설정 예시만 제공, 후속 계획, 미검증을 구분한다. 실제 Drive 연결, API adapter, 범용 통합 패키지는 아직 완성으로 표시하지 않는다. 준비된 샘플과 나중에 사용자가 연결할 개인 문서를 구분한다.
6. 새 문서에서는 GT/qrels가 없으면 Correctness/검색 지표 N/A인 이유, Faithfulness와 정확성의 차이, 실패/미확정과 낮은 점수의 차이를 보여준다. 사용자 선택 API로 문서 일부가 전송됨과 키 보관·모델 호출 비용도 설명한다. API 실패 시 로컬로 또는 반대로 조용히 fallback하지 않는 설계 원칙을 적는다.

제품 코드·런타임·기존 평가 정답/승인·성공 실패 기록 수정, 모델 다운로드/로드·서버 시작·외부 API 호출·UI 재설계·새 원격·main 승격은 제외한다. 다른 미커밋 계획을 끼워 넣지 않는다.

## 검증 계획

JSON 2개 파싱, 링크/이미지/흐름도와 인용한 명령·파일 존재 확인, 비밀값 부재, 문서의 지원 주장 대조를 수행한다. 문서만의 수정에 모델 실행이나 과도한 단위 테스트를 추가하지 않는다. `docs/verification/p024/`에 실제 체크 결과와 제한을 기록하고 guard/기존 훅을 통과한다. 화면 검증이 불가능하면 렌더 관찰을 했다고 주장하지 않는다.
