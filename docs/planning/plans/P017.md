## 입력 구성

| 입력 | UI | 의미 |
| --- | --- | --- |
| 청킹 방식 | 드롭다운 | 고정 크기 / 재귀 / 구조 기반 / 의미 기반 / LLM 기반 |
| 크기 | 숫자 직접 입력 | fixed는 창 길이, 그 외는 기본 청크 최대 길이. 방식별 의미를 라벨에 표시 |
| 오버랩 | 숫자 직접 입력 | 겹칠 문자 수. fixed의 창 이동과 나머지의 분할 후 앞쪽 확장을 구분 |
| 의미 거리 임계값 | 숫자 직접 입력, semantic에서 표시 | 현재 거리 정의를 유지하고 임베딩 모델의 임의 교체와 분리 |
| 검색기 | 드롭다운 | BM25 / Dense |
| Top-K | 숫자 직접 입력 | 표시/평가할 상위 결과 개수 |
| 문자 예산 | 숫자 직접 입력 | 후보 집합에서 통째 청크를 골라 평가하는 총 문자 수 |
| 저장 실행·문서·질문 선택 | 드롭다운 유지 | 기존 객체 선택. 질문 직접 입력은 유지 |

숫자 직접 입력은 무제한 실행을 의미하지 않는다. 허용 최소/최대·단위·정수/실수·방식별 제약을 화면과 API에서 동일하게 검사한다. 크기를 입력해도 실제 청크는 구조/문장 경계 때문에 더 짧을 수 있다. 비고정 방식에서 overlap 적용 뒤 실제 길이가 기본 최대 크기를 초과할 수 있음을 설명한다.

기존 P007의 14개 설정은 선택 가능한 프리셋으로 남길 수 있으나, 프리셋을 선택하면 독립된 방식·수치 입력에 값을 채우는 형태로 한다. 사용자가 수치를 수정하면 사용자 설정으로 표시하고 원래 프리셋 이름으로 실행/저장하지 않는다. 적용되지 않는 수치는 숨기거나 비활성화하고 서버에도 의미 없는 값을 보내지 않는다.

## A/B 비교는 생성 이력에서 선택

2026-10-30 사용자 추가 요청: “a 실행 b 실행 리트리버 ab 테스트는 위에서 생성한 이력만으로 선택할 수 있도록.”

- 위 청킹 실험 영역과 A/B 실행 선택은 같은 저장 실행 이력 목록을 사용한다. 현재 원문 버전/hash와 호환되고 성공적으로 생성·저장된 청크 run만 A/B에서 선택할 수 있다. 아직 실행하지 않은 프리셋/입력 설정, 진행 중·실패·중단된 작업은 비교 대상으로 선택하지 못한다.
- A/B 영역에서는 새 청킹 방식을 독립적으로 조합하거나 청크를 자동 생성하지 않는다. 각 선택지는 방식·크기·오버랩·생성 시각·짧은 run ID를 표시하고, 실제 비교에는 불변 run ID와 저장된 설정을 사용한다. 위 입력을 수정해도 이미 선택한 저장 run의 설정은 바뀌지 않는다.
- 새 청킹 성공 후 같은 이력에 추가되어 A/B 선택지에도 반영된다. 실패/중단 작업은 작업 이력에는 남기되 성공 선택지에 섞지 않는다. 새로고침 후에도 유효한 저장 이력을 복원하며 이력이 없으면 먼저 청크를 생성하도록 안내한다.
- 기존 P007 결과는 위 저장 이력에서 출처가 표시된 상태로 확인·선택할 수 있고, 숨은 별도 A/B 프리셋 목록을 만들지 않는다. 선택한 검색기의 색인이 없으면 해당 run의 색인 준비 상태와 다음 행동을 안내하고 비교 실행을 막는다. 선택만으로 임베딩/LLM 호출이나 색인 작업을 시작하지 않는다.
- 서버도 run 등록·성공 상태·원문 호환성·색인 fingerprint를 검사하여 임의 run ID, 오래된/변조된 결과를 거부한다. 검색기는 기존 BM25/Dense 공통 선택을 유지한다. A와 B에 서로 다른 검색기를 동시에 적용하는 별도 비교 축은 이번 요구에서 확정된 것으로 보지 않는다.

## 실제 실행·재현성

- 모든 수치가 실제 알고리즘·API·CLI에 연결되어야 한다. UI에만 적용하고 코어에서 고정 기본값을 쓰는 구현은 실패다.
- 정규화한 전체 설정과 알고리즘/모델/프롬프트/원문 버전으로 실행·색인·캐시 fingerprint를 구분한다. 같은 설정 재생과 새 실행을 구분하며 다른 size의 결과를 재사용하지 않는다.
- 기존 실험/holdout/후속 P013 인계는 고정된 P007 결과로 보존한다. 사용자 설정 결과를 P007 공식 비교표에 자동으로 섞거나 후보를 자동 재선정하지 않는다.
- Top-K 결과와 문자 예산 결과는 별도 비교라는 현재 의미를 유지하고 각 영역에 사용 후보 수·선택 수·실제 문자 수를 명시한다. 예산 선택 청크/제외 이유를 확인할 수 있게 한다. 기존 후보 상한20 확대는 사용자 요구로 확정된 것이 아니므로 별도 범위 판단 없이 확대하지 않는다.
- LLM 크기를 바꿀 때 경계 검증뿐 아니라 prompt/schema/hash·window 입력 한도·전체 coverage·실패 처리도 함께 일치해야 한다. 기존 고정 프롬프트를 사용하며 새 size가 적용됐다고 표시하지 않는다.
- 기존 모델 호출/시간/임베딩/검색 ledger를 초기화하지 않는다. 추가 사용자 실험의 예산 정책은 기존 사용량 확인 후 준비 검토에서 정하며, 이 초안으로 상한을 늘리지 않는다.

## 확정 입력·자원 계약

- 문자 예산은 **정수 1~24,000자, 기본 8,000자**. Top-K는 정수1~20, 기본5, 예산 후보는 상위20으로 유지한다. 문자 예산은 LLM 청킹 크기/입력 window와 무관한 검색 시뮬레이션이다.
- fixed: size 100~2,000자, 기본400; overlap 0~min(400,size−100), 기본80. 최소 stride100으로 source-v4에서 과도한 청크 생성을 피한다.
- recursive/structure: 기본 최대 크기100~2,000자, 기본400; overlap 0~min(400,size−1), 기본0.
- semantic: 기본 최대 크기400~2,000자, 기본400; overlap 0~min(400,size−1), 기본0; cosine distance threshold는 유한 실수0~2, 기본0.25. 최소 분할 길이100과 기존630단위는 유지한다.
- llm: 기본 최대 크기400~1,200자, 기본800; overlap 0~min(400,size−1), 기본0. 권장 길이는200~400자로 유지하며 목표/최대의 차이를 표시한다. 기존630단위·35window(각 최대1200자/20단위) 유지. 기존 단위 최대400 때문에 그보다 작은 최대 크기는 이번 버전에서 허용하지 않는다.
- 사용자 설정은 category와 유효 숫자만 허용하고 결정적 normalized config ID/hash를 생성한다. canonical 설정을 round-trip할 수 있고 추가/불필요 필드는 거부한다. 기존 고정 config ID·14설정·원문·실험 산출물은 그대로 읽는다.
- 사용자 설정은 별도 algorithm/config 버전으로 표시하고 기존 frozen P007 실험 runner의 spec/후보/holdout을 변경하지 않는다. 새 CLI는 JSON config 파일로 같은 입력을 받는다.
- LLM dynamic prompt는 기존 prefix의 최대800 숫자만 검증된 값으로 치환하고 최대1200/20단위의 모든 window에 기존 보수 입력상한+출력1024≤8192 검사를 호출 전 수행한다. 실제 prompt/hash·설정·최대길이 검증을 일치시킨다. 모델/서버 num_ctx를 확대하지 않는다.
- 기존 cumulative ledger를 그대로 사용한다. 준비 시108/219 LLM,105/210 corpus 요청,2773/32000 embedding item,1638/2328 ranking, unresolved/pending 없음. 새 무제한 실험 예산이나 초기화 기능은 만들지 않는다. 남은 예산을 표시하며 소진 시 이유를 안내한다.
- P017 실제 검증은 deterministic 사용자 설정, semantic 사용자 설정, LLM 사용자 설정 최소1회, BM25/Dense A/B와 화면/독립 fixture를 검증한다. 기존 상한 내에서 전체 LLM1회(35windows, 재시도 포함70)와 필요한 한정 smoke만 수행한다. 잔여 예산 부족/미확정 provider 호출이 생기면 성공으로 숨기지 않고 그 검증을 보류한다.
- 새 사용자 LLM 실행은 선택한 설정으로 fresh 호출한다. 기존 설정과 다르거나 코드/prompt가 다르면 cache/replay로 혼용하지 않는다. overlap용 부모 경계 재사용은 크기·threshold·prompt 등 overlap 이외 설정이 같은 경우만 허용한다. 동일 설정 저장 재생은 실제 호출0임을 표시한다.
- 8003 서버에 실행 중 작업이 없음을 확인한 뒤 이 변경 적용을 위해서만 재시작한다. 다른 서버/모델은 재시작하지 않는다. 개별 실행 실패 원응답/진행 이력과 기존 P007 증거를 보존한다.

## 검증 계획

대표 사용자 설정(예: fixed 크기600·오버랩100)의 실제 경계/길이/원문 coverage를 독립 기대값과 대조한다. 정수/실수·빈 값·음수·0·NaN·무한대·오버랩≥크기 등 부적절한 조합을 API에서도 거부한다. 방식 변경 시 숨겨진 이전 값 누수, 캐시/색인 혼용, 모델 한도 초과, 저장 재생/새 실행, 문자 예산 선택 결과와 화면 일치를 검증한다. 고정 P007 결과 재생과 기존 Naive UI를 회귀 확인하고 키보드·모바일 입력을 실제 브라우저에서 검증한다.

A/B는 생성 이력 없음, 생성 성공 후 목록 갱신, 실패 이력의 선택 차단, 새로고침 복원, 입력값 수정 후 저장 run 불변, 색인 미준비, 원문 버전 불일치, 임의 run ID 요청을 검증한다. 선택한 이력과 실제 검색 청크·결과의 run ID가 일치해야 한다.

입력 도움말의 단위·추천값·허용 범위가 서버 검사와 일치하는지, 방식 변경 시 갱신되는지, 추천 밖/허용 안 입력과 실제 한도 초과가 구분되는지 확인한다. 모바일·키보드에서 상시 도움말과 필드 오류를 읽을 수 있어야 한다.
