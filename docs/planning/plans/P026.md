# P026 — 범용 문서 snapshot과 청킹·검색·선택 LLM 답변 연결

> 준비: 준비 완료
> 실행: 미착수
> 우선순위: 7
> 선행: P025
> 승인 근거: 2026-11-27 사용자의 문서·모델·청킹·검색 선택형 RAG 교육/실사용 패키지 목표. 2026-11-27 준비 검토와 프로젝트 위임에 따라 준비 완료. 실모델/API 실행은 제외.

## 목적

P025의 모델 호출 경계를 실제 문서 기반 RAG에 연결한다. 첫 통합은 로컬 PDF/TXT/Markdown snapshot → 규칙 청킹 → BM25 → 전달 문맥 선택 → 선택 LLM 생성 → 코드 검증한 원문 인용까지다. HF 임베딩·Dense/Hybrid·리랭커의 확장 지점을 만들되 미구현 옵션을 동작한다고 표시하지 않는다. 범용 패키지의 첫 E2E이며 기존 Naive/P007 실험 기준선은 보존한다.

## 기획 준비

현재 `2. Document Chunking/scripts/source_io.py`는 synthetic=true/Google Drive fixture만 허용하고 `experiment_common.py:source`는 고정 source-v4 파일만 허용한다. 이 계약을 완화하지 않고 별도 일반 문서 입력 계약을 만들어야 한다. 순수 청킹·BM25 알고리즘을 선별 재사용할 때 원본 SHA·경로·hash를 남기고 문서 provenance/페이지 매핑/유니코드 offset을 유지한다. 기존 Qwen-only Generator lock을 fake API metadata로 채우는 우회는 금지한다.

PDF는 기존 ingestion-lock의 pypdf 6.21.2·20MiB/100페이지/100만자/30초 격리 파서 사례를 검토한다. 새 package 의존성·설치 명령·지원 Python·추출 실패/스캔·표·암호 PDF 처리 범위를 READY에서 확정한다. PDF를 모두 완벽하게 해석한다고 주장하지 않는다. 임의 로컬 문서/실제 Drive snapshot은 synthetic로 라벨링하지 않는다.

P025 구현 완료 API/CLI/응답 스키마를 관찰하고 명시 계약을 연결한다. 실제 모델/API 실행 없이 고정 transport로 E2E를 검증할 수 있어 P013 중지와 독립이다. 실제 생성 품질/메모리 실험은 별도 권한 범위다.

## 확정 계약

[일반 문서 RAG 통합 계약 v1](../specs/P026-document-rag-contract.md)과 [준비 검토](../reviews/P026-readiness.md)를 따른다. P025의 exact 완료를 확인하고 파일 위치·입출력·CLI·검증/의존성을 고정했다. 아래 준비 항목은 확정 계약으로 해소되며 새 원격/개인 문서 수집/실모델 실행을 허용하지 않는다.

## 범위

- 일반 source snapshot 및 canonical document/page/section/chunk 계약. 해시/원문 페이지·offset·정규화·parser version 기록, 새 output 경로, 변경된 source/index 자동 혼용 방지.
- fixed/recursive/structure 규칙 청킹과 설정 선택·같은 원문 비교. 긴 섹션은 상한에 따라 다시 분할하고 heading path를 metadata로 유지한다. 원문 slice와 추가 제목 표현은 구분한다. semantic/LLM 청킹은 기존 P007 학습과 향후 adapter 연결 범위를 명시한다.
- BM25 첫 검색 구현과 추후 Dense/Hybrid 인터페이스. 후보 top-k와 문맥 예산·최종 포함/제외를 분리 기록한다. 제목이 붙은 표시 텍스트를 원문 quote로 속이지 않는다.
- P025 generation role을 사용하는 실제 ask와 모델 미호출 preview, 고정 질문 집합의 비교 run. no-context는 모델 호출 없이 보류. JSON 답변 schema·citation IDs는 실제 전달된 청크만 허용하고 인용 원문은 코드로 결합한다. malformed/미지원/시간초과를 답변으로 통과시키지 않는다.
- config 선택 모델·role·source/chunk/index fingerprint·프롬프트·실제 전송 문맥·응답 status/usage/지연을 기록한다. GT/qrels가 없으면 품질 지표 N/A. fake transport 실험은 실제 모델 답변으로 기록하지 않는다.
- 실제 개인 문서/키는 저장소 밖의 사용자 지정 경로를 기본으로 하고 공개 검증에는 합성 자료만 사용한다. 기존 UI는 보존하며 범용 UI 연결은 별도 후속이다.

## 검증 계획

P025 완료 후 실제 연결을 기준으로 입력 계약·기대값·CLI와 test entrypoint를 확정한다. PDF 페이지 provenance, 청킹 누락/중복·긴 섹션, 검색/문맥 truncation, 인용 whitelist, 모델 미호출 경로, 설정별 재현성과 실패 보존을 독립 fixture로 검증한다. 모델 품질 PASS와 분리한다.
