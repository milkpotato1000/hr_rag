## 목적과 준비

현재 `1. Naive RAG/`에서 모델이 정확한 답변을 만들고도 quote 복사 오류로 보류되는 문제를 줄인다. 모델은 답변과 실제 전달 문맥의 청크 ID만 선택하고, 코드는 해당 요청의 문맥 snapshot에서 청크 전체 원문과 출처를 찾아 citations를 조립한다.

보고된 식대 질문은 BM25가 welfare-meal을 검색/전달했고 답변 내용도 맞았으나 quote의 “휴:” 삽입으로 기존 검증이 보류한 사례다. 실제 재현 여부는 새 증거에서 구분한다. dev의 P006 증거에는 PDF 줄바꿈을 생략한 q06의 동일 유형 실패가 있다. 기존 검증이 고장났다고 주장하거나 검색 실패로 분류하지 않는다.

[준비 검토](../reviews/P009-readiness.md)는 dev 6644bac5d6a0e2511bf7df61002a79590e935bdd의 코드·lock·P006 피드백·완료 증거와 채택 상태를 확인했다. P007/P008은 초안으로 유지하며 P009가 다음 준비 완료 dev 작업이다.

## 계약 변경 범위

이 카드는 P004의 모델 출력에 quote를 요구하는 부분과 이에 의존한 현재 코드/lock/프롬프트를 앞으로의 실행에서 대체한다. P004~P006 카드 요구 문구·과거 실행 로그·실패 증거를 소급 수정하지 않는다. 기존 모델·digest·양자화·Ollama 버전·sampling·num_ctx/num_predict·BM25/Dense·top-k·문맥 선택·청크/색인/원문 hash는 변경하지 않는다. 재검색·추가 생성·ID 재발급·문장 단위 인용은 범위 밖이다.

적용 대상은 scripts/rag.py, generation.py, setup_generation.py, 새 프롬프트 파일, generation-lock.json, serve.py 상태 메타데이터, 관련 테스트·학습 문서다. 기존 실제 UI와 CLI 및 P006의 명시 chunks 경로가 같은 코어를 사용한다.

## 모델 응답과 최종 인용 계약

모델 응답은 다음 스키마로 고정한다.

```json
{"status":"answered","answer":"재택근무일과 휴가일에는 식대가 지원되지 않습니다.","citations":[{"chunk_id":"welfare-meal"}]}
```

- 최상위 키는 status/answer/citations만 허용한다. status는 answered 또는 abstained, answer는 비어 있지 않은 문자열이다. 각 citation 객체의 키는 chunk_id 하나만 허용한다.
- answered에는 하나 이상의 고유한 청크 ID가 필요하다. abstained에는 citations=[]만 허용하고 기존 표준 보류 문구와 model_abstained 사유를 사용한다. 중복 ID, 빈 ID, 잘못된 타입, 없는 ID, 검색됐지만 실제 전달되지 않은 ID, quote나 source 등 추가 키는 거부한다.
- 모델에 보내는 JSON schema는 요청별 실제 전달 contexts의 ID를 enum 허용 목록으로 갖는다. 전역 schema/lock을 in-place 변경하지 않는다. 다른 요청의 ID나 전체 corpus의 ID가 섞이지 않도록 매번 독립 구성한다. enum만 신뢰하지 않고 코드에서 같은 허용 목록을 다시 검사한다.
- 기존 chunk_id를 그대로 사용한다. ID를 추측하거나 오탈자를 보정하지 않는다. 전달 문맥의 중복 ID/잘못된 text는 내부 실행 오류로 검출한다.
- 유효한 answered는 모델이 선택한 순서로 최종 citations를 조립한다. 각 항목은 chunk_id, quote, source, title, version, document_id를 가진다. quote는 실제 전달 문맥에 저장된 text 전체와 정확히 같아야 한다. strip/줄바꿈 정규화/요약/말줄임/문장 추출을 하지 않는다. 최종 인용은 더 넓은 corpus나 응답 시점에 다시 읽은 변경 파일에서 가져오지 않는다.
- 외부 API의 citations/quote 필드는 유지하므로 기존 화면은 원문 인용을 계속 표시한다. trace에 citation_mode=full_chunk_from_transmitted_context와 응답 계약 버전을 표시한다. 전체 청크 인용이 특정 문장 인용이라는 인상을 주지 않게 학습 안내를 고친다.
- 유효하지 않은 모델 JSON/ID/추가 키는 기존 invalid_model_response 보류와 검증 사유를 유지한다. provider/timeout은 기존 오류 경로를 유지한다. no_context는 모델 호출 0회, 문맥이 있으면 생성 최대 1회다.
- 원문 문자열 일치를 보장하는 것과 선택 근거가 답변을 의미상 지지하는 것은 별개다. semantic_support=not_automatically_evaluated를 유지하며 잘못된 근거 선택/환각이 해결됐다고 주장하지 않는다.

## schema·프롬프트·lock·trace

새 system-v3 프롬프트를 추가해 근거 ID만 선택하도록 지시한다. 기존 v1/v2 파일은 과거 비교용으로 보존한다. 부정적 결론(불가/제외/미지원)도 근거가 있으면 answered라는 지시, 다중 조건·예외 보존, 자료 속 명령 무시, 보류 기준은 유지한다.

generation-lock의 schema_version/response contract를 명시적으로 올리고 정적 ID-only schema template과 요청별 enum 생성 규칙을 고정한다. 요청별 ID는 lock에 저장하지 않는다. load_generation_lock과 setup_generation은 새 계약을 일관되게 검증한다. 모델/런타임 불일치 거부를 약화하지 않는다. 승인된 기존 lock→새 lock 변경의 before/after diff/hash·이유를 P009 증거에 기록하고 이전 lock은 Git/증거로 보존한다. setup 재실행은 현재 lock/모델이 일치하면 재사용하고 임의 metadata 덮어쓰기를 계속 거부한다.

실제 /api/chat에 전송한 dynamic schema와 hash·허용 ID 목록·prompt 버전/hash·원본 모델 응답·검증 결과·완성된 인용의 원문 출처를 trace로 확인할 수 있게 한다. trace.request.format이 정적 template을 실전 요청처럼 표시하지 않게 한다. no_context에 호출하지 않은 요청을 실제 전송으로 표시하지 않는다. setup의 빈 근거 smoke는 enum=[] 문제를 피하도록 maxItems=0 등 유효 schema로 구성하고, 실제 API의 지원을 확인한다.

## 검증과 실제 인계

- 올바른 ID로 원문 전체가 문자열 및 UTF-8 재인코딩 기준 동일함을 독립 기대값으로 검증한다. 한글·개행·앞뒤 공백·따옴표·PDF 줄바꿈을 포함한다.
- 미전달/미존재/빈/숫자/배열/객체 ID, 중복 ID, 빈 answered 근거, abstained 비어 있지 않은 근거, quote/source/title 추가 키, 최상위 추가 키, invalid JSON을 검증한다. 복수 근거 순서와 정확 조립, no_context·provider·timeout·stale 회귀를 유지한다.
- 동시/연속 서로 다른 문맥의 요청에서 enum과 인용 매핑이 섞이지 않는지, schema template/lock이 변하지 않는지, provider spy로 실제 전송 schema와 trace가 일치하는지 검증한다. 테스트의 모의 응답은 실제 모델 품질 증거로 표시하지 않는다.
- 최초 보고된 식대 질문을 BM25 top-k5·기존 설정으로 실제 Qwen에 실행한다. welfare-meal 전달, status=answered, 재택/휴가일 미지원의 정확한 의미, 코드 인용과 원문 완전 일치를 확인한다. 정상 결과가 안 나오면 원응답·실패를 보존하고 원인을 분리해 수정/재검증한다. 검증을 통과시키려고 모델/검색/문서/질문을 바꾸지 않는다.
- 기존 14개 질문을 실제 모델로 같은 고정 설정에서 실행해 정확/부분/오답/과도보류/적정보류/오류와 인용 구조/의미지지를 분리 기록한다. 모든 질문 정답을 완료조건으로 추가하지 않으며 종전 품질값과 비교할 때 프롬프트/schema 변경·생성 변동성을 명시한다. 복수 근거 q03, 근거 없음 q13과 P006 PDF q06을 포함해 신규 방식의 한계를 관찰한다.
- 기존 전체 회귀·명시 source-v2 corpus·단독 복사 실행을 확인한다. 실제 HTTP 및 브라우저에서 식대 질문의 답변/전체 청크 인용/trace와 system-v3 metadata를 확인하고 필요한 경우 소유 서버만 안전하게 재시작해 사용 화면에 반영한다.
- docs/verification/p009/에 최초 실패·수정·최종 PASS, 비교 기준/lock diff·실제 trace·원문 대조 rubric·브라우저 증거와 보존 hash를 커밋한다. README/LEARNING_GUIDE에 모델의 근거 선택과 코드의 원문 조립, 의미 검증 한계를 설명한다. 코드·테스트·문서·증거·P카드 실행 로그를 dev에 정상 커밋/push한다.
