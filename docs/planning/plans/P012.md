## 목적과 기준

P011의 ADOPT_LANGCHAIN 판정 이후 학습자는 기본 화면에서 LangChain으로 질문하고 검색·문맥·답변을 관찰한다. Direct/LangChain 구현 선택과 A/B 비교는 별도 실험 메뉴로 옮긴다. 검색 방식(BM25/Dense), top-k, 문맥 예산의 학습 조작은 기본 화면에 유지한다.

기준 dev는 `150884f5576aa75cdb324f66ff0a26e4fdf97d2b`다. 이 커밋의 `docs/verification/p011/adoption-decision.json`과 `final-review.md`에서 P011 완료·ADOPT_LANGCHAIN·미해결 차단 없음과 고정20질문 반복 비교의 한계를 확인했다. 기존 조건 누락·과도 보류가 해결됐거나 속도가 개선됐다는 의미로 표시하지 않는다.

[상세 화면·실행 계약](../../architecture/langchain-learning-default.md)은 이 카드의 필수 계약이다. P011의 당시 Direct 기본값과 완료 증거는 역사적 사실로 보존하고 이 후속 카드에서만 현재 기본값을 변경한다.

## 구현 범위

- `1. Naive RAG/variants/langchain/`의 현재 실행 래퍼·web_compare·안내를 확장한다. 새 큰 번호 폴더나 프레임워크·의존성은 추가하지 않는다.
- 기본 `/`는 LangChain 단일 실행 학습 화면이다. 구현 선택기·A/B 비교 버튼/결과는 별도 `/experiments/implementation`의 “실험 → 구현 비교”로 이동한다.
- 현재 비교 서버 `/api/ask`, `scripts/ask_compare.py`, `scripts/comparison.py`는 implementation 생략 시 LangChain으로 통일한다. 명시적 direct는 실험·재현 호환용으로 지원한다. `/api/compare`는 기존 Direct→LangChain 두 실행과 결과·실패를 보존한다.
- 원래 Naive와 후보의 보존된 `rag.py`/`ask.py`/`serve.py`/web 등 Direct 사본은 기준선으로 유지한다. 기본 학습 진입 안내는 후보 서버8001로 통일하고 기존8000은 직접 구현 기준선이라고 명시한다. 사용 중인 포트를 빼앗지 않는다.
- 메뉴 이동·뒤로가기·새로고침·요청중 조작·JSON 내보내기와 실패 처리를 검증한다. 기본/실험 결과를 서로의 새 실행 결과로 표시하지 않는다.

## 검증과 인계

기본값 라우팅·명시 선택·오류·생성 호출 수·직렬 잠금의 자동 회귀, 실제 CLI/API/브라우저의 LangChain 실행·근거 없음·실험 A/B·실패·좁은 화면·다운로드를 수행한다. 검증 증거와 실패/재검증은 `docs/verification/p012/`에 남긴다. UI 변경만으로 P011의120슬롯 비교를 반복하지 않으며 검색·생성·모델 payload의 의미 변경은 이번 범위가 아니다.

완료 후 다음 작업은 별도 공개 설치형 plan-dev 하네스 제작이다. 이는 HR RAG 번호 단계/P카드로 구현하지 않으며 이 카드가 다른 저장소 생성·게시를 수행하는 작업은 아니다. P010 Hybrid는 초안을 유지한다. 사용자의 작업 전환 순서를 roadmap에 기록하고 dev는 P012 완료 후 Hybrid를 자동 착수하지 않는다.
