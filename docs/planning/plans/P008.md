# P008 — 청킹 실험 화면과 최종 답변 품질 비교

> 준비: 초안
> 실행: 미착수
> 우선순위: 80
> 선행: P007
> 승인 근거: 사용자 원문·청킹·검색/답변 실험 학습 추가 요청 범위 내 후속 기획, 상세 실행 계약 준비 전

## 목적과 준비

P007에서 검색/비용 결과를 얻은 후보를 기존 학습 화면과 실제 Qwen 생성 경로로 연결한다. 사용자는 원문→분할→검색 후보→실제 전달 근거→답변까지 추적하며 가설을 검증한다. 2026-10-28 사용자 결정에 따라 Hybrid 이후의 세 번째 학습 단계에서 수행하며, 예정 위치 `3. Document Chunking/`에 기존 코어를 복사·선별해 재사용한다. Naive/Hybrid 기준선은 보존하고 정확한 복사 범위는 준비 검토에서 정한다. P007의 실제 결과/선정 기준·API·예산 측정·UI 스키마를 검토한 뒤 준비 완료로 전환한다.

P009 완료 이후의 답변 비교는 ID-only 모델 선택과 코드의 전체 청크 인용 계약을 기준으로 한다. 과거 quote 생성 방식과 비교할 때 계약/프롬프트 버전을 구분한다.

P011의 LangChain 비교·판정 → P010 Hybrid 이후 수행한다. P011에서 선택된 기반과 P010의 실제 결과/출처를 확인하며 LangChain 채택 성공을 미리 전제하지 않는다.

## Project B 평가 재사용

[P013](P013.md)/[P014](P014.md)의 별도 평가 모듈을 재사용해 실제 전달 문맥 기반 Faithfulness와 승인 reference 기반 Factual P/R/F1을 표시한다. 기존 원문 rubric 검토도 유지한다. P007에서 새 원문을 작성하면 원문 hash/시행일·span에 맞춘 Ground Truth 버전을 사람 재승인한 뒤 비교한다. 평가기 버전은 A/B 사이에 고정하고 정답 미승인·평가 미실행/오류/판정 불능을 점수로 위장하지 않는다. 평가기 자체를 P008에서 다시 만들지 않는다.

## 예정 범위

- 문서 원천 Google Drive와 현재 fixture/실제 연결 상태·snapshot 버전·원본 링크(실제 확인된 경우만)를 표시한다. 로컬 캐시 경로를 HR 업로드 장소로 설명하지 않는다.
- 새 corpus의 기본값 적용/명시 선택 시점과 기존 15청크/source-v2 재현 경로를 준비 검토에서 확정한다. 화면에서 가상 자료·corpus 버전·실제 Drive 연결 여부를 구분한다. 원문에 없는 제목/섹션 메타데이터를 quote에 덧붙이지 않는다.
- 원문/PDF 페이지·추출 텍스트·청크 경계/overlap을 확인하고 청킹 방식·크기·겹침·corpus 버전을 선택하는 화면을 제공한다. 색인 생성 전/진행/실패/준비 상태, 기존과 새 색인의 혼용을 명확히 처리한다.
- 같은 질문에서 실험 A/B의 검색 순위·원문 위치·필수 근거 회수·중복·선택/제외 문맥·답변/인용·보류·시간을 비교한다. 정답/평가지표는 평가용으로만 쓰고 모델 프롬프트나 검색 입력에 넣지 않는다.
- 현재 '문맥 예산 · 문자'는 '검색 근거 최대 분량 · 문자'로 설명한다. 청크 크기, 검색 K, 근거 분량, Qwen 실행 num_ctx, 모델 지원 길이, 출력 여유를 구분한다. 8000문자·8192토큰은 초기 실행 설정이며 모델 고유 사양/최적값으로 표시하지 않는다.
- 토큰 예산 검증은 정확한 현재 모델 tokenizer/template 또는 실제 런타임의 계측 가능 범위를 먼저 확인해 계약화한다. 단순 문자 비율을 정확한 토큰 수로 표시하지 않는다. 관측 토큰과 사전 추정치를 구분하고, 전체 prompt/출력 여유/overflow 처리·묵시적 잘림 탐지 가능 여부를 명시한다.
- 검색 후보의 근거 회수율과 예산 적용 후 실제 전달 근거 회수율을 따로 표시한다. 검색은 성공했지만 문맥에서 빠진 경우를 생성 실패와 구분한다.
- P007에서 정한 후보 선정 규칙으로 baseline과 비교 후보를 선정한다. 동일 질문·모델/digest·프롬프트·생성 설정을 고정해 실제 답변을 비교한다.
- 질문별 사실 정확성·필수 조건 누락·근거 충실성·인용의 구조/의미·과도 보류·근거 없는 단정을 원문 rubric으로 검토한다. 생성 모델의 자기평가만을 정답으로 삼지 않는다. Codex 대조/사람 검토/자동 검사 주체를 명시한다.
- 검색 점수 개선과 답변 개선이 불일치하는 사례도 보존한다. cold/warm·문서 구축 비용·검색/생성 시간과 모델 오류를 분리한다.
- 기존 고정15청크 기준선과 재현 경로를 보존한다. API/단위/회귀 테스트와 실제 브라우저·실제 모델 E2E·좁은 화면 검증 후 README·LEARNING_GUIDE를 업데이트한다.
