# P008 — 청킹 실험 UI의 최종 답변·평가 결과 확장

> 준비: 초안
> 실행: 미착수
> 우선순위: 70
> 선행: P007, P014
> 승인 근거: 사용자 원문·청킹·검색/답변 실험 학습 추가 요청 범위 내 후속 기획, 상세 실행 계약 준비 전

## 목적과 준비

P007에서 구현한 원문·청크·검색 비교 UI와 선정 후보를 이어받아 실제 Qwen 생성·평가 결과를 연결한다. 사용자는 원문→분할→검색 후보→실제 전달 근거→답변까지 추적한다. 2026-10-29 순서 변경에 따라 `2. Document Chunking/`의 P016/P007 결과를 이어받으며 P013/P014 평가기를 사용할 수 있게 된 후 수행한다. 기존 Naive 기준선을 보존하고 P007 결과/선정 기준·API·예산 측정·UI 스키마를 검토한 뒤 준비 완료로 전환한다.

P009 완료 이후의 답변 비교는 ID-only 모델 선택과 코드의 전체 청크 인용 계약을 기준으로 한다. 과거 quote 생성 방식과 비교할 때 계약/프롬프트 버전을 구분한다.

기반은 P011 ADOPT_LANGCHAIN/P012 및 P007의 실제 출처로 확인한다. Hybrid는 선행이 아니며 P008 완료 이후 P010에서 검색 결합만 비교한다. 원문·청크·검색 비교 UI는 P007에서 먼저 제공하며 이 카드는 그 UI에 답변·인용·실제 전달 문맥·평가 점수를 추가한다. 자동 답변 평가가 필요한 범위는 P014 이후로 유지한다.

## Project B 평가 재사용

[P013](P013.md)/[P014](P014.md)의 별도 평가 모듈을 재사용해 실제 전달 문맥 기반 Faithfulness와 승인 reference 기반 Factual P/R/F1을 표시한다. 기존 원문 rubric 검토도 유지한다. P016 원문이 후속 개정되면 원문 hash/시행일·span에 맞춘 Ground Truth 버전을 사람 재승인한 뒤 비교한다. 평가기 버전은 A/B 사이에 고정하고 정답 미승인·평가 미실행/오류/판정 불능을 점수로 위장하지 않는다. 평가기 자체를 P008에서 다시 만들지 않는다.

## 예정 범위

- P007의 문서 원천/fixture 상태·snapshot·원문 진입 화면을 재사용한다. 실제 Drive 연결을 새로 구현하지 않으며 로컬 캐시를 HR 업로드 장소로 설명하지 않는다.
- 새 corpus의 기본값 적용/명시 선택 시점과 기존 15청크/source-v2 재현 경로를 준비 검토에서 확정한다. 화면에서 가상 자료·corpus 버전·실제 Drive 연결 여부를 구분한다. 원문에 없는 제목/섹션 메타데이터를 quote에 덧붙이지 않는다.
- P007의 원문/PDF·추출 텍스트·청크/설정·색인 상태·검색 A/B를 보존하고 답변과 평가 결과에서 해당 원문/청크/run으로 연결한다. 화면 중복 재구현 대신 기존 UI/API 확장으로 처리한다.
- 같은 질문에서 실험 A/B의 검색 순위·원문 위치·필수 근거 회수·중복·선택/제외 문맥·답변/인용·보류·시간을 비교한다. 정답/평가지표는 평가용으로만 쓰고 모델 프롬프트나 검색 입력에 넣지 않는다.
- 현재 '문맥 예산 · 문자'는 '검색 근거 최대 분량 · 문자'로 설명한다. 청크 크기, 검색 K, 근거 분량, Qwen 실행 num_ctx, 모델 지원 길이, 출력 여유를 구분한다. 8000문자·8192토큰은 초기 실행 설정이며 모델 고유 사양/최적값으로 표시하지 않는다.
- 토큰 예산 검증은 정확한 현재 모델 tokenizer/template 또는 실제 런타임의 계측 가능 범위를 먼저 확인해 계약화한다. 단순 문자 비율을 정확한 토큰 수로 표시하지 않는다. 관측 토큰과 사전 추정치를 구분하고, 전체 prompt/출력 여유/overflow 처리·묵시적 잘림 탐지 가능 여부를 명시한다.
- 검색 후보의 근거 회수율과 예산 적용 후 실제 전달 근거 회수율을 따로 표시한다. 검색은 성공했지만 문맥에서 빠진 경우를 생성 실패와 구분한다.
- P007에서 정한 후보 선정 규칙으로 baseline과 비교 후보를 선정한다. 동일 질문·모델/digest·프롬프트·생성 설정을 고정해 실제 답변을 비교한다.
- 질문별 사실 정확성·필수 조건 누락·근거 충실성·인용의 구조/의미·과도 보류·근거 없는 단정을 원문 rubric으로 검토한다. 생성 모델의 자기평가만을 정답으로 삼지 않는다. Codex 대조/사람 검토/자동 검사 주체를 명시한다.
- 검색 점수 개선과 답변 개선이 불일치하는 사례도 보존한다. cold/warm·문서 구축 비용·검색/생성 시간과 모델 오류를 분리한다.
- 기존 고정15청크 기준선과 재현 경로를 보존한다. API/단위/회귀 테스트와 실제 브라우저·실제 모델 E2E·좁은 화면 검증 후 README·LEARNING_GUIDE를 업데이트한다.

## 준비 시 확정할 항목

실제 P007 manifest/보고서·코어 인터페이스, 실험 UI/API 계약, 후보 선정·holdout 공개 시점, 토큰 계측과 넘침 처리, 모델 실행량·재실행/부분 실패 정책, 화면별 완료 기준을 확정한다. 자동 준비 완료·임의 전수 대량 생성은 하지 않는다.
