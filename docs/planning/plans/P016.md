# P016 — 장문 가상 HR 규정집과 청킹 비교용 원문 확장

> 준비: 준비 완료
> 실행: 미착수
> 우선순위: 66
> 선행: P015
> 승인 근거: 2026-10-29 사용자 dev 요청 R20261029-593e4840 및 plan 채팅 “실제 회사의 규정집처럼 실험하는게 효과가 좋을 것 같아.” + 준비 검토 위임 + docs/planning/reviews/P016-readiness.md

## 목적과 선행

실제 규정집처럼 길고 계층적인 가상 문서를 만들어 청킹의 경계·문맥 보존·비용 차이를 관찰할 수 있게 한다. 분량이 늘면 특정 알고리즘의 성능이 좋아진다고 미리 판정하지 않는다. [P015](P015.md)는 기존 정책을 보존한 PDF6개/6페이지로 완료됐다(dev `7980162d9204d0443235f4dabaa835c0d19a39fc`). canonical 192~469자의 짧은 원문은 보존 기준선으로 남긴다. 이번 새 정책/절차 확장은 완료 P015의 수정이 아닌 후속 범위다.

[준비 검토](../reviews/P016-readiness.md)와 [입력 근거](../reviews/P016-baseline.json), [문서 구조 규격](../specs/P016-corpus-spec.json)을 따른다. P016은 문서 작성·검증 작업이며 청킹 구현·실험은 [P007](P007.md)에서 한다.

## 위치·버전·보존

- `2. Document Chunking/data/source-v4/`에 새 Markdown6개와 PDF6개, fixture catalog, snapshot/cache, extracted canonical/pages, section map, 정책 목록/대응표, 인계 manifest를 만든다. 새 큰 번호 폴더는 만들지 않는다.
- 기존 `1. Naive RAG/`, `source-v3/` 전체와 P015 완료 카드/검증 증거는 byte 보존한다. source-v3를 새 본문으로 덮어쓰거나 같은 버전으로 재생성하지 않는다. 원문 간 비교는 corpus 개정 비교이지 청킹 성능 개선이 아니다.
- P015 PDF/추출 도구·고정 의존성을 재사용한다. v4 전용 도구 또는 명시 버전/출력 경로 인자로 확장할 수 있지만 기존 기본값과 v3 재현 결과를 보존한다. stage-manifest의 과거 항목은 유지하고 원본 full SHA/path/hash 및 이번 변경 이유를 추가한다. 부모 단계 import·symlink 의존을 만들지 않는다.
- PDF만 수집 대상으로 등록하고 편집 Markdown, 해설, 정책 대응표, 예시는 중복 수집하지 않는다. 실제 Drive 대신 fixture를 사용한다. 가상 규정임을 각 문서 앞에 표시하며 실제 회사명·실제 결재/법적 기준을 꾸미지 않는다. 시행일은 unknown/null, corpus 버전은4로 기록한다.

## 허용하는 가상 정책 확장

1. 기존 source-v3 및 그 정책 대응표의 전체 주장을 출처로 삼는다. 수치·지급량·발생/소멸·사용 기한·대상/제외·승인 주체·기존 예외를 모두 보존한다. 기존 생일휴가·포인트, 연차·이월, 재택 대상·빈도, 복지 지급, 교육·출장 규칙의 의미를 바꾸지 않는다.
2. 새로 설정할 수 있는 것은 신청 정보의 작성/정정, 접수 확인, 중복 신청 정리, 담당자 검토와 기록, 신청 변경/취소, 시스템 장애 시 임시 접수/복구, 승인 내용 통지, 보완/이견 확인 등 **처리 절차와 그 절차상 예외**다. 실제 권리/금액·자격을 좁히는 추가 서류 의무·마감·승인권자·제재를 조용히 만들지 않는다. 기존 마감/승인 주체를 유지하고 내부 검토 기한을 새로 정하더라도 기존 신청 가능성을 제한하지 않는다.
3. 문서별 주제에 맞게 서술한다: 생일은 특별휴가와 포인트의 구분·신청 정정, 연차는 발생/반차/이월·긴급신청 처리, 재택은 장소/기기/보안·주소변경, 복지는 지급/내역 확인·정정, 교육은 신청/승인/변경·결과 기록, 출장은 승인/일정변경/비용자료 처리. P015에 없는 대상이나 금액을 상식으로 채우지 않는다. 범위 밖의 새로운 권리·보상·징계·법적 의무가 필요하면 해당 부분을 중단하고 plan 피드백으로 남긴다.
4. `policy-inventory.json`에 모든 규범 문장/절차를 stable ID로 기록한다. 각 항목은 `preserved`(v3 출처와 대응), `added_fictional`(설정 이유·기존 조항과 비충돌 근거)로 구분한다. 비규범 설명/사례는 `explanatory`로 별도 매핑한다. 하나의 문장에 두 종류가 섞이면 span을 나눠 기록한다. 미분류 규범 문장, 출처 없는 보존 주장, 누락된 기존 주장은 실패다.
5. 사례/주의사항은 기존 또는 새로 선언한 규칙을 설명하며 독립된 숨은 예외를 만들지 않는다. 조건·예외·관련 조항은 자연스러운 업무 순서에 배치하고 stable 조항 ID 참조를 사용한다. 다른 문서 참조도 실제 대상/버전/조항 ID와 일치해야 한다. 자기 참조/끊어진 참조·순환해서 기본 규칙을 결정할 수 없는 참조는 거부한다.
6. `policy-map.json`은 v3→v4의 모든 기존 주장 대응 및 신규 주장 목록을 제공한다. 새 canonical의 정확 quote/span·페이지·문서 hash와 관계 조항을 연결한다. 정책 충돌을 예외 우선순위로 임의 해결하지 않는다. 이 검토는 Codex의 가상 원문 대조이며 사람 승인 Ground Truth가 아니다.

## 길이·구조의 완료 기준

분량 단위는 NFC/LF 편집 Markdown에서 문서 메타/제목/가상 안내·목차를 제외한 **규정 본문 Unicode 문자 수**다. Markdown 문법 표시는 제외하고 본문 공백은 센다. 계측 도구와 포함/제외 span을 기록해 재계산 가능하게 한다. PDF 줄바꿈·페이지 번호가 포함된 canonical 길이는 별도로 기록한다.

| 문서 | 본문 최소~최대 문자 |
| --- | --- |
| 생일 특별휴가·포인트 | 3,000~5,000 |
| 연차 | 7,000~10,000 |
| 재택근무 | 6,000~9,000 |
| 복지 | 5,000~8,000 |
| 교육휴가 | 5,000~8,000 |
| 출장 | 7,000~10,000 |

총 본문33,000~50,000자이며 이는 학습용 규모 선택이지 실제 회사 평균이나 모델 한도가 아니다. 주제마다 분량을 다르게 하여 짧은 규정을 억지로 동일 길이로 늘리지 않는다. 자연스러운 내용이 이 기준에 못 미치면 반복/불필요한 의무를 추가하지 말고 부족 사유를 plan에 전달한다.

- 각 문서는 `문서 제목 → 장 → 조항`의 검증 가능한 계층, 장2개 이상·조항6개 이상을 가진다. 최소 연차/재택/출장은 `장 → 절 → 조항` 한 단계 더 깊은 구조를 포함한다.
- 각 문서에 본문80~250자의 짧은 조항2개 이상, **하위 제목 없이 1,200~2,500자가 이어지는 조항1개 이상**, 400~900자의 자연스러운 본문 문단2개 이상을 포함한다. 긴 조항 안에서 주제는 유지하되 접수→검토→변경 등 의미 전환이 있어야 한다. 긴 조항도 청크 한 개로 강제하지 않는다. 짧은/긴 기준은 본문 기준이며 제목 문자는 제외한다.
- 각 문서에 신청→검토/승인→통지/변경의 연결 절차1개 이상, 기본 절차와 조건부 예외 연결2건 이상, 실제 다른 조항 참조2건 이상을 둔다. corpus 전체에서 문서 간 참조3건 이상을 확보한다. 구조 개수만 맞추지 않고 어떤 업무 목적을 갖는지 구조 검토표에 적는다.
- A4·한글 본문10.5~12pt·사방 여백18~25mm의 읽기 쉬운 단일 단 편집을 기본으로 한다. 문서마다 자연스럽게2페이지 이상, 전체48페이지 이내. 페이지 수를 채우기 위한 수동 페이지 나눔·빈 페이지·거대한 여백을 쓰지 않는다. 긴 문단/조항이 실제 페이지를 넘는 사례를 corpus에서3개 이상 확보하고 page map으로 확인한다. OCR·복잡한 표/다단은 이번 범위 밖이다.
- 동일 문단 반복으로 길이를 늘리지 않는다. 가상 안내·문서 식별/페이지 표시 외의 동일 본문 문단은 중복 보고서에 모두 표시하고 제거하거나 규정상 필요한 반복임을 수동 설명한다. 전체 문단/조항을 사람이 읽는 방식으로 검토해 근접 재진술·부자연스러운 문장·숨은 정책 변경도 기록한다. 자동 중복 검사만으로 현실성을 보장하지 않는다.

## 작성·추출·동결 절차

1. 기존 정책 전수 목록과 신규 절차 개요를 먼저 작성하고 일관성을 검토한다. 청킹 결과/질문/정답/검색 점수는 작성 입력으로 사용하지 않는다. 검색 평가를 본 뒤 분할하기 좋게 문장을 재배치하지 않는다.
2. Markdown6개를 완성하고 내용·구조·분량·참조·중복을 검토한 후 PDF를 생성한다. 기존 로컬 작성 환경과 폰트를 사용하고 이름/version/hash·배포 제약을 남긴다. 폰트나 실제 HR 자료를 새로 공개 저장소에 복사하지 않는다.
3. PDF 스킬에 따라 **전체 출력 페이지를 렌더링하고 직접 검수**한다. 여백/넘침·한글·줄/페이지 순서·제목/본문 분리·연속 문단을 확인한다. 각 페이지별 판정·수정 이력을 `docs/verification/p016/`에 남긴다. 표본 몇 페이지만 확인해 완료로 보고하지 않는다.
4. PDF→snapshot→추출→canonical/page map을 고정한다. P015의 NFC/LF·Unicode code point `[start,end)`·원자적 출력/변조 거부를 유지한다. Markdown 본문 전체와 추출본의 비공백 문자/순서를 대조하고 숫자·부정·예외·조항 참조 누락은 별도 실패 처리한다. 허용한 제목/메타/페이지 표시 차이는 명시적으로 매핑한다.
5. section map에는 stable ID, 실제 heading span, 부모 ID/전체 제목 경로, 본문 span, page 범위를 기록한다. 부모 범위가 자식 범위를 포함하고 동일 수준 조항은 순서/범위가 겹치지 않도록 검증한다. offset은 canonical 기준이며 PDF 좌표가 아니다. title path는 메타데이터이고 본문에 제목을 복제하지 않는다.
6. `corpus-profile.json`에 문서별 본문/canonical 길이, 장/절/조항·문단 길이 분포, 페이지 횡단/참조/중복 검토 결과를 저장한다. `handoff-manifest.json`에 모든 PDF·canonical/page/section map·정책 대응·프로파일의 hash와 버전/완료 commit 연결을 제공한다. 자기 파일의 hash를 자기 안에 넣는 순환은 피하고 외부 검증 증거에 manifest hash를 둔다.
7. 새 단계 단독 복사에서 수집/재추출 및 검증을 재현한다. 같은 입력 PDF의 canonical/page/section 내용·hash가 같아야 한다. PDF 재작성 byte 동일성은 같은 고정 작성 환경에서 확인하고, 다른 폰트/환경의 동일성은 주장하지 않는다. 시간 등 관측 메타데이터를 byte 동일 조건에 넣지 않는다.

## P007 인계와 제외

실행 순서는 **P015 완료 → P016 장문 규정집 → P007 다섯 청킹·검색/UI → P013 → P014 → P008 → P010**이다. P007 준비는 source-v4 확정본으로 다시 한다. v3는 짧은 기준선이며 v3/v4를 같은 청킹 비교군에 섞지 않는다.

- P007이 확정할 항목: 다섯 방법·overlap 후보, section metadata/긴 조항 재분할, query/fact/span·새 정책/다중 조항 질문·tuning/holdout, 전체 문서 coverage, UI 원문 선택/페이지 탐색·긴 청크 목록, 모델 입력/호환·실제 window 수·요청/시간/벡터 항목 예산.
- 이전 P007의 문서당8window/300요청·14기존질문+12holdout·440ranking은 확정값으로 승계하지 않는다. source-v4 실측 후 예산/표본 계획을 재검토하며 문서를 잘라 예산에 맞추지 않는다. 최소 3회 반복·전체 corpus 사용 원칙을 바꾸려면 plan에서 명시적으로 개정한다.
- P016에서 검색 정답/holdout이나 모델 호출·색인/청킹 sweep·검색/답변/UI 개발을 하지 않는다. 기존 UI 기본 corpus/8001 서버도 교체하지 않는다. 실제 Drive 연결·법적 검증·LLM/NLI 평가·main 승격은 제외다.

## 검증 계획

`docs/verification/p016/`에 모든 기준별 최초 실패/수정/최신 PASS를 남긴다. 독립 fixture로 길이/계층/참조·offset 경계·페이지 누락·정책 미분류/누락·hash 변조·PDF 손상/암호화/timeout·빈 페이지·기존 출력 덮어쓰기 거부를 검증한다. PDF 렌더·정책/서술 대조는 직접 검수 증거를 별도로 둔다. v3 데이터와 이전 단계 byte 보존 및 변경한 공용 도구의 기존 회귀, 독립 복사 재현을 확인한다. 필요하지 않은 모델/서버는 시작하지 않는다.
