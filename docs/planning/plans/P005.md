## 목적과 기획 준비

사용자가 직접 코드를 쓰지 않고 질문→검색→문맥→답변→인용을 관찰하고 한 설정씩 바꾸며 학습할 수 있는 로컬 실행 화면과 재현 안내를 완성한다. `1. Naive RAG/` 안에서 P004의 실제 함수·결과 스키마를 재사용한다. P004의 고정된 CLI·trace·장애 분류·모델 품질 검증 계약을 입력으로 [준비 검토](../reviews/P005-readiness.md)를 수행했다. P004 선행 완료 대기로 등록하며 dev는 착수 전에 커밋된 P004 완료 증거와 실제 인터페이스가 이 계약에 맞는지 대조한다. 불일치는 피드백으로 남기고 계약을 임의로 바꾸지 않는다.

Naive RAG E2E 범위는 고정 합성 문서→실제 임베딩·색인→한 번의 검색→문맥 조립→한 번의 실제 LLM→인용 검증→답변/보류다. 재검색·reranker·hybrid·agent·Drive·Slack·배포는 포함하지 않는다. 모든 모델·색인은 로컬이며 다른 큰 단계 폴더를 만들지 않는다.

## 실행 화면과 API

1. 로컬 서비스 명령은 `.venv/bin/python scripts/serve.py --port 8000`이다. 127.0.0.1에만 bind하며 현재 모델·색인 상태와 실행·종료 방법을 README에서 안내한다. 선택 가능한 설정은 retriever(dense/bm25), top-k와 문맥 예산이다. 실제 model digest와 prompt 버전을 관찰할 수 있다.
2. GET /는 질문 입력·실행 버튼과 예시 질문을 제공한다. 기본 예시는 생일 휴가 자격, 여러 근거가 필요한 생일 질문, 퇴직금 계산식이다. “가상 HR 문서 학습용”임을 표시한다.
3. POST /api/ask는 P004 ask 경로를 그대로 호출해 결과를 반환한다. 새 프롬프트·검색·응답 검증을 별도로 재구현하지 않는다. 요청 JSON과 질문·설정을 검증한다. 입력 오류400, provider 장애502/timeout504, 그 밖의 실행 실패500을 처리한다. 정상 answer/abstain은200이며 서버 장애를 근거 없음으로 표시하지 않는다.
4. UI에서 최종 답변/보류/장애 상태, 순위·점수·청크본문·출처, 선택/제외 문맥과 이유, 인용 원문, 모델·프롬프트·설정·구간별 시간까지 확인할 수 있어야 한다. 검색과 답변을 나란히 따라갈 수 있는 한국어 설명을 제공한다.
5. 모델·문서·질문 내용은 사용자 데이터로 렌더링하고 raw HTML 실행을 하지 않는다. 중복 클릭에는 진행 상태를 표시하고 완료·실패 후 재시도할 수 있다. 서버는 단일 로컬 Qdrant 접근과 모델 요청을 일관되게 관리하고 기존 사용자 프로세스를 종료하지 않는다.
6. browser 개발 환경이나 외부 CDN·계정 없이 실행한다. 정적 자산은 단계 폴더에 두며 코드·데이터·문서가 단계 단독 복사 후에도 동작한다.

## E2E 검증과 인계

- 네트워크 없이 고정 provider로 실제 로컬HTTP 서비스와 API를 호출해 정상·보류·입력실패·provider실패·unknown route·잘못된JSON·답변 렌더링을 검증한다. 테스트 provider로 실행한 결과를 live 모델로 표기하지 않는다.
- 실제 Ollama·Qdrant·Qwen 모델로 UI 또는 HTTP를 통해 근거 있는 질문, 근거 없는 질문, 복수 근거 질문을 실행하고 CLI와 같은 경로·스키마를 쓰는지 확인한다. 최소 실제 정상답변과 적절보류를 관찰한다. 생성문자열의 바이트일치까지 요구하지 않는다.
- 브라우저에서 입력→클릭→진행→답변/인용/trace를 직접 확인한다. 좁은 화면의 스크롤·긴 청크·에러 표시도 확인하고 실제 화면 증거를 남긴다. API검증만으로 화면확인을 대체하지 않는다.
- 초기 bootstrap/모델다운로드는 Codex가 수행하고 완료 인계 시 런타임·색인·질문화면을 실제로 실행할 수 있어야 한다. 사용자에게 모델 설치·코드 작성·테스트 구현을 과제로 넘기지 않는다.
- 기존P001~P004 회귀·큰단계 단독복사 실행을 확인한다. 소스·설정·코드·README·LEARNING_GUIDE.md와 docs/verification/p005/의 명령·실제출력·화면·실패/재검증·최종계약/큐 검증을 커밋한다.

## 학습 가이드

제품폴더의 LEARNING_GUIDE.md에는 아래를 실제 실행 명령·예시 질문·관측 결과·파일 위치와 연결한다. 가이드의 학습자는 코드 구현보다 “예상→관찰→실패 계층 분류→한 변수 실험→결과 해석”을 수행한다.

- 전체 흐름 지도: 원문/청크, 임베딩, Qdrant, retriever, top-k와 문맥, 프롬프트, 생성, 인용·보류의 역할. 코드 전체 통독을 선행 과제로 요구하지 않는다.
- 첫 세 관찰: 생일 휴가 자격의 조건·인용 확인, 복수 근거 질문의 문맥 누락 확인, 퇴직금 질문의 보류 확인. 실제 모델실패가 있으면 그대로 사례로 남긴다.
- 검색 평가: Recall@K/MRR/nDCG와 생성문맥의 근거 누락. qrels가 검색기에 유입되면 실험이 무효인 이유.
- 생성 평가: 정확성·조건누락·근거충실성·인용구조와 의미지지, 과도보류와 근거없는 단정. 자동키워드 검사·모델자기평가의 한계.
- 첫 최적화 실험: top-k1/3/5/10을 비교하며 corpus·embedding·LLM·prompt·질문을 고정한다. 검색 Recall 상승과 답변 품질·문맥 길이·지연이 다르게 움직일 수 있음을 실제 결과에서 관찰한다.
- 두 번째 실험: BM25/Dense 비교. 같은질문에 단어표현·조사가 달라질 때 실제검색 결과와 누락원인을 추적한다. 작은 합성평가를 일반화하지 않는다.
- 이후 실험: 문맥예산·프롬프트·모델크기·temperature를 한 번에 하나씩 바꾼다. 청킹·corpus 변경은 새데이터버전·qrels 재검토가 필요한 이유와 원본 보존을 설명한다.
- 테스트 지도: 단위(산식/스키마/인용), 통합(색인/모델어댑터), 회귀(고정질문), E2E(UI/API→실제모델), 수동의미평가의 역할.
- 성능: cold/warm·모델로드·질문임베딩·검색·생성·전체지연을 분리하고 같은 환경·prompt·출력길이 조건을 기록한다. 작은 표본의 p95와 단일관측을 과장하지 않는다.
- Codex 요청 예시: “같은질문으로 top-k만 바꿔 비교해줘. 검색/답변/보류/시간을 따로 보고 실패3건의 근거를 보여줘.” 사용자가 코드를 직접 고치지 않아도 가설·기대결과·판단을 자신의 말로 설명하도록 한다.

가이드에 완료 상태·실제 사용할 명령·중단/재시작법·의존성/모델 lock·평가기 한계·향후 큰 단계 후보를 적는다. 자동 테스트 통과와 모든질문 정답 달성을 혼동하지 않는다.
