# P032 S8 · 선택한 구성으로 PDF에서 최종 답변까지

## 준비 검토

S3~S7에서 각각 PDF 답변, 검색·리랭킹 비교, 생성 모델 비교, 저장 청크 및 제목 경로를 검증했다. 설치 안내의 마지막 계층 실습은 BM25 비교 보고서에서 끝난다. schema_version 3의 검색 설정은 저장 청크를 직접 읽고 candidates는 그 청크 원본을 전달한다. 이 경로를 재사용해 선택한 구성 하나가 실제 마지막 인용까지 이어지는 설치본 실습을 완성한다.

## 범위와 완료 기준

1. init한 폴더에서 사용자가 로컬 PDF, 질문, 청킹 설정, 검색 설정과 공개 임베딩 프로필, 리랭커 사용 여부와 프로필, 생성 모델 설정을 선택하고 결과를 받는 간결한 실행 진입점을 제공한다. 기존 CLI 코어 또는 CLI 명령을 조합한다. 기존 산출물 식별·권한 검사와 실패 처리를 재사용한다. 모델별 별도 실험 메뉴와 기존 개별 명령을 유지한다.
2. 기본 미리보기에서 각 단계의 유효한 설정·필요한 모델 작업·출력 위치를 보여준다. 사용자가 선택한 로컬/API와 데이터 전송 대상을 실행 전 확인할 수 있게 한다. 명시 실행에서 snapshot → 선택한 청크 → 인덱스·검색 → 동일 후보 재정렬 또는 none → 최종 문맥 → 답변·인용을 차례로 잇는다. 선행 단계 실패 후 후속 호출은 0회다. 기존 출력·실패 근거를 보존하고, 재생 시 모델 실행은 0회다.
3. 독립 설치본으로 현재 PDF·handbook-v1 400/80·E5 Hybrid(후보20·K5·4000자)·mMiniLM·기존 로컬 Qwen 4B를 한 경로에서 실행한다. S3의 단일 신청 기한 질문을 고정한다. 실제 실행 상한은 인덱스 1회·질의 임베딩 1회·재정렬 20쌍 1회·생성 1회, 모델은 순차 실행한다. 검색 작업은 S4 제어와 로컬 파일을, 생성은 S3 단일 호출·시간·자원·종료 조건을 재사용한다. 자동 재시도 0. 모델 없는 준비와 입력/제어를 커밋한 뒤 호출한다.
4. 최종 인용의 청크 ID가 선택한 계층 청크 및 최종 문맥에 있는지, 제목 경로·페이지·문자 범위·인용문이 PDF와 일치하는지 검증한다. 3영업일이 신청 행위에 연결되는지 직접 대조한다. 질문에 맞는 답변 생성 여부, 청킹·검색·재정렬의 각 성공 여부를 구분해 보고한다. 고정 청크나 이전 답변으로 대체하지 않는다.
5. 모델 없는 시험으로 BM25·none, 다른 등록 모델 설정, API 미리보기, 잘못된 설정과 빈 문맥, 부분 실패·결과 재생을 검증한다. 설치 가이드에서 Codex나 Claude Code에 줄 한 가지 실행 예시와 선택값 변경 위치를 안내한다. 새 wheel, 일반 실행 경로, 회귀, 학습 보고서, dev 커밋·push까지 확인한다. Drive·평가기·모델 다운로드·유료 API 실호출은 보류한다.
