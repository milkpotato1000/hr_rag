# P032 S7 · 규정집의 장·절·조항을 따라 청킹하기

## 준비 검토

S6 완료 01c382e에서 기존 구조 청킹은 규정집 목차와 본문의 장 제목 12개를 검출했고 절 제목 15줄 및 BD-03은 검출하지 않았다. chunks.headings는 Markdown 제목과 제N장·제N조만 인식한다. make_chunks는 이미 제목 사이가 길면 크기에 맞춰 재귀 분할하고 heading_path를 저장한다. 기존 분할기를 재사용하고 이 규정집의 계층 해석을 선택할 수 있게 한다.

## 구현·검증

1. 구조 기반 청킹에 규정집 계층 프로필을 선택적으로 제공한다. 기존 설정 생략 시 기존 결과·ID·재생 규약을 유지한다. 새 프로필은 실제 본문의 장·절·조항 제목을 원문 줄에서 인식하고 목차와 본문을 구분한다. 본문 안의 단순 조항 참조, 장 전환 시 이전 절, 여러 문서 간 제목 경로가 섞이지 않게 한다. 지원하는 제목 형식과 인식하지 못하는 경우의 동작을 학습 자료에 적는다.
2. 각 하위 청크에 장→절→조항의 경로를 메타데이터로 유지한다. 원문 인용은 원래 문자 범위와 페이지에서 그대로 재현한다. 긴 절·조항은 설정 크기와 겹침을 지키며 나누고 경계를 넘는 겹침을 막는다. 기준 분할 구간 전체가 연속해서 원문을 덮는지 검사한다. 검색용 텍스트에 인위적으로 제목을 추가하지 않는다. 새 프로필은 구성·산출물 식별에 포함한다.
3. 같은 PDF·400/80·BM25·질문·후보20·최종5·예산4000으로 기존 구조 방식과 신규 프로필을 비교한다. BD-03의 실제 장·절·조항 경로, 원문 전체 문장과 신청 기한의 첫 순위·전달 여부, 총 청크 수와 목차 검출을 실측한다. 개선 여부는 관측대로 기록한다.
4. 긴 하위 섹션(2만자·5만자), 목차와 중복 본문 제목, 조항 참조, 여러 장·문서, 제목 없는 문서, 기존 산출물 읽기를 회귀 검사한다. 설치본 CLI와 기존 청킹 UI에서 프로필을 선택하고 경로와 원문을 확인할 수 있게 한다. 독립 설치 실습·보고서와 학습 목차를 연결하고 dev에 정상 push한다. 모델 호출·다운로드·Drive·평가기 실행은 없다.
