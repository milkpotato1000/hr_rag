# P032 S4 · 설치본에서 같은 PDF의 검색 방식과 리랭커 비교하기

## 준비 검토

S3에서 설치된 일반 ask가 BD-03을 인용해 단일 신청 기한 질문에 답했다. init의 fixed.json은 고정 400/80 BM25이고 rag-hybrid.json은 재귀 400/80 Hybrid다. 두 샘플을 그대로 비교하면 청킹과 검색이 함께 바뀐다. 기존 검색·리랭커 명령과 공개 모델 카탈로그를 재사용해 같은 PDF에서 한 조건씩 바꾸는 실습을 제공한다.

## 실습과 검증

1. S3 종료 커밋 후 정확 채택한다. 설치본 HANDBOOK에서 비교 실습에 진입한다. 동일 snapshot, 고정 400/80, 동일 질문, 최종 K5·문맥 예산 4,000자를 유지한다. BM25, E5 Dense, E5 Hybrid(RRF), 같은 Hybrid 후보에 리랭커 끔/켬을 비교한다. E5를 BGE로, 리랭커를 등록된 다른 모델로 바꾸는 설정 위치와 인덱스 재생성 여부를 명시한다. 모델별 파일 경로는 사용자 준비 프로필을 받는다.
2. 설치된 일반 CLI와 지원 UI의 실제 입력 이름을 사용한다. Codex/Claude Code에 줄 예시 요청, 필요한 준비물, 각 단계에서 볼 후보 순위·인용 페이지·전달 청크를 보여준다. init 샘플이나 기존 명령을 재사용하고 형식이 맞지 않는 데모 경로는 수정한다.
3. 새 독립 실습 폴더에서 제공된 PDF로 가이드를 재현한다. 동일한 청크 ID 및 내용, 질문, K·문맥 예산을 검사한다. Dense와 Hybrid 간 모델·인덱스 재사용은 제품의 식별자가 허용할 때만 한다. 리랭킹 전후에는 같은 후보 ID·순서·점수·질문을 동결한다. 순위가 바뀐 BD-03 근거의 위치와 최종 문맥 포함 여부를 표로 보여준다. 해당 결과가 같아도 그대로 보고한다.
4. 기존 로컬 공개 모델 파일과 고정 retrieval SDK를 확인하고 모델 없는 preflight로 실행 수·시간·메모리 및 입력을 먼저 동결한다. S1에서 검증된 직렬 worker 제어와 한도를 재사용한다. 실제 실행은 임베딩 최대 2개 인덱스와 2개 질의, cross-encoder 1개 질문의 후보 최대 20개, 재시도 0이다. 한도 내 정상 경로로 실행할 수 없는 경우 단계·진단을 기록한다. 다른 공개 모델 설정은 준비·미리보기와 실측을 구분한다.
5. 리랭커 결과에서 answer-from-rerank로 전달할 문맥까지 확인한다. 답변 생성을 추가 호출하지 않는다. S1의 256/64 지표를 이번 400/80 청크에 이식하지 않는다. 학습 자료·manifest·패키징 검사·모델 없는 회귀·실험 결과를 dev에 커밋하고 정상 push한다. Drive·유료 API 실호출·평가기·새 모델 다운로드는 보류한다.
