# P032 S24 · 같은 규정집에서 임베딩과 리랭커를 각각 바꿔 보기

## 준비 검토

dev b3a630d 기준 S4는 규정집에서 E5와 mMiniLM의 검색 순위를 실측했고, S15는 준비된 네 모델의 프로필과 설치 UI 선택을 검증했다. 학습자가 같은 질문으로 두 임베딩 또는 두 리랭커의 실제 순위 차이를 재현하도록 연결한다.

## 실행 계약

1. 기존 규정집, S4의 신청 기한 질문과 원문 범위, 고정 청킹 400/80, 후보 20·최종 5·문맥 예산 4,000자를 고정한다. 준비된 Hugging Face 모델과 revision 및 실제 파일을 확인한다. 기존 설치 CLI와 프로필을 사용한다.
2. 임베딩 비교는 리랭커를 끈 Hybrid RRF에서 E5-small과 BGE-M3만 바꾼다. 같은 BM25 순위와 청크 집합을 확인하고 각 모델의 Dense 순위, 결합 순위, 최종 전달 근거를 기록한다. 임베딩 인덱스는 해당 모델 전용으로 구분한다.
3. 리랭커 비교는 E5 Hybrid의 동일한 후보 ID·순서·원문을 저장한 후 끔, mMiniLM, BGE-reranker-v2-m3를 적용한다. 최종 순위·문맥·페이지를 비교한다. 두 비교에서 신청 기한을 담은 첫 근거와 팀장 승인까지 담은 첫 근거를 각각 표시한다. 순위가 같거나 하락한 경우도 그대로 기록한다.
4. 일치하는 기존 실행 증거는 입력·모델·후보의 동일성을 확인한 후 재사용하고 필요한 계산만 순차 실행한다. 기존 메모리 점검·중지 정책을 유지한다. 새 모델 다운로드, Qwen 추가 생성, 외부 API와 Drive 연결은 범위 밖이다. 실행할 수 없는 조건은 원인과 미측정 상태를 구분해 남긴다.
5. 설치 예제에 학습자가 같은 두 비교를 재현할 명령과 결과 해석을 연결한다. 질문 하나에서 나온 순위 변화를 모델 전체의 우열로 해석하지 않는다. 회귀 확인과 dev 기록·푸시까지 진행한다.
