# P032 S17 · LLM이 원문 경계 후보 중 하나를 선택하는 청킹

## 준비 검토

dev b834f82의 설치 경로에서 짧은 합성 교육휴가 PDF를 선택할 수 있다. 기존 방식은 모델이 길이 제한을 계산하며 끝 번호 전체를 직접 반환한다. S2i·S2j의 762자 첫 창은 두 번 모두 출력 4,096토큰에 도달했고 유효한 응답이 없었다. 출력 상한에 도달한 사실만으로 세부 원인을 단정할 수 없다. 원래 진단을 종료 상태로 보존하고 별도 선택형 방법을 검증한다.

## 구현 및 판정

1. LLM 청킹에 선택 가능한 모드를 추가한다. Python은 원문 단위·offset과 길이/피복 제약을 이용해 창마다 소수의 서로 다른 유효 분할을 결정적으로 만든다. 예를 들어 앞에서부터 채우는 경계와 절·문단 전환을 우선하는 경계를 비교한다. 조합 전체를 열거하지 않는다. 후보 ID, 각 조각의 실제 원문, 차이가 나는 지점을 검토할 수 있어야 한다. 모델은 각 후보가 규정과 조건·예외를 함께 유지하는지 읽고 후보 ID 하나를 고른다. 하나만 가능한 창은 모델 호출 없이 그 이유를 기록한다.
2. 선택 ID를 제시한 후보에만 매핑하고 기존 parse/emit으로 원문 순서·중복·빈틈·겹침 및 길이 상한을 검증한다. 잘림·무효 ID는 명시 실패다. 성공처럼 대체 선택하지 않는다. 설정·프롬프트·후보의 재현 정보를 결과와 미리보기에 기록하고 이전 LLM 방식과 기존 저장 결과 재생을 보존한다.
3. 설치 패키지에서 새 설정을 선택해 일반 chunk 및 통합 파이프라인이 같은 후보·경계를 사용하도록 한다. 복수 창·강제 경계·단일 후보·잘린 응답·이전 결과 호환을 모델 없는 시험으로 검증한다. 원문·후보·선택 ID·생성된 청크를 나란히 보여 주는 학습 예제를 남긴다.
4. 새 소유 실행에서 S16의 짧은 합성 PDF 전체로 Qwen 4B를 시험한다. 설치본 미리보기에서 문서 전체를 포함하고 실제 선택이 필요한 창이 한 개가 되는지 먼저 검증하며, 최소 두 유효 후보의 의미 있는 차이를 확인한다. 원문 자르기·허위 후보 생성은 허용하지 않는다. 조건을 충족하지 못하면 모델 실행 전 한계와 이유를 기록한다. S11의 기존 모델 식별·시간·자원·소유 서버 정리 절차, 신규 생성 최대 1회·자동 재시도 0을 적용한다. 유효한 완성 청크를 얻은 경우 BM25로 S16 질문의 근거 페이지를 확인한다. 실패 시 검색 성과를 추정하지 않는다.
5. 의미 품질과 형식 유효성을 별도 보고한다. S2j와 입력 길이·문서·의사결정 방식이 달라 우열 비교 실험이 아님을 명시한다. 전체 기존 23쪽 문서의 실추론, Drive·유료 API·평가기·새 모델은 보류한다. 설치 안내·검증 자료·dev 정상 push까지 진행한다.
