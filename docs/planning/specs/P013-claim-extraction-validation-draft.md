# P013 — Codex 정답 후보 작성과 Qwen 추출 단독 검증

상태: DRAFT / 구현·모델 호출 계약 아님. 2026-11-04 사용자 “정답 후보는 코덱스가 원문 기반으로 만들고 사람이 승인하는 걸로 하자. Qwen의 클레임 추출 성능 평가는 고정된 답변으로 따로 검증하도록 P013 플랜에 반영해줘”를 반영한다.

## 1. 두 데이터 경로

| 구분 | 작성/실행 역할 | 입력 | 출력과 사람 검토 기준 |
| --- | --- | --- | --- |
| 기준 정답 후보 | Codex 작성 → 사람 승인 | 버전이 고정된 원문·질문 범위 | 질문·기준 답변·원자 정답 claims·원문 근거. 원문에 맞고 질문에 충분한지 승인 |
| 추출 검증 입력/기대값 | Codex 준비 → 사람 검토 | 고정 답변·질문 | 답변에 실제 나타난 사실의 기대 claims/답변 span. 원문 정답과 다르더라도 답변 의미에 충실한지 확인 |
| 추출 모델 단독 실행 | Qwen3-8B | 질문·고정 답변만 | 추출 claims·답변 span·원응답·실행 메타. 기대값과 별도로 대조 |

기준 정답 후보 작성에 Qwen 정답 생성 호출을 요구하지 않는다. Codex 작성은 사람 승인이 아니며 실제 승인자·항목/패킷 hash·시점·근거를 보존한다. 추출 검증 기대 클레임과 HR 기준 정답의 승인 상태를 별도로 관리한다.

## 2. 고정 답변 추출 검증 순서

1. 질문/답변 원문·ID·hash·작성 출처와 데이터셋 버전을 동결한다. 합성 답변인지, 기존 생성 run에서 가져온 답변인지 구분한다. 검증 실행 중 새 답변 생성·검색은 하지 않는다.
2. Codex가 답변에 충실한 기대 클레임·정확한 답변 인용/span·필수 조건/부정/수치·중복 발생 위치를 작성한다. 사람이 원자화/의미 보존과 기대값을 검토하고 대상 hash·검토 기록을 동결한다.
3. 모델 digest·프롬프트/출력 스키마·입출력 한도·timeout·반복/재시도·총 호출/시간 상한을 준비 검토에서 고정한다. P019의 과거 실행량을 새 실행 권한으로 재사용하지 않는다.
4. Qwen에 질문과 고정 답변만 전달해 추출을 실행한다. 질문은 지시 대상·생략 주어를 이해하는 용도다. 원문, 승인 정답, 기대 클레임, 사람 판정 라벨을 모델 입력에 포함하지 않고 실제 요청 snapshot으로 확인한다.
5. 코드가 구조·ID·인용/span·hash·누락을 검사한다. 사람이 확인한 의미 대응으로 추출 결과와 기대 클레임을 정렬하고 오류 종류를 기록한다. 같은 Qwen의 재판정만으로 사람 기준을 대체하지 않는다.
6. 단독 보고서를 저장한다. 실제 RAG 답변의 Faithfulness/Correctness run과 run ID/지표 이름/기대값 경로를 분리한다. 이후 평가 경로에서는 추출 artifact/hash를 고정해 재사용한다.

## 3. 준비할 필수 사례와 기대 동작

아래는 고정 세트를 설계하기 위한 예시다. 실제 기대값 세트의 사람 검토·승인 완료나 모델 실행 결과를 뜻하지 않는다. HR 원문에 모두 존재하는 정책이라고 주장하지 않는다.

| 사례 | 고정 답변 예시 | 추출에서 확인할 것 |
| --- | --- | --- |
| 복수 사실·숫자·기한 | “연차는 최대 5일 이월할 수 있고, 사용 기한은 다음 해 3월 31일입니다.” | 이월 한도와 사용 기한을 두 주장으로 분해하고 숫자·다음 해를 보존 |
| 조건 보존 | “수습 중이 아닌 재직자는 생일휴가 1일을 신청할 수 있습니다.” | 자격 주장에 수습 제외·재직·1일 조건을 유지. ‘직원은 신청 가능’으로 일반화하지 않음 |
| 부정 보존 | “수습 직원은 생일휴가를 사용할 수 없습니다.” | 사용할 수 없음이라는 부정을 뒤집거나 제거하지 않음 |
| 중복 | “이월 한도는 최대 5일입니다. 최대 5일까지만 이월할 수 있습니다.” | 의미상 고유 주장1개, 발생 위치2개. 중복을 감추지 않고 별도 기록 |
| 사실 오류 보존 | “연차 이월 한도는 최대 10일입니다.” | 원문 정답이5일이어도 답변의10일을 추출. 오류 수정·정답 보충은 추출 오류 |
| 비사실/무주장 | “확인해 드리겠습니다.” | 정책 사실을 새로 만들지 않고 빈 claims를 반환하는 기대 정책을 고정 |

조건은 독립된 문장 조각으로 떼어 의미를 잃게 하지 않는다. 추출 누락·추가·잘못된 분해/합침과 표면적인 표현 차이를 구분하고, 허용하는 동등 표현·정렬 정책을 검증 전에 고정한다.

## 4. 독립 성능 지표와 실패 보고

- 기대 고유 클레임 수 B, 추출 고유 클레임 수 A, 사람이 확인한 의미/조건 보존 일대일 대응 수 H로 `extraction_precision=H/A`, `extraction_recall=H/B`, `extraction_f1=2H/(A+B)`를 보고한다. 의미를 바꾸거나 원문 정답으로 고친 주장은 올바른 대응에 포함하지 않는다.
- 이 수치는 **추출이 답변을 충실히 분해했는지**에 대한 지표다. 승인 HR 정답과의 Correctness P/R/F1이나 NLI 지지 비율과 구분한다. 추출기의 비교 대상은 고정 답변의 기대 클레임이다.
- 누락·추가·원시 중복 수, 숫자/기한/조건/부정 손실, 무단 사실 교정, 잘못된 분해/합침, 구조·인용 실패를 사례/클레임별로 남긴다. 원시 출력과 정규화 결과를 모두 보존한다.
- 구조/출력 잘림/실행 실패는 정상 빈 claims로 치환하지 않는다. 실패 사례의 점수는 null/failed로 표시하고 전체 시도 수·유효 수·실패율/coverage·실패 사유를 보고한다. 유효 사례만 집계할 경우 제외 수를 명시한다.
- 정상 무주장 입력은 사실을 생성하지 않았는지 별도 확인한다. A=B=0이면 세 지표는 null/no_claims, A=0·B>0이면 P=null/R=0/F1=0, A>0·B=0이면 P=0/R=null/F1=0으로 구분한다. 비정상 입력/실행 실패와 혼동하지 않는다.
- 세트 크기·tuning/확인 세트 구분·반복 수·통과 임계값과 필수 사례의 허용 오류는 P013 READY 전에 고정한다. 결과를 보고 기대값·threshold를 맞춰 바꾸지 않는다. 지연·호출 수·메모리·반복 판정 차이도 별도로 기록한다.

## 5. 기존 패킷과 완료 조건

P019/run001, P021/run002의 Qwen 초안·Codex 수정 이력·오류·원문/패킷 hash를 유지한다. 기존45개 정답 후보를 새 절차로 재사용하려면 Codex가 원문에서 다시 대조하고 새 버전에 유지/수정 근거와 이전 ID 대응을 남긴 뒤 사람이 승인한다. 이 문서를 추가했다고 현재 후보가 새로 작성되거나 승인된 것으로 표시하지 않는다.

P013 C1은 Codex 후보·사람 승인의 출처와 정답 유효성, C2는 고정 답변 추출 단독 검증 및 기존 산술/판정 fixture, C3는 실제 승인 데이터의 답변 평가와 분리 보고서를 요구한다. 원문 기반 정답 후보 생성 성공·산술 fixture PASS·JSON 형식 통과는 Qwen 추출의 의미 정확도 PASS를 대신하지 않는다.

정답 승인·P021 완료·모델/예산·정확한 채택 등 미결 게이트는 유지한다. 이번 변경은 계획 반영만이며 정답 패킷 수정, 모델 호출, 제품 구현을 실행하지 않는다.
