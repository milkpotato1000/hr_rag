# P032 S6 · 설치본에서 PDF 청킹 방법 비교하기

## 준비 검토

S3~S5의 설치 실습은 고정 400자·겹침 80자로 생성한 규정집 청크를 사용했다. START_HERE에는 독립 청크 저장과 재생 명령이 있고 HANDBOOK에는 같은 PDF의 검색·리랭킹·모델 비교가 있다. 기존 chunk, compare, chunk-report와 UI를 활용해 학습자가 동일 질문에서 청킹 자체를 선택·비교하는 경로를 연결한다.

## 실행 계약

1. S5 완료 7a7a695 이후 정확 채택한다. 독립 설치본과 S3와 같은 로컬 PDF에서 한 snapshot을 준비한다. 실제 init 샘플로 fixed·recursive·structure를 각각 400/80으로 실행하고 동일 BM25·후보 20·최종 5·예산 4,000자에서 동일 질문으로 검색한다. 각 방식의 청크 ID를 해당 snapshot의 원문 위치와 연결한다.
2. BD-03의 신청 기한 구절과 승인 요건까지 담은 완전한 문장에 대해 원문 페이지와 문자 범위를 고정한다. 세 방식 각각의 총 청크 수, 해당 조항 경계와 앞뒤 원문, 단일 청크에 문장이 온전히 포함되는지, 검색 결과에서 첫 순위와 최종 문맥 포함 여부를 실측 표로 제시한다. 두 청크가 합쳐야 문장이 완성되면 단독 포함과 구분한다. 일반적인 제목 기반 방식이 이 규정집의 장·절 패턴을 실제로 인식했는지도 해당 산출물로 확인한다. 결과가 같은 비교도 보존한다.
3. HANDBOOK에서 기존 실습과 연결하고 복사해 실행할 CLI와 Codex/Claude Code용 요청 예시를 제공한다. 학습 UI의 기존 청킹 메뉴에서 설정·원문·경계·검색 결과를 어느 순서로 보는지 보여준다. semantic은 기존 실측 보고서 또는 새 입력 preview, LLM은 preview 및 S2i/S2j의 출력 잘림으로 안내하며 성공 실측과 구분한다.
4. 새 wheel과 독립 폴더에서 문서대로 원문→청킹→검색 비교→저장 보고서 재생까지 검증한다. 예제 명령·링크·manifest·회귀 검사, 지원 UI에서 비교 결과 읽기, dev 커밋·정상 push를 확인한다. 모델 호출·다운로드·Drive 연결·유료 API·평가기는 이번 비교에 필요하지 않다. 기존 복합 질문 실패와 다른 청킹의 관련성 정답을 이번 결과에 이식하지 않는다.
