# P013 — 근거 누락과 답변 누락을 구분하는 평가기 검증

상태: DRAFT / 구현·모델 실행 계약 아님. 2026-11-05 사용자 요청에 따라 생일휴가 예시로 근거 청크 전체/일부, 답변 클레임 누락을 분리한다. [고정 입력·기대값 JSON](P013-evaluator-scenarios-draft.json)을 함께 사용한다.

## 1. 고정 질문·정답·근거

질문: “생일휴가의 재직 기간 요건, 연간 사용 일수, 사용 가능한 달은 어떻게 되나요?”

| 정답 ID | 고정 정답/생성 주장 | 독립 근거 청크 |
| --- | --- | --- |
| ref1 / g1 | 생일휴가 신청 대상은 재직 기간이 3개월 이상인 직원이다. | ctx1: 재직 기간 요건 |
| ref2 / g2 | 생일휴가는 매년 1일 사용할 수 있다. | ctx2: 연간1일 |
| ref3 / g3 | 생일휴가는 생일이 속한 달에 사용해야 한다. | ctx3: 사용 월 |

위 세 사실만 존재하는 합성 정책이다. 실제 source-v4의 수습 제외 등 다른 조건을 삭제/개정하거나 현재 run002의 정답 후보를 승인한 것으로 해석하지 않는다. `synthetic=true`, `human_approval=null`로 보존하고 별도 fixture 경로/버전을 사용한다. 사람이 검토하기 전 모델 판정 정확도의 승인 라벨로 취급하지 않는다.

## 2. 필수 네 상황과 기대값

정답은 모든 상황에서 ref1·ref2·ref3 전체를 유지한다. 근거는 생성 모델에 실제 전달한 문맥을 모사한 snapshot이다. 답변에서 빠뜨리는 주장은 g3, 문맥에서 빼는 청크는 ctx3로 고정해 다른 요인을 바꾸지 않는다.

| 상황 | 전달 근거 | 고정 답변 주장 | Faithfulness / Neutral / Contradiction | Correctness P / R / F1 |
| --- | --- | --- | --- | --- |
| A: 모두 완전 | ctx1·ctx2·ctx3 | g1·g2·g3 | 1 / 0 / 0 | 1 / 1 / 1 |
| B: 근거만 누락 | ctx1·ctx2 | g1·g2·g3 | 2/3 / 1/3 / 0 | 1 / 1 / 1 |
| C: 답변만 누락 | ctx1·ctx2·ctx3 | g1·g2 | 1 / 0 / 0 | 1 / 2/3 / 4/5 |
| D: 근거·답변 누락 | ctx1·ctx2 | g1·g2 | 1 / 0 / 0 | 1 / 2/3 / 4/5 |

- A→B는 답변과 정답이 같고 전달 근거만 줄어든다. g3는 neutral이며 모순이나 실행 실패가 아니다. 답변은 정답과 같으므로 Correctness를 낮추지 않는다.
- A→C는 문맥과 정답이 같고 답변만 줄어든다. 생성 주장2개는 모두 지지되므로 Faithfulness는2/2다. ref3는 누락(FN1)이므로 Recall=2/3, F1=4/5다.
- B→D는 근거가 같고 g3를 말하지 않게 된다. 생성하지 않은 g3를 neutral로 추가하거나 Faithfulness의 분모에 포함하지 않는다. 근거 없는 주장을 말하지 않았어도 질문의 필수 답변 누락은 Correctness에서 드러난다.
- C와 D의 점수는 같을 수 있다. 이 사실만으로 어느 검색이 충분했는지 결론 내리지 않는다. 별도 검색 지표와 후보/전달 snapshot 기록으로 구분한다.

## 3. 검증 단계와 입력 경계

1. **산술/보고서 검증:** fixture의 고정 추출 claims·기대 판정/매칭을 주입해 집계와 JSON/읽기 보고서 재현을 확인한다. 독립 fixture 계산 성공을 실제 Qwen/NLI 판정 정확도 PASS로 보고하지 않는다.
2. **평가기 단독 검증:** 같은 고정 claims를 사용해 claim verifier에는 전달 문맥만, matcher에는 전체 기준 정답만 전달한다. 사람이 검토한 기대값과 실제 LLM 판정/매칭을 대조한다. 추출기 차이를 평가기 차이로 섞지 않는다. NLI 비교는 후속 P014에서 같은 입력으로 수행한다.
3. **추출 단독 검증:** [별도 계약](P013-claim-extraction-validation-draft.md)에 따라 질문·고정 답변만 Qwen에 주고 기대 추출 claims와 비교한다. 원문·근거/GT·기대값을 추출 입력에 넣지 않는다.
4. **실제 RAG E2E:** 검색·문맥 예산·생성을 실제 실행해 확보한 전달 snapshot과 답변을 평가한다. 해당 단계가 리랭킹을 사용하면 그 결과도 포함하며 이번 요청으로 P013에 새 리랭커를 추가하지 않는다. 모든 청크가 회수됐다고 가정하거나 평가 때 누락 청크를 보충하지 않는다. B의 답변처럼 모델이 우연히 정답을 말한 상황도 실제 관찰이 있어야 결과로 기록한다.

합성 상황에서는 retriever/reranker나 생성 모델을 실행해 목표 답변을 유도하지 않고 고정 데이터를 사용한다. evaluator 모델 실행량·반복·timeout·출력 한도는 P013 READY 전에 별도 고정한다. 이번 계획 변경으로 실행 권한을 부여하지 않는다.

## 4. 결과와 수용 기준

질문/답변/claim·GT·context snapshot 및 hash, 각 claim의 라벨·근거 청크 ID/인용·짧은 이유, 생성-정답 매칭, unmatched reference IDs, E/U/C/분모/coverage·세 비율·TP/FP/FN/P/R/F1을 상황 ID별로 제공한다. claim별 E/N/C 기대값은 전체 전달 문맥에 대한 판정이며 청크쌍 개수로 점수를 나누지 않는다.

누락 청크 ctx3가 B/D의 Faithfulness 입력·근거 ID에 등장하면 실패다. ref3는 모든 상황의 matcher 입력에서 유지해야 하며, C/D에서 FN1임을 확인한다. B에서 g3를 추출/판정 결과에서 조용히 삭제하거나 C/D에서 g3를 만들어내면 실패다. 하나의 주장을 여러 근거가 지지해도 분자는1건이며 근거 목록만 여러 개 남긴다.

모든 주장 판정이 유효한 이 네 상황의 coverage는1이며 status=complete다. neutral은 정상 판정이다. 실제 모델이 실패/미확정이면 관측 결과를 incomplete/failed로 보존하고 정해진 기대 점수로 덮어쓰지 않는다. 실제 판정 정확도·반복 일치·실패는 별도 보고한다. JSON·보고서의 개수/분모/값은 허용 오차1e-12 안에서 독립 계산과 같아야 한다.

필수4상황이 fixture/보고서에 포함되고 각 입력 경계·기대 산술·claim별 의미 판정 검증과 실패 증거가 P013 C2/C3에 연결돼야 한다. 준비 검토에서 실제 사람 라벨 검토·통과 기준·예산을 고정한다. 기존18개 산술 fixture, P019/P021 이력, 미승인 정답과 P013 DRAFT 상태는 유지한다.
