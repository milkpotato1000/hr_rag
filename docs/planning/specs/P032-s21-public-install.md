# P032 S21 · 공개 저장소에서 첫 설치 재현

## 준비 검토

S20은 dev 36557ec에서 공통 진입점을 검증했다. 소스는 로컬 Git 복제본, 빌드 도구와 PDF reader는 사전 준비한 wheel 모음이었다. 공개 GitHub의 dev 커밋 및 99개 설치 입력 blob은 별도로 일치했다. 신규 사용자가 README의 기본 온라인 경로로 설치할 수 있는지 검증할 차례다.

## 실행과 판정

1. 새 임시 폴더에서 익명 HTTPS로 공개 dev를 체크아웃한다. 사용자 Git URL 재작성·SSH 자격증명이나 사내 패키지 미러를 전제하지 않는다. 소스 SHA·Python 버전을 기록하고 설치에 필요한 파일이 원격 커밋과 같은지 확인한다. 개발 작업트리·사용자 전역 Git/pip 설정을 변경하지 않는다.
2. 빈 pip 캐시, 새 전용 venv, 공개 PyPI와 기존 hash lock으로 README의 first_handbook 명령을 실행한다. wheelhouse·기존 site-packages를 쓰지 않는다. 다운로드·빌드·wheel 설치·PDF reader·init·검색 단계별 성공을 기록하고 설치된 wheel 출처와 PDF 해시를 확인한다. 설치는 공개 의존성 다운로드만 사용한다. 모델·API·계정·Drive·평가기·외부 코딩 세션 호출은 0회다.
3. 규정집 PDF 1쪽 BD-03의 신청 기한이 어느 순위에서 나오는지 원문과 대조한다. S20의 동일 질문·PDF·설정과 결과를 비교한다. 생성 답변으로 표시하지 않는다. 공개된 자료에는 계정 정보·인증·로컬 경로가 필요 없는 재현 명령을 남긴다.
4. 공개 서버 연결 실패, 배포 버전 또는 hash 부재, Python 호환성 문제, 패키지 자체 오류를 구분한다. 실행 가능하고 호환되는 범위의 설치 안내·진입점 결함은 단계 안에서 수정 후 새 폴더로 검증한다. lock 검사를 끄거나 출처가 다른 캐시로 성공을 대체하지 않는다. 공유 의존성 기준선 변경이 필요하면 영향 범위와 검증 가능한 대안을 기록해 plan으로 전달한다. 배포물 변경 시 공개 dev 반영본으로 마지막 설치를 재확인한다. main 승격·PyPI 게시 없이 dev 증거와 정상 push로 종료한다.
