# P032 S2i · 현재 규정집의 첫 LLM 청킹 경계 검증

## 준비 검토

S2h 종료 d251ad9에서 실제 생성과 출력 잘림을 기록했다. 기존 답변 실험은 종료 상태로 보존한다. 사용자 요청의 LLM 청킹 학습 범위에서 첫 구간 경계만 독립 검증한다. S2a의 로컬 미리보기에는 34개 창이 있고 현행 chunk_artifact.build의 execute는 모든 창을 순회한다. 첫 창 진단은 전체 문서 실행과 구분해야 한다.

## 실행 계약

1. S2a의 전체 원문 snapshot과 256자·겹침 64자 설정을 그대로 사용한다. 설치된 패키지의 preflight로 생성한 w000의 단위 ID, 시작·끝 위치, 순서와 실제 메시지를 S2a와 대조한다. 원문을 잘라 새 문서 ID를 만들지 않는다. 예시 프로필만 S2h에서 확인된 기존 Ollama Qwen 4B 프로필의 chunking 역할로 교체한다.
2. 첫 창 진단은 제품의 메시지 생성·llm.preview/invoke·chunk_policy.parse를 재사용한다. 같은 창의 원문과 선택된 끝 ID·경계를 학습 보고서에 표시한다. 여러 경계가 가능하므로 형식 검증과 의미상 자연스러운 경계인지는 별도로 기록한다. 유효성은 해당 창 안의 고유 ID, 순서, 마지막 단위 포함, 구간당 192자 이하, 첫 창 원문 전체의 연속 피복으로 판정한다. 부분 결과를 전체 문서 청크나 검색 인덱스로 게시하지 않는다.
3. 모델 없는 검증에서 잘못된 ID·순서·중복·마지막 ID 누락·길이 초과·출력 잘림을 주입한다. 실패 후 추가 전송 0, 유효 예시 원문 offset 일치, 일반 전체 문서 빌드 동작 보존을 확인한다. 입력·모델 digest·실행 제어·설치본을 커밋한 뒤 실제 실행한다.
4. 별도 ledger에서 w000 추론 POST 최대 1회, 자동 재시도 0, 순차 1, HTTP 480초/watchdog 510초, 전체 12분, RSS 8GiB 이내. S2h의 서버 소유권·메모리 압력·정리 및 결과 불명 중단 절차를 재사용한다. thinking 텍스트는 저장하지 않는다. 결과·지연·토큰·최대 메모리를 기록하고 나머지 33개 창의 예상 시간은 추정값으로 표시한다.
5. S2h 생일휴가 재호출, 나머지 청킹 창, 실제 임베딩·검색·재순위·평가기·외부 API·Drive는 이번 실행에 포함하지 않는다. 모델 실패도 학습 결과로 보존한다. 전체 문서 비교는 이 결과를 검토한 후 별도로 계획한다. 학습 목차에 보고서를 연결하고 검증 근거를 dev에 커밋·정상 push한다.
