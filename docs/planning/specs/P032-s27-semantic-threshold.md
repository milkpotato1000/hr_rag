# P032 S27 · 의미 거리로 달라지는 청크 경계 관찰

dev 46e581f의 S2b recovery001에는 규정집 단위 567개, E5 단위 벡터와 인접 거리 566개가 저장돼 있다. 기준 설정은 256자, 겹침 64자, 최소 120자, 임계값 0.35이며 내부 경계 249개가 모두 길이 제한으로 생겼다. 설치 CLI의 chunk-derive는 저장 벡터로 임계값만 바꾸는 경로를 제공한다.

## 실습과 검증

1. 저장 자료의 무결성, 모델·단위 설정을 확인한다. 기존 설치 CLI로 동일 기준을 재현하고, 나머지 설정을 고정한 채 임계값만 0.15와 0.05로 바꿔 두 결과를 새 경로에 저장한다. 값을 결과에 맞춰 조정하지 않는다.
2. 세 결과에서 의미 거리·최대 길이·문서 끝에 따른 경계 수를 분리한다. 실제 원문에서 경계가 달라진 첫 위치의 앞뒤 문장, 거리, 누적 길이, 해당 조건과 겹침 구간을 보여 준다. 바뀐 경계가 없으면 그 사실과 조건을 기록한다. 모든 청크의 원문 위치·겹침·전체 범위 보존을 확인한다.
3. 같은 BD-03 신청 기한 질문·BM25·후보20·최종5·예산4000자로 세 결과를 검색한다. 신청 기한과 팀장 승인의 원문 포함 여부 및 전달 순위를 대조한다. 원문 변화나 검색 순위 상승을 미리 가정하지 않는다.
4. 설치 안내에 재현 명령, 저장 벡터가 있어야 하는 이유, 의미 경계와 길이 경계를 판별하는 방법을 연결한다. 원본 산출물 보존과 새 임베딩·생성·외부 요청 0회를 확인한다. 기존 기능을 재사용하고 원인 있는 수정만 적용한다. dev에 검증 기록과 안내를 푸시한다.
