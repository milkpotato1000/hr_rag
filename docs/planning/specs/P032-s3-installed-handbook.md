# P032 S3 · 설치한 패키지로 내 PDF에 첫 질문하기

## 준비 검토

현재 init 샘플은 Markdown·TXT 두 문서로 시작한다. 문서별 CLI와 설정 설명, 규정집 검색·답변·청킹 보고서는 있지만 설치 직후 현재 PDF를 연결하고 실제 답변을 확인하는 연속 실습이 분산돼 있다. S2j의 첫 창 결과(입력 1,037토큰, 출력 4,096토큰에서 잘림)는 기록하고 추가 청킹 호출은 종료한다. 기존 구현과 설치 가이드를 활용해 독립 폴더에서 실행 가능한 흐름을 검증한다.

## 산출물과 수용 기준

1. init의 START_HERE 및 학습 목차에서 하나의 PDF 실습으로 진입한다. Claude Code 또는 Codex에서 그대로 사용할 짧은 요청 예시와 사람이 따라 할 CLI 순서를 제공한다. 로컬 PDF 경로, 질문, 모델 설정이 어디에 들어가는지 명시한다. 기존 규정집은 사용자 제공 파일에 해당하며 패키지에 복제하지 않는다.
2. 설치된 CLI의 일반 진입점에서 PDF 의존성 확인 → 가상 규정집 snapshot → 고정 청킹·BM25 build → ask preview로 질문·원문 페이지·전달 문맥 확인 → Ollama 모델 설정 → 명시적 ask 실행 → 답변·인용·원문 확인을 연결한다. 로컬 기본과 유료 API 선택의 공통 단계 및 generation 설정 교체 지점을 보여준다. API는 네트워크·키 조회 없는 설정 검증까지만 진행한다. 기존 UI에서 같은 결과를 여는 지원 경로가 있으면 실제 명령과 화면 위치를 안내한다.
3. 제공된 spec으로부터 기존 Qwen 4B의 실제 프로필(Thinking 지원 포함)을 정상 CLI로 만들 수 있는지 검증한다. 일반 경로의 결함이 있으면 필요한 최소 수정과 호환성 검증을 포함한다. 저장된 dev 실행 폴더·절대경로·임시 wheel에 의존하지 않도록 문서와 정적 샘플을 대조한다.
4. 새 wheel/독립 설치·새 실습 폴더에서 문서에 인쇄한 명령을 재현한다. 설정 예제·패키지 resource manifest·링크를 확인하고, 모델 없이 preview에서 실제 전송 전까지를 검증한다. 그 후 일반 ask에서 기존 로컬 Qwen 4B에 현재 규정집 질문 하나를 전달한다. 입력 질문은 첫 사용자 실습에 맞춰 “생일 특별휴가는 사용 며칠 전까지 신청해야 하나요?”로 고정한다. 이는 새 단일 질문의 설치 경로 시험이다. 과거 gt01 복합 질문의 6개 조건 통과 기록으로 합산하지 않는다.
5. 기존 소유 서버·digest·실행 제어를 사용한다. 추론 1회, 자동 재시도 0, HTTP 480초/watchdog 510초·전체 실행 12분·RSS 8GiB 제한. 실제 답과 BD-03 인용을 원문과 대조하고 “3영업일 전 신청” 및 승인 시한 추가 여부를 판정한다. 실패 시 해당 단계·실제 결과·진단 위치를 그대로 문서에 남긴다. 검증 보고서, 학습 진입점, dev 커밋과 정상 push를 확인한다. Drive·평가기·유료 API 실행·추가 청킹 창과 모델 다운로드는 보류한다.
