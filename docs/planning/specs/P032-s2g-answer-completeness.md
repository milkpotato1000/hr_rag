# P032 S2g · 복합 질문의 조건과 예외를 담은 답변

## 준비 검토

S2f 결과 d40bb30에서 gt01은 유효한 답변과 PDF 1쪽 인용 3개를 반환했다. 필수 조건 6개 중 수습 직원 제외가 빠졌고 해당 문장은 인용된 BD-01 안에 있다. 기존 document-rag-json-v1은 근거·보류·인용 형식을 지시한다. 이번 비교의 가설은 복합 질문의 각 부분과 그 답을 바꾸는 예외까지 확인하라는 일반 지시가 누락을 줄일 수 있다는 것이다.

## 개발 범위와 통과 기준

1. 문서 답변용 시스템 프롬프트에 “질문이 묻는 각 항목에 답하세요. 근거에 대상·범위를 제한하는 조건이나 예외가 있으면 해당 답과 함께 명시하세요. 질문과 무관한 세부사항은 생략하세요.”와 같은 일반 지시를 추가하고 버전을 구분한다. JSON 구조, 근거 부족 시 보류, 인용 규칙을 유지한다. 정답지·질문별 예시·개별 규정 명칭을 프롬프트에 넣지 않는다.
2. ask와 answer-from-rerank에서 같은 새 지시와 버전을 쓰는지, preview와 실제 요청이 일치하는지 모델 없이 검증한다. 기존 산출물 읽기, 이전 결과 보존, 새 wheel 독립 설치와 회귀를 확인한다. 모델·옵션·스키마·질문·검색 문맥·순서·사용자 메시지를 고정하고 S2f 요청과의 차이가 시스템 지시뿐인지 확인 후 입력과 제어를 커밋한다.
3. S2f 종료 기록은 보존한다. S2g 전용 ledger로 같은 로컬 4B에서 gt01을 1회 실행한다. 필수 6개가 답변에 명시되고 인용 원문이 주장을 지지하는지 검토한다. 통과하면 gt02, 이것도 통과하면 나머지 8문항으로 확장한다. S2f의 gt02 및 잔여 문항별 검토 기준과 기술·내용 중단 규칙을 유지한다. 질문당 1회·최대 10회(이전 세 호출 포함 누적 13회), 자동 재시도 0, S2f와 같은 순차 실행·90분·자원 및 종료 한도를 적용한다.
4. 보고서에서 gt01 변경 전후 실제 답변·인용·필수 항목을 나란히 제시한다. 한 질문의 변화로 일반적인 모델 성능 개선을 단정하지 않는다. 학습 목차 연결과 dev 커밋·정상 push까지 확인한다. Drive, API 호출, 평가기, LLM 청킹은 보류한다.
