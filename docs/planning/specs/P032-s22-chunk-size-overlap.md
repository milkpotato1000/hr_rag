# P032 S22 · 청크 크기·겹침·전달 예산 실습

## 준비 검토

dev ce76826의 설치 화면에는 규칙 청킹 크기·겹침 입력이 있다. 통합 pipeline-setup은 기존 chunk-config 파일을 필수로 받고 S6·S13 안내는 400/80에서 방법을 바꾼다. 학습자가 코딩 도구에 숫자만 지정해 재사용할 구성을 만들고, 한 질문으로 세 값이 서로 다른 단계에서 작동함을 관찰하게 한다.

## 구현과 증거

1. 기존 청킹 설정을 기준으로 size_chars·overlap_chars를 명시적으로 바꿀 수 있는 설치 CLI 경로를 제공한다. 기존 pipeline-setup 또는 그 입력 준비 로직을 재사용한다. 지정하지 않은 방법·제목 프로필·모델 설정을 보존하고, 기존 validator로 허용 범위 및 모델 기반 청킹의 단위 길이 충돌을 검출한다. 기존 파일을 변경하지 않고 유효 설정을 설치 CLI 미리보기와 학습 UI에 동일하게 전달한다. 이미 동작하는 화면 조절 기능을 재구현하지 않는다.
2. 같은 규정집·BD-03 신청 기한 질문·BM25·리랭커 끔·후보 수·최종 K를 고정한다. 기준 400/80에서 (a) 크기만 변경 (b) 겹침만 0으로 변경 (c) 전달 예산만 축소하는 세 비교를 만든다. 숫자와 질문은 검색 전에 기록한다. 원문 청크 수·경계·겹치는 문자 범위, 후보 순위, 전달 여부·실제 문자량, 신청 기한과 신청 행위가 함께 보이는지를 설치본으로 계산한다. 전달 예산 비교에서는 같은 청크와 순위를 재사용/대조하고 예산을 넘는 청크를 현재 구현이 실제로 어떻게 처리했는지 확인한다.
3. 원문 구간과 전달 청크를 인용한 간단한 학습 표, Codex/Claude Code 요청 예시, 재현 명령을 기존 안내에 연결한다. 청크 크기·전달 예산은 문자, 모델 입력 창은 토큰이라는 단위 차이 및 겹침의 효과를 해당 관찰값으로 설명한다. 답변 생성 품질은 측정하지 않는다.
4. 독립 wheel에서 예제 변경값 및 잘못된 겹침·기존 설정 호환·원본 보존·CLI/UI 설정 일치를 확인한다. 검색 계산은 BM25만 사용한다. 모델·Drive·유료 API·외부 코딩 세션·평가기 호출 없이 검증 자료와 dev push까지 진행한다.
