# P032 S2h · 기한과 행위를 연결하는 규정 답변

## 준비 검토

S2g dev 완료 3d8366f의 gt01 검토에서 수습 제외는 복원됐지만 신청 기한이 승인 완료 시한으로 읽혔다. 6개 필수 사실 중 5개 명확, 1개 부분 전달이며 gt02~10은 미실행이다. S2f와 S2g의 출력과 중단 기록을 보존한다.

## 구현과 독립 검증

- S2g의 근거·조건·예외·보류 규칙 위에 일반적인 표현 지시만 추가한다. 예를 들어 “근거에 여러 절차가 있으면 각 행위를 별도 문장이나 항목으로 쓰세요. 기간·수량·조건은 원문에서 직접 수식하는 행위에 붙이세요.” 질문별 키워드, 정답, 모범 문장, 정답지를 요청에 넣지 않는다.
- S2g와 같은 모델 digest, 설정, 구조화 출력, 질문·검색·전달 청크와 순서를 유지한다. 두 제품 진입점의 prompt version, 실제 요청/preview 일치, 과거 결과 읽기, 회귀 및 새 설치를 모델 없이 확인한다. 동결한 요청 차이는 시스템 메시지에 한정한다.
- S2g에서 완료된 한 번을 포함하면 기존 누적 생성은 4회다. 신규 ledger에서 질문당 한 번·순차 실행·자동 재시도 0, 최대 10회(누적 14회)로 제한한다. S2g의 90분·메모리·서버 및 기술 오류 중단 조건을 유지한다.
- gt01의 대상·예외·일수·신청·사용 관련 필수 6개와 인용을 원문에 직접 대조한다. 어떤 행위에 기한이 걸리는지 별도 기록한다. 근거가 없는 시한 추가나 예외 누락은 중단한다. 통과하면 gt02, 양쪽 모두 통과하면 잔여 8개로 확장한다. S2f/S2g의 문항별 의미 검토 조건을 그대로 쓴다.
- 세 버전의 gt01 답변과 인용을 학습 보고서에서 대조한다. 실패해도 보존하고 같은 질문의 추가 프롬프트 변형을 자동으로 승인하지 않는다. 완료 기록과 보고서를 personal/dev에 전달한다. Drive와 평가기 실험은 보류한다.
