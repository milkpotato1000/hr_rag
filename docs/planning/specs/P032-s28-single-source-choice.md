# P032 S28 · 원문을 한 번 읽고 청킹 후보 선택하기

## 근거와 가설

dev c3c3996의 window_input은 후보별 pieces에 원문 전체와 오프셋을 반복해 보낸다. S17과 S18은 동일한 후보와 질문에서 일반 JSON과 enum을 각각 사용했으나 둘 다 출력 상한 4,096토큰에 도달했다. 저장된 기록으로 잘림의 내부 원인을 특정할 수 없다. 이번에는 같은 선택 과제에서 입력 표현만 바꾸고, 실제 모델의 선택 결과를 확인한다.

## 구현과 검증

1. 선택형 LLM 청킹의 선택 옵션으로 원문 단위를 순서대로 한 번만 제시하고, 각 후보는 해당 창의 단위 번호 경계 목록으로 제시한다. 이전 후보별 전체 원문 방식과 저장 결과 재생을 보존한다. 생략이나 요약 없이 모든 원문과 두 분할안을 복원할 수 있어야 한다. 정답 힌트·선호 후보를 입력하지 않는다. 제품 경로의 선택·파싱·원문 피복 검증을 재사용한다.
2. S18에서 사용한 교육휴가 PDF, 후보 1·2의 경계와 순서, Ollama 모델 digest·thinking·출력 상한·seed·enum을 고정한다. 호출 전에 기존 요청과 새 요청을 비교해 변경된 입력 표현, 실제 후보별 복원 원문 및 입력 크기를 기록한다. 한 후보일 때 모델 호출 생략, 잘못된 ID·잘림 거부, 여러 창의 번호 범위, 이전 설정과 저장 결과 재생을 검사한다.
3. 기존 안전 점검 후 설치본의 새 제품 경로에서 로컬 Qwen 4B를 한 번 호출한다. 완결된 유효 ID가 있으면 선택된 청크의 원문·페이지·제1조 제목과 본문 보존을 확인하고 BM25로 교육휴가 대상 질문의 전달 근거를 기록한다. 모델 선택이 사람이 선호한 후보와 달라도 원래 결과를 남긴다. 실패하면 기술적 결과를 기록하고 중단한다. 이전 실험의 호출 장부는 재사용하지 않는다.
4. 실제 성공·실패와 설치본 재현 경로를 기존 학습 가이드에 연결한다. 이 사례 하나를 일반적 품질 개선으로 해석하지 않는다. 새 모델·Drive·유료 API·평가기 호출은 범위 밖이다. 결과와 회귀 검사를 dev에 반영한다.
