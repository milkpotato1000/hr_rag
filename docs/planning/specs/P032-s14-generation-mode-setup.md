# P032 S14 · 첫 설치에서 답변 모델 고르기

## 준비 검토

dev 96849b1의 설치본은 규정집과 실제 로컬 실행 예제를 제공한다. llm-configure는 spec 파일을 필수로 받으며 START_HERE와 HANDBOOK의 다른 모델·API 예제는 학습자가 JSON을 편집하도록 한다. handbook-qwen-spec은 개발 머신에서 쓴 Thinking 변환본의 출처를 미리 담고 있다. 같은 별칭을 쓰는 다른 설치에서 모델 출처까지 동일하다고 가정할 수 없다.

## 범위와 완료 기준

1. 새 설치 폴더에서 로컬 Ollama 또는 선택형 상용 LLM API와 모델을 고르고 **JSON 수작업 편집 없이** 규정집 답변용 구성을 만든다. Codex와 Claude Code가 같은 비대화식 CLI로 실행할 수 있도록 기존 llm-configure·설정 검증·프로필 등록을 재사용한다. 출력된 프로필과 실제 다음 pipeline/serve 명령이 연결되어야 한다. 사용자 지정 spec과 기존 실습 명령도 계속 동작한다.
2. 로컬 경로에서 이미 설치된 정확한 별칭을 지정할 수 있고, 원하면 등록된 로컬 모델 목록을 메타데이터 조회만으로 확인한다. S11/S13의 실측 모델 digest와 일치할 때 해당 예제 출처와 설정을 제공할 수 있다. 다른 digest는 별칭이 같아도 실험의 HF 출처·양자화·Thinking 설정을 자동 확정하지 않는다. 서버에서 확인한 값·사용자 입력·미확인을 구분하고 실제 실행의 기존 identity 검사를 유지한다.
3. API 경로는 지원 중인 provider, 모델, endpoint와 키 환경변수 **이름**을 받는다. 생성한 설정과 미리보기에서 선택 모델 및 문서 전송 대상을 확인한다. 설정 단계에 토큰값 입력·저장, 키 조회, 네트워크 유료 호출은 필요하지 않다. 기존 출력과 사용자 설정 덮어쓰기를 방지한다.
4. 독립 설치본에서 두 경로를 각각 선택하고 생성된 설정을 동일 PDF·같은 질문의 통합 실행 미리보기까지 연결한다. 로컬 metadata fixture로 별칭 동일/digest 다름, 등록 모델 부재, 기본 예제와 동일한 digest, API는 키가 없는 설정 및 실행 전 미리보기를 검증한다. 구성 생성과 재열기에서 모델 추론 0회. 두 코딩 도구에 그대로 줄 요청과 수동 명령을 설치 학습 안내에 싣고 실제 시험과 미검증 범위를 명시한다. 실제 유료 호출·Drive·평가기·모델 다운로드는 보류한다.
