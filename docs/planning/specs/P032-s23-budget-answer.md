# P032 S23 · 전달 예산이 달라진 두 문맥에서 실제 답변 확인

## 준비 검토

dev 2bc89ab의 S22는 같은 신청 기한 질문에서 예산 4,000자와 400자 모두 신청 기한 근거를 전달했다. 팀장 승인까지 포함한 조항 전체는 4,000자 조건에만 남았다. 실제 생성 호출은 0회였다.

## 실행 및 검증

1. S22 inputs.json의 질문과 고정 크기 400자·겹침 80자·BM25·리랭커 끔 설정을 그대로 쓴다. 같은 설치 CLI에서 예산 4,000자와 400자만 바꾼다. 모델에 들어가는 문맥 ID·길이·내용을 S22 전달 결과와 대조하고 모델 식별자·생성 설정을 고정한다.
2. 기존 로컬 Ollama Qwen 4B로 각 조건을 한 번씩 순차 생성한다. 기존 메모리 사전 점검과 호출 기록 및 실패 시 중지 기준을 적용한다. 모델 설치, 유료 API, Drive 및 자동 평가기 호출은 범위 밖이다.
3. 질문의 필수 답은 ‘사용 3영업일 전까지’다. 각 답변 원문, 날짜 단위와 방향, 인용 ID와 실제 지지 구절, 보류·실패 여부를 기록한다. 팀장 승인은 보충 정보다. 빠져도 기한 누락으로 세지 않고, 언급하면 실제 전달 문맥에서 지지되는지 별도로 확인한다. 두 문맥 모두 기한을 포함하므로 짧은 예산에서 무조건 답변 불가로 판정하지 않는다.
4. 기존 학습 가이드에 두 입력과 관찰된 답변을 나란히 제시하고 재현 명령을 연결한다. 서로 다른 출력이 있어도 단일 쌍에서 일반적인 성능 차이를 추정하지 않는다. 실험 기록과 변경 파일을 dev에 커밋하고 푸시한다.
