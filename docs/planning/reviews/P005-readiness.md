# P005 기획 준비 검토

검토일: 2026-10-22 Asia/Seoul
상태: 준비 완료·P004 선행 대기

사용자는 구현·테스트·수정은 Codex가 끝까지 맡고, 본인은 의미 이해·평가·최적화 실험에 집중할 수 있는 Naive RAG E2E를 요청했다. P문서별 순차 진행 지시에 따라 P004 생성과 P005 화면·최종 인계를 분리한다.

## 준비 근거와 순서

P003은 dev/personal-dev 커밋74b3c35a551671e1387904a0715ea5f8a1625a0c에서 완료됐고 실제모델·영속검색·53개 회귀 증거를 검토했다. P004는 plan a043f1a3527df9f375b4fe8c0876d9f3417bbb00에서 CLI·재사용코어·결과/trace스키마·인용·보류·장애·실14질문 검증계약을 고정해 준비 완료로 인계했다.

P004가 구현 중인 동안 다음 독립 인터페이스·인계 과제를 plan이 준비할 수 있다는 AGENTS.md 위임에 따라 P005를 선행 대기로 등록한다. 준비 완료는 P004가 이미 끝났다는 뜻이 아니다. dev는 P004 전체검증·완료커밋을 먼저 마친 뒤 P005 착수 시 그 실제 결과와 계약을 대조한다. 결과스키마나 품질이 맞지 않으면 무시하지 않고 피드백·수정한다. 두 작업을 동시에 진행하지 않는다.

## 검토 판단

- 대상은 현재 `1. Naive RAG/` 하나다. 검색·생성 로직을 UI에서 다시 만들지 않고 P004 코어를 재사용한다.
- 화면은 질문입력·후보순위·선택문맥·답변·인용·보류/장애·설정·시간을 관찰하는 학습용 로컬UI다. 외부계정·원격배포·새 큰단계·Agent기능이 필요하지 않다.
- P004에 고정된 status·answer·citations·reason·trace가 UI/API의 입력계약이다. localhost HTTP와 로컬 자산만 사용한다. 실제화면·에러·좁은화면 확인을 완료기준으로 두어 API테스트만으로 끝내지 않는다.
- 실제모델 E2E와 모의provider HTTP통합을 구분한다. 정상답변·근거없는 질문·복수근거를 직접 실행하고 기존회귀·단독복사·실행/종료 인계를 확인한다.
- 학습가이드는 실제질문·실행명령·관측실패를 바탕으로 예상→관찰→원인계층→한변수실험→결과해석을 안내한다. 테스트통과·유효인용·의미정확성을 구분한다.
- 사용자는 직접 모델설치·코드구현·테스트작성으로 넘겨받지 않는다. 구현·검증·실행은 Codex가 맡고 최종 화면·가이드와 실제한계를 인계한다.

기능·출력·실패·검증·학습목차·완료조건이 명시돼 P004 완료 이후 실행 가능한 계약으로 등록한다. P004 완료 후 실제 구현과의 대조는 선행 검증이며 별도 인계허가를 반복해서 묻는 단계가 아니다. 상세는 [P005](../plans/P005.md)를 따른다.
