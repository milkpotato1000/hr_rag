## 연구 근거와 프로젝트 결정의 구분

- [NIST TREC 2006 QA](https://trec.nist.gov/pubs/trec15/papers/QA06.OVERVIEW.pdf)는 vital/okay 정보 단위를 구분하고 필수 정보 Recall을 평가했다. 필수와 허용 보충의 구분에 대한 선례이며, 여기서 사용하는 원자 P/R/F1 전체가 그 공식과 같다는 뜻은 아니다.
- [Ragas Factual Correctness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/factual_correctness/)는 생성/기준 claim 겹침의 P/R/F1과 atomicity/coverage를 명시한다. 단순 reference 미매칭은 사실적 거짓과 다르며, 기준 답변 범위가 점수에 영향을 준다.
- [Ragas Response Relevancy](https://docs.ragas.io/en/v0.2.0/concepts/metrics/available_metrics/answer_relevance/)는 질문 관련성을 사실성과 구분한다. 선택 정보의 정확성과 관련성·간결성을 한 점수로 뭉개지 않는 근거다.

필수38/보충19, 핵심 범위 P/R/F1과 전체 생성 근거 비율의 분리는 사용자 위임에 따른 이 프로젝트의 정책 결정이다. 보편 표준이나 위 논문의 그대로인 구현으로 주장하지 않는다. 기대 점수는 [채점 정책](../specs/P023-scoring-policy.md)에서 별도 정의한다.

## 승인 이력

사용자는 run003 gt01의 첫 다섯 항목을 순서대로 명시 승인했다(재직 기간, 연1일, 수습 제외, 생일월, 근무일). 해당 parent packet/ID/text/source와 함께 역사로 기록한다. 여섯 번째 이후와 다른 질문은 Codex 위임 검토 결과이며 직접 사람의 항목별 승인을 받은 것으로 표시하지 않는다. 위임·분류 정책의 수락은 새 패킷 전체의 실제 사람 정답 승인이나 평가기 판정 라벨 승인이 아니다.
