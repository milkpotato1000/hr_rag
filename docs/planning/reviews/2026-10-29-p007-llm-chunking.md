# P007 LLM 기반 청킹 추가

2026-10-29 사용자 “llm 기반도 포함해보자” 요청을 P007 초안에 반영했다. 기존 BGE-M3 임베딩 의미 분할과 구별되는 다섯 번째 방법이다. 원문·추출본은 P015 산출물로 고정하고 문서 처리 모델은 경계 ID만 선택한다. Python이 원문 slice·coverage·source map을 검증하므로 모델의 요약/재작성 텍스트가 검색 corpus로 들어가지 않는다.

계약에는 입력 window/합치기·구조화 응답·원문 누락/중복/재배열 방지·오류/제한된 재시도·원응답/최종 경계 기록·실제 호출/토큰/시간·캐시와 새 반복 구분·경계 일관성 비교를 포함했다. 관련 UI 표시와 C1/C3/C5 완료 조건을 함께 확장했다. LLM 성능 우위를 완료 조건으로 요구하지 않는다.

모델 버전·prompt/schema·window·후처리·호출/시간 상한·반복 횟수/산식은 P015 실제 분량을 확인해 READY 전에 확정한다. 청킹용 LLM은 P013의 답변 평가기와 별개이며 P013을 선행으로 추가하지 않는다. P015 → P007 → P013 → P014 → P008 → P010 순서, P007 초안/미착수 상태, 준비 완료 P015와 기존 완료 카드/제품 코드는 유지한다. 새로운 모델 다운로드·실행을 승인하거나 구현 완료로 표시한 변경이 아니다.

검증은 큐 순서·선행 순환·문서 링크·완료 조건/실행 상태·변경 범위로 수행한다. 이 추가 계획은 앞선 P007 UI 인계의 후속으로 정확한 커밋을 dev에 전달한다.
