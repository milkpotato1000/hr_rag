## 코드와 범위 대조

P030 완료 계약과 dev의 chunk_artifact.preflight/build, chunk_policy 및 설치 예시를 읽었다. 규칙3종은 deterministic make_chunks/publish, semantic/llm은 execute=false일 때 preview artifact를 반환한다. semantic preflight는 unit수/profile max_chunks를 검사하고, LLM preflight는 각 window의 실제 preview body byte와 상한을 검사한다. S1 E5 profile max_chunks5000, token512, CPUfloat32batch1은 그대로 참고하며 이번에는 encode를 호출하지 않는다.

size256/overlap64와 model unit120/minimum120/threshold0.35는 계약에 고정했다. LLM window1200문자/20unit/64window/16384bytes는 기존 지원 범위다. 실제 window수가64를 넘을 수 있으므로 실패를 기록하고 설정을 즉석에서 늘리지 않는 조건을 넣었다. 미설정 local/API 예시의 preview는 선택/인증/실행 성공이 아니다. 정확 tokenizer가 없으면 토큰 보장을 하지 않는다.

모델 입력에 query/GT를 넣지 않고 source fact의 단일/복수 청크 포함 여부만 사후 원문 대조한다. 전체 청크 합집합 포함을 retrieval recall이라고 부르지 않는다. 다른 chunk fingerprint에 S1 qrels를 재사용하지 않는다. source/fact/source mapping의 동일성은 보존하며 기존 목차/heading 문제를 숨기거나 S1 원문을 수정하지 않는다.

## 완료·중단 경계

사전 준비 완료 증거는 규칙3 artifact, 두 모델 방식의 실제0호출 preview 또는 명시적인 사전거부, source/설정/설치 identity, 단위·window·크기·예상 작업량, 경계 검토,0모델/0네트워크/0키 검증, 보존 hash 및 커밋된 학습 안내다. 기존 제품 기능의 결함/새 요구는 적절한 intake로 되돌린다. 모델/검색/답변 실험은 시작하지 않는다.

이 검토는 실행 모델 선택을 대신하지 않으며 P013/P014·P029 C4·기존 grant를 재개하지 않는다. S1 완료 한도를 새 호출에 전용하지 않는다. 사전 준비 이후 실제4방식과 LLM·답변 비교의 각각 필요한 새 실행 계약/선택이 남는다. 별도 dev가 정확 READY를 채택·커밋·guard/queue 확인 후 수행하고 정상 personal/dev 전달한다. main 승격은 포함하지 않는다.
