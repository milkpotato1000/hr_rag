# Project B 학습 범위 등록 검토

2026-10-29 사용자 제공 설계와 후속 순서 요청을 plan에 반영했다. 준비 완료 검토가 아니라 **초안 등록**이다. plan 작업 전 clean과 새 접수 대기0건, P012가 dev에서 진행 중임을 확인했다. dev의 미커밋 구현·증거·P012 계약/로그를 수정하거나 현재 작업을 중단하지 않았다. 이 요청은 plan 직접 접수이므로 가상의 dev R번호를 만들지 않는다.

확정 순서: P012 → 외부 설치형 하네스 완료 → P013 기본 LLM 평가기 → P014 NLI 비교 → P010 Hybrid → P007/P008. NLI 비교는 기본 평가기의 다음 과제로 배치했고 성능 우위를 필수 결과로 강제하지 않는다. B는 번호 단계가 아닌 별도 모듈이며 A/C 정의는 미확인이다.

P013 우선순위67/선행P012, P014 우선순위68/선행P013, P010 우선순위69/선행P014로 큐에 반영했다. 외부 하네스 완료는 실제 저장소·완료 commit/tag·검증 근거를 P013 준비 검토에서 확인한다. 문서상 등록만으로 다운로드/모델 평가·사람 승인·하네스 완료를 주장하지 않는다.

Faithfulness premise는 검색 전체가 아닌 실제 전달 snapshot으로 정했다. Ground Truth의 실제 사람 승인, 공통 추출 claims, Python 산식과 0분모/보류/불확실·중복/부분일치, 평가기 자체 검증, 모델 역할 분리·NLI 입력 한도/한국어/다중 근거를 준비 항목에 넣었다. Qwen3-8B는 평가 후보이며 기존 생성4B를 자동 교체하지 않는다. corpus·질문수·승인 세트·모델 revision/실행환경·자원/호출 상한·판정 기준·UI 범위를 확정한 뒤 READY로 전환한다.

기획 검증: 큐/카드 파싱·선행 순서와 P012 진행 중/P011 완료 유지, 수정 문서의 로컬 링크·diff 공백 검사. 제품 코드/모델 실행 검증은 이번 작업에 해당하지 않는다. 작업 중 dev가 P012를 완료·push해 최종 큐에서4/4 완료를 확인했고 현재 roadmap/brief 상태를 갱신했다. 기존 dev 채팅에 추가 실행 메시지를 보내지 않고 계획을 커밋·정상 plan push로 공유한다.

사용자가 A=NL2SQL+Tool Calling, B=RAG→Agentic RAG, C=Multi-Agent Orchestration의 전체 정의를 제공했다. 위 최초 등록 당시의 “B는 별도 모듈/A·C 미확인” 해석은 현재 정의로 대체한다. 현재 HR RAG 전체가 B이고 P013/P014는 B 내부 평가 모듈이다. [프로젝트 구분](../project-map.md)에 출처·전체 학습 영역·완료/초안 구분을 기록했다. 기존 평가 모듈 범위·초안 상태·하네스 이후 평가기→NLI→Hybrid의 사용자 확정 순서는 바꾸지 않았다. A/C 구현이나 새 dev 실행을 시작하지 않았다.
