## 남은 문서 문제와 범위

README는 여전히 초기 P024 설계 JSON과 이전 BM25 실행을 중심에 놓고 현재 init 설치 안내를 하단에 둔다. 실행 가능한 spec과 설계 전용 JSON, 현재 지원과 단계 당시 상태가 섞여 있다. 일반 RAG 답변 흐름 아래 보류된 평가기가 필수처럼 표시되는 부분도 정리해야 한다. 이는 S1/S2b 결과 링크 추가만으로 해결되지 않은 실제 사용 경로 문제다.

`rag_package/resources/sample/START_HERE.md`와 workspace.init의 manifest 검증을 읽었다. 문서 resource를 바꾸면 새 wheel/sdist·resource manifest가 일치해야 하므로 source 없는 새 core-only 설치에서 init과 preview 명령을 검증한다. 이전 실제 검색 wheel9342add...는 그대로 보존하고 새 문서 wheel을 실제 검색 검증본으로 소급 표시하지 않는다. runtime 알고리즘·SDK·모델 파라미터 변경은 필요하지 않다.

기존 build 도구가 불완전할 경우 고정 build lock만 새 전용 환경에 설치하는 것은 문서 배포물 생성에 필요한 범위다. 모델 다운로드·retrieval SDK 재설치·LLM/API/Ollama/Drive 호출은0이다. 링크/CLI help·init 파일·core preview·두 모드 설정 검증은 새 사용자 경로의 정확성을 확인하지만 실제 생성/API/Drive 성공을 증명하지 않는다.

정확 채택 후 dev가 문서 정리→필요 resource hash/배포물 갱신→모델0 설치 실습→근거 커밋→정상 personal/dev 전달을 수행한다. S2b가 이미 정리한 설명은 보존하고 중복 수정하지 않는다. P032 전체 체크·P013/P014·P029 C4·실제 생성/Drive 선택은 이번 범위와 별개다.
