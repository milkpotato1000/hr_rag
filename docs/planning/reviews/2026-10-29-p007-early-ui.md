# P007 원문·청크·검색 UI 조기 제공

2026-10-29 사용자 요청: “P007부터 원문·청크·검색 비교 UI도 쓸 수 있게 플랜에 반영하고 dev에 전달해줘.”

P007 초안에 원문/PDF·추출 텍스트·청크 경계/설정·색인 상태·같은 질문 검색 A/B·검색 지표/실패·artifact 다운로드를 추가했다. 실제 코어를 사용하는 브라우저·키보드·390/1200px·오류/재실행·단독 복사 검증을 완료 조건 C5로 추가하고 기존 채택/큐 조건은 C6로 유지한다. 검색 정답 없는 임의 질문은 N/A이며 답변 품질 점수를 흉내 내지 않는다.

P008은 P007 UI를 다시 만드는 작업이 아니라 실제 전달/제외 문맥·답변/인용·보류·P013/P014 평가 점수를 확장하는 작업으로 좁혔다. P015 원문 준비 범위는 그대로다. 의존 순서 P015 → P007 → P013 → P014 → P008 → P010을 유지한다.

기존 P012 UI 구성은 새 `2. Document Chunking/`에서 재사용하되 `1. Naive RAG/`의 코드/화면/기본 corpus와 실행 포트를 보존한다. 이 계획 변경으로 기존 화면이 바뀌었다고 주장하지 않는다. 전체 웹 복사는 P015가 아닌 P007의 범위다.

P007은 P015 산출물을 확인해 검색 정답/실험 그리드·자원 상한·UI/API·비동기 실행 수명·복사 범위를 확정해야 하므로 아직 초안이다. 이번 범위 승인은 초안 자동 구현 허가가 아니다. P015는 기존 준비 완료를 유지한다. dev에는 정확한 plan 커밋과 이 경계를 전달하고 안전한 통합·채택/수신 확인까지만 요청한다. 별도 제품 구현 시작 요청은 보내지 않는다.

검증: 변경한 문서의 상대 링크, P007 6개/P008 5개 완료 조건, 미착수 상태/비어 있는 실행 로그, 큐의 다음 plan=P007/dev=P015, 선행 순환 없음, 완료 카드와 제품 코드 무변경을 확인한다. plan 훅의 dev 계약 검사는 plan에서 SKIP하는 설계이며 제품 회귀 통과로 보고하지 않는다.
