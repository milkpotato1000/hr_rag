# P032 S2d 준비 검토

2026-11-28 READY. 사용자가 기존 로컬 Qwen4B·현재 규정집 실제 답변 검증을 선택하고 dev 직접 전달을 요청했다. Drive 연결은 명시 보류다. [실행 계약](../specs/P032-s2d-local-generation-contract.md)은 해당 선택만 실행 가능하게 하며 P013/P014 및 LLM 청킹/API 비교를 재개하지 않는다.

## 코드·증거 검토

- dev clean HEAD/personal-dev `0ea558018b94b50d29c54fe45cb2ba34616c4356`와 S2c 완료 기록을 확인했다. source 없는 core-only wheel `87744fba87853c84a2a3c9b05b80a727c72d1113812139029210f4d664fba6bd`는 기존 runtime을 유지한다.
- `rag_package/__main__.py`의 answer-from-rerank, `reranking.load/answer`, `rag.messages_for/business_answer`, `llm.core.preview/invoke`, `llm_setup.configure`를 읽었다. 저장 후보/문맥 검증 후 생성만 호출하는 경로가 이미 있으므로 신규 CLI/재검색 없이 이번 비교가 가능하다.
- [590입력 해시](p032-s2d-input-audit.json)를 새로 계산했다. S1 none 경로10개는 E5 Hybrid 후보와 원문을 포함한다. 모든 문맥은5청크·1280자이며 gt01=6/6,gt02=3/3,gt03=3/8,gt08=2/8이다. gt09/10은 사실0이지만 문맥은 존재하므로 실제 답변의 보류를 검토해야 한다.
- 기존 local 예시는 8B judge와 text 모드를 포함하므로 그대로 실행하면 안 된다. 4B 하나의 새 json_object profile을 만들고 generation 역할만 호출한다. 과거4B는 Thinking-2507/Q4_K_M digest이며 현재 metadata와 일치 여부는 dev 사전 확인 대상이다. strict thinking 거부는 완화하지 않는다.

## 실행 준비 판단

원문·질문·저장 문맥·제품 호출 경로가 고정돼 있고 사용자 모델 선택이 확정됐다. 10회/45분/단일 호출 및 smoke2의 내용·기술 게이트,180초HTTP/210초watchdog, metadata200회, RSS8GiB/critical pressure 중단을 운영 한도로 확정했다. 숫자는 모델 성능 보장이나 하드웨어 최소치가 아니다. 실제 서버 상태·가용 메모리는 plan이 조회하거나 실행하지 않았으며 dev의 사전 점검 실패면 생성0으로 멈춘다.

기존서버 우선, 필요 시 설치된 Ollama의 소유 loopback 서버1회 시작만 허용한다. 다른 모델/프로세스 강제 종료나 다운로드는 없다. 기존 P013 중지·grant를 우회하지 않도록 별도runner·ledger 및 timeout/소유권/중복방지 독립 시험을 선행한다. 실패 시 소유 client 종료만으로 서버 추론 종료를 단정하지 않는다.

내용 검토는 자동 평가기 실험과 구분한 Codex 원문 대조다. GT를 프롬프트에 넣지 않고, 필수정보 누락의 검색/생성 원인을 나누며 새 승인이나 일반화 품질을 주장하지 않는다. 기존 실패와 학습 자료는 보존한다. 완료와 중단 양쪽의 보고 기준이 명시됐으므로 이 범위의 준비 완료·정확 채택·dev 착수가 가능하다.
