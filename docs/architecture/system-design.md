# HR RAG 시스템 아키텍처 방향

검색, 에이전트 제어, 모델 서빙을 분리해 한 계층을 바꿔도 같은 평가 데이터를 사용할 수 있게 한다. 전체 범위는 [프로젝트 기획](../planning/project-brief.md)을 따른다. 이 문서는 후속 설계 방향이며 P001의 구현 범위는 합성 데이터와 평가기에 한정한다.

## 처리 경로

질문 입력 → Python 애플리케이션 → 검색 또는 모델 호출 → 검증한 도구 실행 → 근거 확인 → 출처 포함 답변 또는 보류·담당자 연결 순서로 처리한다.

| 구성 요소 | 책임 | 주요 경계 |
| --- | --- | --- |
| 입력 어댑터 | 로컬 CLI, 후속 FastAPI·Slack 요청을 공통 질문으로 변환 | 요청 ID와 사용자 권한 전달 |
| Agent | 도구 선택 결과 검증, 실행, 재검색, 종료 상태 관리 | 허용한 도구와 횟수·시간·토큰 예산만 실행 |
| Retrieval | 문서 필터, Dense·BM25·RRF·reranker 결과 반환 | 문서 ID·버전·청크 ID·점수·출처 유지 |
| LLM provider | Ollama 또는 vLLM API 호출과 공통 응답 변환 | 최종 텍스트와 구조화된 도구 호출을 분리 |
| Knowledge pipeline | 원문 읽기, 버전 관리, 청크·색인 갱신 및 삭제 | 원본 권한과 유효한 버전만 검색에 노출 |
| Escalation adapter | 보류 이유와 근거 요약을 담당자에게 전달 | 초기에는 로컬 결과만, 실제 전송은 후속 계약 |
| Evaluation | 고정 데이터와 설정에 대한 품질·지연 평가 | 실험 설정과 데이터 버전을 결과에 포함 |

## 근거와 실패 처리

답변에는 검색한 유효 문서에서 확인한 내용만 인용한다. 문서 시행일, 폐기 여부, 접근 권한과 상충 규정 처리는 실제 문서 도입 전에 계약으로 정한다. 검색 결과가 비거나 모호하면 보류할 수 있어야 한다.

모델이 반환한 알 수 없는 도구, 잘못된 인자, 예산 초과, 검색·서빙 장애는 명시적 실패 상태로 남긴다. 모델 출력을 임의 코드나 SQL로 실행하지 않는다. 문서의 지시문은 검색 자료로 다루며 실행 권한으로 사용하지 않는다.

## 관찰과 비교

요청 ID를 기준으로 LLM 요청 메타데이터, 도구 호출, 도구 결과의 문서 ID, 검증 결과, 최종 상태와 소요시간을 연결한다. 인증 정보와 실제 HR 본문은 공개 로그에 포함하지 않는다. 내부 추론 전문을 수집할 필요 없이 동작을 재현할 수 있는 실행 기록을 남긴다.

Ollama와 vLLM의 API 차이는 provider 어댑터에 모은다. 교체 전 모델 ID·양자화·chat template·thinking·sampling·tool parser의 지원과 설정을 확인한다. 동일 입력의 도구 호출·구조화 출력·streaming·오류 처리를 각각 검증한다.
