# 실제 문서 형태를 닮은 가상 HR 원문 요구

2026-10-28 사용자: “가상 자료이지만, 실제 상황과 비슷하게 구성하는게 필요할 것 같아.”

## 현재 확인한 차이

- UI 기본 corpus는 수작성 15청크이며 각 text에 가상 자료 안내가 반복된다. 실제 연속 문서를 분할한 결과가 아니다.
- P006 source-v2에는 Markdown/PDF 원문과 실제 분할 산출물이 있지만, birthday.md 등에 “답변을 작성할 때는 … 함께 설명해야 한다”, “질문이 두 항목을 함께 묻는다면 … 근거를 함께 확인한다” 등의 RAG 학습 해설이 들어 있다.
- 따라서 기존 데이터를 회사 규정 문서의 현실적인 대용물이라고 설명해서는 안 된다. 안내 문구 제거만으로 이 차이가 해결되지 않는다.

## 다음 원문 버전에 필요한 구성

1. 먼저 독립된 규정 문서를 작성하고 그 파일에서 추출·청킹한다. 질문별 정답 청크를 먼저 쓰고 이어 붙이지 않는다.
2. 기존 정책 의미와 수치(생일 휴가 3개월/수습 제외/연1일/3영업일/팀장 승인 등)는 유지한다. 새 자격·예외·보상 규정을 임의로 만들지 않는다.
3. 문서 제목, 절/조항, 대상, 사용 기준, 신청 절차, 다른 제도와의 관계를 자연스러운 문서 구조로 배치한다. 제목은 실제 원문 위치에만 존재한다.
4. 가상 자료 안내는 문서 앞부분과 UI에 표시한다. 청크마다 본문 앞에 안내를 추가하지 않는다. 실제 원문에 들어 있는 안내는 추출 시 그대로 유지한다.
5. 모델에 답변법을 가르치는 문장, 평가 질문별 해설, 청킹/검색 학습 설명은 LEARNING_GUIDE 또는 평가 파일에 둔다. 검색 corpus에는 넣지 않는다.
6. 문서명/섹션명/원문 위치는 본문과 구분된 메타데이터로 관리한다. 제목을 검색 입력에 보강하는 실험은 별도 설정으로 표시하며 원문 quote를 변경하지 않는다.
7. 원문 분할 후 조건·예외가 다른 청크에 나뉘는지, 제목이 없는 후속 청크를 이해할 수 있는지, 생일 포인트와 생일 휴가를 혼동하는지 확인한다. 어려운 구성을 일부러 정답에 맞춰 재배치하지 않는다.
8. 기존 15청크와 source-v2 및 평가 이력을 보존하고 새 버전으로 분리한다. corpus 변경은 새 색인·원문 기반 평가 근거와 함께 관리한다.

## 규정 본문 형식 예시

```text
생일 특별휴가 운영 규정

1. 적용 대상 및 부여 일수
입사 후 3개월이 지난 재직자는 매년 생일 특별휴가 1일을 신청할 수 있다.
수습 중인 직원은 대상에서 제외한다.

2. 사용 기간
생일 특별휴가는 생일이 속한 달의 근무일에 사용한다.
해당 월을 넘겨 이월하거나 현금으로 지급하지 않는다.

3. 신청 및 승인
사용 3영업일 전까지 휴가 시스템에서 신청하고 팀장의 승인을 받아야 한다.
```

이 예시는 기존 정책 의미를 보존한 형식 제안이며 활성 corpus를 교체한 것이 아니다.
