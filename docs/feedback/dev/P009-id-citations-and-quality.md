# P009 인용 조립 적용과 남은 의미 품질

P009는 현재 Naive RAG에 적용했다. 모델은 답변/근거 ID를 생성하고 코드는 동일 요청의 불변 문맥 snapshot에서 원문 전체를 조립한다. 새 system-v3와 id_only_v2 계약, 요청별 enum 및 독립 코드 검증을 사용한다. PDF 줄바꿈과 공백은 원문 그대로 유지한다. 모델·retriever·문서/청크/색인·sampling은 변경하지 않았다.

실제 식대 BM25 k5와 PDF q06은 최초 P009 실행에서 정상 답변 및 정확한 전체 원문 인용이다. Dense14질문은 정확7/부분3/과도보류1 + 적정보류3. JSON/ID 구조는 14개 모두 통과했지만 q09는 팀장 승인 주장의 근거인 birthday-request를 선택하지 않았다. 전체 text 일치는 근거 선택의 의미적 완전성을 보장하지 않는다.

남은 사례:
- q03: 전달/인용된 eligibility의 연1일이 answer에서 빠짐.
- q07: 현장 장비 직무 제외, 팀장 승인 주체 누락.
- q08: remote-security가 전달됐으나 VPN/공용PC 규정이 없다고 과도 보류.
- q09: 별도 신청 안내/수습 제외 누락과 불완전한 인용 선택.

이들은 검색·문맥 전달·ID 형식 성공 이후의 의미 처리 문제다. 후속 평가에서 답변 완전성, 선택 인용의 주장 지원, 과도보류를 별도로 기록할 필요가 있다. P007/P008 초안이나 새 기능을 자동 승인하지 않는다. 실제 단일 실행 수치를 일반 정확도 향상으로 단정하지 않는다.
