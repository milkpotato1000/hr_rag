# dev 새 요구의 plan 접수

새로운 요구는 **dev 기록 → plan 검토 → P카드 준비 완료 → dev 정확한 채택 → 구현** 순서로 처리한다. dev 채팅의 새 요청이 plan 역할 전환이나 준비 검토 생략을 뜻하지 않는다. 기존 계약에 들어 있는 수정/검증은 계속할 수 있다.

## 분류

| 요청 | 처리 |
| --- | --- |
| 개념 설명, 현재 동작 확인 | 읽기/설명. 변경 약속이 생기면 아래로 분류 |
| 채택된 카드의 명시 요구를 충족하기 위한 버그 수정/회귀 검증 | 해당 P번호·조건·변경 영향·검증 기록 후 dev 진행 |
| 새 기능, corpus 기본값 변경, 새로운 정책/평가 기준, 학습 순서·폴더 변경 | 새 요구 접수 후 plan 판단 |
| 기존 카드에 포함되는지 불명확 | 요청 기록 후 plan에서 범위 판단; 해당 새 범위의 구현 보류 |

예: PDF 추출 오류로 문장이 누락된 문제를 기존 보존 계약에 맞게 고치는 것은 수정이다. 현실적인 PDF 원문으로 corpus를 교체하거나 새 청킹 방식을 추가하는 것은 새 범위다. 기존 계약·증거는 요구 변경으로 덮어쓰지 않는다.

## dev 접수

요청 내용을 임시 UTF-8 텍스트 파일에 작성하고 dev 작업폴더에서 실행한다. 공개 저장소에 적합한 가상/비민감 내용만 기록한다.

```sh
python3 scripts/plan_intake.py request \
  --title '요청을 식별할 제목' \
  --request-file /tmp/hr-rag-request.txt \
  --source '사용자 요청 날짜/채팅과 문맥' \
  --impact '관련 P번호, 기존 범위와 다른 점, 코드·데이터·평가 영향'
```

`docs/feedback/dev/requests/R날짜-식별자.json`이 생성된다. 생성은 로컬 파일 기록이며 자동 커밋/push/메시지/구현을 하지 않는다. 요청 파일을 검토해 dev에 커밋하고 기존 push 권한으로 공유한다. plan은 커밋된 dev 요청을 읽는다. 사용자는 파일을 다시 복사해 전달할 필요가 없다. 기존 요청을 수정/삭제하지 말고 원 요청 ID를 명시한 정정 요청을 새로 만든다.

## plan 검토

```sh
python3 scripts/work_queue.py --owner all
python3 scripts/plan_intake.py list
python3 scripts/plan_intake.py review R20261028-0123abcd \
  --disposition linked --cards P010 \
  --reason '이 카드에 반영할 범위와 결정 이유' \
  --review-reference '관련 준비 검토 또는 결정 문서 경로'
```

예시 ID는 실행용 요청이 아니다. 실제 대기열의 ID를 사용한다. plan만 검토 파일을 쓸 수 있다. 기존 검토 개정은 변경 이유를 남기며 직접 편집하고, 요청 본문 hash가 달라지면 대기열은 CHANGED로 재검토를 요구한다.

- `linked`: 기존/새 P카드에 반영. 초안 연결은 구현 승인이 아니다.
- `covered`: 이미 채택한 계약 범위에 포함된다고 판단. P카드·구체 조건·재검증 범위를 근거로 남긴다.
- `deferred`: 이유와 재검토 조건을 남겨 보류.
- `rejected`: 적용하지 않는 이유를 기록.

linked/covered는 실제 존재하는 P카드를 연결해야 한다. dev 진척을 plan에 병합할 필요는 없다. 검토 파일과 관련 P카드를 plan에 커밋하고, 준비 검토를 마친 카드만 준비 완료로 등록한다. dev는 기존 병합·정확한 채택 절차를 따른다. 초안/보류/제외 요청은 실행하지 않는다. 현재 실행 중인 별도 승인 작업은 새 요청 하나 때문에 모두 중단하지 않는다.

## 검사와 한계

기존 contract guard는 dev의 plan 소유 파일·검토 결정·P카드 요구 변경을 거부한다. 새 요청 파일의 필수 필드와 기존 커밋 대비 수정/삭제도 검사한다. 검사 대상은 worktree/index/실제 push 커밋이며 검토 결과는 plan 소유 경로에서 보호한다. queue는 누락된 연결 카드, 잘못된 형식, 변경된 요청 hash를 검사하고 미검토 요청을 표시한다.

이 로컬 하네스가 자유 형식 사용자 대화나 모든 코드 diff의 의미를 자동 판정하지는 않는다. **새 요구인지 분류하고 구현 전에 접수하는 책임은 AGENTS 규칙을 읽는 에이전트에 있다.** 요청 등록 누락이나 dev 에이전트가 임의로 plan 브랜치를 사용하는 행위를 Git만으로 완전히 막는다고 주장하지 않는다. 역할 규칙과 검토 기록·정확한 채택을 함께 사용한다. 다른 채팅으로 자동 메시지를 보내거나 대기 중인 plan 채팅을 깨우지 않는다.

이전 일반 Markdown 피드백은 그대로 보존한다. 기존 내용을 일괄 새 요청으로 재등록하지 않으며, 앞으로 새 실행 요구는 구조화된 요청 기록을 함께 남긴다.
