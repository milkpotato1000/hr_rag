# 선택 확장 경계

코어는 Git/Python 기록, 계획 채택, 큐, 사용자 중지와 결정 대기를 관리한다.
Asana, 외부 협업 도구, 특정 서비스의 버전 확정, 호스트 메시징은 기본 설치 대상이 아니다.

| 확장 | 코어에서 받을 정보 | 확장이 지켜야 할 경계 |
| --- | --- | --- |
| 업무 도구 동기화 | 커밋된 P카드/상태/증거 | 기존 카드 조회, 중복 방지, 사용자 권한, 별도 매핑 |
| 서비스 버전 승인 | plan 소유 승인 장부와 검증 결과 | 실제 서비스 API 실행 전 권한 확인, 도메인별 검사 |
| 세션 메시징 | PENDING 인계와 커밋 문서 | 실제 수신자 확인, 명시 권한, 성공/수신 근거로 상태 갱신 |

권장 배치: plugins/<adapter>/에 코드·지침·테스트를 두고 프로젝트별 매핑은 별도 관리한다.
비밀값은 저장소 밖에 둔다. 회사 계정/보드 ID/예산/고객 데이터/운영 권한을 범용 템플릿에 넣지 않는다.
기존 post-commit/post-merge 훅은 보존하고 충돌을 검토한다. 코어 설치는 기존 외부 연동을 제거하지 않는다.
훅에서 미반영 상태를 알리는 것과 외부 서비스에 실제 쓰는 것은 구별한다.

이 문서는 어댑터 설계 계약이다. 등록 API, 자동 플러그인 로더, Asana 연결 또는 서비스 승인
엔진을 제공한다고 주장하지 않는다. 도메인별 확장은 별도 계획과 승인 범위에서 구현한다.

## 호스트 메시징 절차 어댑터

[직접 전달 절차](workflow-controls.md)의 인간 권한·대상 확인→커밋 문서/PENDING→실제 발송→
SENT→실제 수신 응답 확인→ACK를 따른다. 호스트가 실제 제공하는 목록·읽기·발송·대기 도구를
사용하며 특정 도구의 존재를 추정하지 않는다. 이 어댑터는 문서 절차이며 코어의 자동 전송기나
새 API가 아니다. 명시 지시 또는 검증 가능한 인간 위임과 도구가 있으면 직접 전달을 수행한다.
위임이 없는 상황에 이를 기본 발송 권한으로 적용하지 않는다.

대상 식별·권한·전달 시도·전송/수신 근거는 이벤트에 연결된 비민감 문서에 기록한다.
공개 문서에는 실제 개인 채팅 ID·비밀·다른 프로젝트 요구를 넣지 않는다.
수신 증거는 송신자의 read/wait 관찰로 확보할 수 있다. 수신자가 허가 없이 다른 채팅에
메시지를 보내 ACK를 되돌리는 구조를 요구하지 않는다. 전송 불명/미응답은 근거와 현재 상태를
남기며 무한 재시도나 ACK 핑퐁을 만들지 않는다. 권한/도구 부재 시 파일 인계로 남긴다.
