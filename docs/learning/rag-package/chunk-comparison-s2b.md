# 청킹 비교가 실행 전에 멈췄을 때

[네 방식 비교 보고서](../../verification/p032-s2b/report.html)의 이번 결과는 **검색 미실행40건**이다. 의미 청킹의 첫 임베딩 작업이 SDK 오류로 실패해 이후 고정·재귀·구조·의미 방식의 검색 비교까지 진행하지 않았다. 세 규칙 방식의 기존 경계는 [S2a 안내](chunk-boundaries-s2a.md)에서 계속 볼 수 있다.

프로세스가 종료 코드0을 반환했지만 응답 JSON에는 `embedding_sdk_failed`가 있었다. 종료 코드만 확인했다면 실패 뒤에도 다음 검색을 실행할 수 있었다. 이번 runner는 오류를 기록하고 다음 요청을 막았다. 567개 단위를 요청했고 worker1개가 시작·종료됐지만, 실제 완료 단위 수는 미확정으로 남겼다.

모델을 호출하지 않는 후속 import 진단에서는 `torch`가 필요한 `typing_extensions`를 찾지 못했다. 설치 폴더에서 해당 파일과25개 패키지의 METADATA/RECORD가 없음을 확인했다. 언제 왜 없어졌는지는 확인되지 않았다. 모델 파일 hash와 상위 SDK 버전이 맞아도 전체 실행 환경의 정상 동작을 보장하지 않는 사례다.

학습할 때는 세 상태를 구분한다.

| 상태 | 이번 사례 | 해석 |
| --- | --- | --- |
| 요청·실패 | 의미 경계567단위, worker1개 | 처리 완료 수는 미확정 |
| 미실행 | 네 방식×10질문 | 검색 지표 N/A, 0점이 아님 |
| 기존 성공 | S2a 규칙3종 경계 | 이번 검색 비교의 성공 결과가 아님 |

따라서 지금은 “의미 청킹이 나쁘다” 또는 “고정 청킹이 더 좋다”고 결론 낼 수 없다. 비교가 실행된 뒤에는 같은 질문에서 branch union, 최종 후보20개, top5, 실제 전달 문맥의 필수 사실 회수를 차례대로 봐야 한다. 이번에는 이 값들이 모두 미측정이다. 새 청크의 관련성 주석도 없으므로 chunk Recall/MRR/nDCG를 계산하지 않는다.

실패 기록과 원래 실행 시계·한도를 보존하고 독립 환경 복구 검토를 접수했다. 현재 환경을 임의로 재설치하거나 모델을 재시도하지 않았다. 별도 준비 검토와 정확 채택 이후에만 재개하며, 답변 생성·LLM 청킹·평가기·Drive 실험은 계속 별도 단계다. [개발 증거](../../verification/p032-s2b/README.md)에서 상세 진단을 확인할 수 있다.
