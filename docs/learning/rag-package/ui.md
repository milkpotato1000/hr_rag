## 실행

UI가 포함된 dev wheel을 설치한 새 환경에서 시작합니다. 기존 설치 안내의 P028 고정 소스에는 UI가 없습니다. UI 소스·배포물 hash는 [P029 검증 기록](../../verification/p029/installation.json)과 완료 커밋 기록을 확인하세요. 빌드 의존성과 설치 방법은 기존 안내와 같습니다.

```sh
rag-lab init --out /원하는/새실습폴더
rag-lab serve --workspace /원하는/새실습폴더 \
  --sources /원하는/새실습폴더/sources.json \
  --llm-config /원하는/새실습폴더/llm-local.json \
  --llm-config /원하는/새실습폴더/llm-api.json
```

터미널에 나온 `http://127.0.0.1:8765`를 엽니다. 이미 사용 중이면 `--port 8766`처럼 명시적으로 바꿉니다. 다른 서버를 종료하거나 자동으로 다른 포트를 선택하지 않습니다. 서버 종료는 해당 터미널의 Ctrl+C입니다. 페이지를 닫아도 작업은 중지되지 않으며 서버 종료가 외부 요청 취소를 보장하지 않습니다.

설정·원문은 지정한 workspace 안에 두고 symlink는 사용하지 않습니다. `--sources`를 생략하면 업로드로 시작할 수 있습니다. 실제 credential은 workspace/Git 밖에 두며 브라우저에 키를 입력하지 않습니다. 작업은 `.rag-runs/ui/`에 저장됩니다. 개인 문서·질문·답변은 공개 Git에 추가하지 마세요.

## 비교하며 배우기

1. **문서:** 샘플을 선택해 snapshot을 만들고 원문 페이지를 확인합니다. PDF/TXT/MD 업로드는 등록 단계이며 파싱은 snapshot에서 실행합니다. 빈 PDF·추출 실패의 `needs_review`를 성공으로 취급하지 않습니다.
2. **모델:** 기본 로컬 설정은 EXAMPLE placeholder입니다. 미리보기는 가능하지만 실제 실행은 차단됩니다. 설정 복제에서 모델명·출력 길이·temperature를 저장할 수 있습니다. 로컬은 실제 digest/HF 출처·revision·quantization도 필요합니다. 저장은 모델 검증 성공이 아니며 기존 설정을 덮어쓰지 않습니다.
3. **청킹:** fixed/recursive/structure 중 하나와 크기·overlap을 선택합니다. 문자 수는 Unicode codepoint 기준입니다. 이모지 하나가 JavaScript 내부에서 두 단위여도 코어와 같은 수를 표시합니다. 페이지·청크·token은 서로 다른 단위입니다.
4. **검색:** 같은 질문에서 top-k와 문맥 예산을 바꿉니다. 후보 전체가 모델에 전달되지는 않습니다. 후보·포함·예산 제외 카드의 본문과 원문 위치를 대조하세요. 순위는 후보 순서, score는 BM25 점수입니다.
5. **답변:** 기본 ‘검색·입력 미리보기’는 답변을 생성하지 않습니다. 질문이나 모델·검색 조건을 바꾸면 다시 미리보기합니다. 실제 생성 결과의 인용은 검증한 원문 slice입니다. 인용이 정확해도 답변에 연간 일수 같은 조건이 빠질 수 있습니다.
6. **비교:** 같은 snapshot·질문에 설정 2~4개를 적용합니다. 먼저 청킹 방식 하나만 바꾸고 이후 크기·overlap·문맥 예산·모델을 각각 바꿉니다. 여러 조건을 함께 바꾸면 `changed_axes`를 확인하고 원인을 하나로 단정하지 않습니다. 실패 행도 남습니다.

예를 들어 생일휴가 질문에서 예산을 400자로 줄이면 관련 청크가 검색되어도 제외될 수 있습니다. 원문에 조건이 있는지 → 후보에 있는지 → 전달됐는지 → 답변이 표현했는지 순서로 보면 검색 실패와 답변 누락을 구분할 수 있습니다. 현재 품질 지표는 평가기·정답·qrels 미연결로 N/A이며 0점이 아닙니다. usage가 있어도 비용은 미측정입니다.

## 실제 연결을 사용할 때

등록 endpoint/key-env는 브라우저에서 변경하지 않습니다. API 연결은 사용자가 서버 시작 전에 provider 안내대로 설정하고, 새 endpoint가 필요하면 별도 config를 등록합니다. Ollama identity는 사용자가 설치한 모델의 `ollama show 모델명`과 로컬 `/api/tags` 응답의 digest, 실제 HF 원본·revision·quantization을 대조합니다. UI가 alias에서 출처를 추측하지 않습니다. 현재 작업에서는 이 조회나 다운로드를 실행하지 않았습니다.

설정이 준비된 뒤 사용자가 별도로 `--allow-model-execution`을 지정한 서버를 시작하면 ‘실제 답변 생성’을 명시적으로 실행할 수 있습니다. API 선택 시 질문과 포함 문맥이 해당 provider에 전송될 수 있습니다. 비교는 최대 80회 요청이며 버튼 옆에 현재 상한을 표시합니다. 자동 재시도는 없습니다.

Drive는 workspace 안에 인증 참조 config를 준비하고 `--drive-config /실습폴더/drive-token-env.json` 등으로 등록합니다. 화면에서 지원 Drive 링크와 등록 인증을 선택합니다. 링크 미리보기는 인증·HTTP 호출 0회입니다. 실제 pull은 `--allow-drive-download`가 필요하며 버튼을 누를 때만 실행됩니다. URL/resourcekey는 영속 작업 기록에 저장하지 않습니다. OAuth 로그인은 [Drive 안내](drive.md)의 CLI 절차이며 이번 검증에서는 실제 계정에 접속하지 않았습니다.

## 상태와 지원 범위

한 번에 작업 하나만 실행됩니다. 같은 요청 ID는 재실행하지 않으며 새로고침은 이력을 조회합니다. 서버가 중단되면 진행 작업은 다음 시작에 `interrupted`로 남고 자동 재개하지 않습니다. 입력·설정 파일이 바뀌면 stale 오류가 나므로 새 서버에서 명시적으로 등록합니다. 원문 위치 조회도 저장된 hash를 검사합니다.
