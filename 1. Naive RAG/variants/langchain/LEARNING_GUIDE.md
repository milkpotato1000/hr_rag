# LangChain으로 학습하고 별도 실험에서 비교하기

현재 기본 학습 화면은 http://127.0.0.1:8001/ 이며 LangChain으로 단일 실행한다. 질문 후 검색 → 전달 문맥 → 답변/인용을 대조하고 검색 방식·K·예산을 한 번에 하나씩 바꾼다. 구현별 차이를 보고 싶을 때만 상단 **실험 → 구현 비교**(`/experiments/implementation`)로 이동한다. “학습으로 돌아가기”를 누르면 LangChain 기본 화면으로 복귀하며 실험 결과/Direct 선택은 이어지지 않는다. 실행 중 앱 메뉴는 잠기고 새로고침은 자동 질의를 실행하지 않는다.

이번 실습은 기존 Naive RAG를 같은 검색기·데이터·프롬프트·모델로 연결하는 구조 변경이다. 구현·설치·반복 실행은 Codex가 맡고, 사용자는 예상과 결과 해석에 집중한다.

1. 같은 질문을 두 구현으로 실행한다. top-k, 문맥 예산과 검색 방식을 함께 확인한다.
2. 검색 ID·순서·점수를 비교한다. 다르면 답변 이전에 원인을 찾는다. LangChain을 도입했다는 이유로 검색 결과가 달라져야 하는 것은 아니다.
3. 모델에 전달한 청크, 제외된 청크, 실제 messages와 요청별 인용 ID enum을 본다. 검색 결과가 같아도 문맥 구성이 바뀌면 공정한 구현 비교가 아니다.
4. 답변의 필수 조건을 직접 체크한다. 원문 인용에만 있는 사실은 답변에 포함된 것으로 세지 않는다. 출처 ID가 유효한지와 선택한 출처가 주장을 지지하는지를 구분한다.
5. 시간은 검색/질문 임베딩/생성/모델 load를 나눠 본다. 이 환경은 BGE와 Qwen을 번갈아 로드하므로 두 모델이 모두 메모리에 상주한다고 가정하지 않는다. 화면 한 번의 실행은 정식 반복 평가와 다르다.

## 실제로 살펴볼 사례

- 생일 휴가 종합 질문: 자격·수습 제외·연1일·생일 달 근무일·신청 기한/절차·승인을 원문과 대조한다. 연1일이 인용에만 있어도 본문 누락은 남는다.
- 재택 자격 질문: 현장 장비 운영 직무 제외와 승인 주체인 팀장을 빠뜨리지 않았는지 본다.
- 공용PC/VPN 질문: 필요한 근거가 전달됐는데도 보류하면 과도 보류다.
- 생일 포인트 질문: 별도 신청/승인을 설명했는지, 승인 주장을 실제 선택한 인용이 지지하는지 본다.
- 교육 휴가 질문: 요청한 내용을 맞혔더라도 덧붙인 연차 신청 기한이 선택 인용으로 뒷받침되는지 확인한다.

P011 구조 보존 비교는 완료했고 P012는 기본 화면과 실험의 동선을 분리했다. 이 사례를 고치려고 구현 비교 중 프롬프트·청킹·검색 알고리즘을 함께 바꾸면 LangChain 효과와 구분할 수 없다. 품질 최적화는 후속 계획에서 한 변수씩 진행한다.

## 판정 읽기

`ADOPT_LANGCHAIN`은 고정20개 case의3회 비교에서 case별 품질 저하를 관찰하지 않았고 계약/안정성 검사를 통과했다는 뜻이다. 기존 누락이 모두 해결됐다는 뜻이나 모든 미래 질문의 통계적 동등성 보장은 아니다. `KEEP_DIRECT`는 관찰된 저하, `INCONCLUSIVE`는 유효한 비교 이후에도 남는 의미 판정 불확실성을 뜻한다. 미구현·미실험을 완료 판정으로 처리하지 않는다.

작업 순서는 P012 기본 학습/실험 분리 완료 → 별도 공개 설치형 plan-dev 하네스 제작 → HR RAG Hybrid → PDF 추출·청킹 실습이다. 청킹 실습에서는 고정 크기, 재귀, 의미 기반, 제목/섹션 기반과 overlap을 분리해 바꾼다. 설치형 하네스는 별도 프로젝트에서 준비하며 이 HR RAG 작업에서 자동 시작하지 않는다.
