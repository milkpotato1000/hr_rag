에 주소 확인 상태를 연결하여 같은 요청이 중복 처리되지 않게 한다. 주소를 정정했다는 통지를 
받았다는 이유로 근무 날짜에 대한 팀장 승인까지 완료된 것으로 표시하지 않는다. 변경 내용을 안
내할 때에도 등록 정보 정정의 결과인지 근무 신청의 결과인지 구분한다.
RM-06 기기 정보의 정정과 확인 기록
신청자와 회사 지급 기기의 연결 정보가 잘못 표시되었다는 문의가 있으면 담당자는 화면의 기기 
식별 정보와 확인 가능한 지급 내역을 비교한다. 같은 직원에게 연결된 예전 기기가 표시되는 경우
에는 현재 사용하는 기기와 과거 기록을 구분하고, 예전 기록을 단순히 지워 지급 이력을 알 수 없
게 하지 않는다. 기기 교체가 있었는지, 표시 이름만 달라졌는지, 다른 직원의 항목이 잘못 연결되
었는지를 확인한 뒤 정정 범위를 정한다. 정보 확인을 위해 문의한 내용은 재택 신청의 해당 항목
과 연결하되, 기기의 비밀번호나 내부 문서 내용을 신청 설명에 적게 하지 않는다. RM-03@v4의 
회사 지급 기기 사용 조건은 정보 정정 과정에서도 유지하며, 지급 여부를 확인하지 못한 기기를 임
의로 확인 완료 상태로 바꾸지 않는다. 문의자가 기기 정보의 정정만 요청한 경우에는 이를 새로운
 재택 날짜 신청이나 기존 승인 취소로 처리하지 않는다.
기기 정보가 바로잡힌 뒤에는 어느 항목을 수정했는지와 그 정정이 어떤 신청에 연결되는지를 기
록한다. 화면에 반영되기 전에 안내가 먼저 전달된 경우에는 실제 반영 상태를 확인하여 안내와 화
면의 차이를 설명한다. 동일 오류가 다른 날짜의 신청에도 나타나면 관련 기록을 찾아 연결하되, 각
 신청의 승인 내용을 한꺼번에 변경하지 않는다. 사용 가능한 회사 기기가 확인되었다는 사실만으
로 VPN 사용 여부도 확인된 것으로 기록하지 않고 두 항목을 분리한다. 기기 확인이 끝났다는 안
내에 근무 장소나 날짜까지 승인되었다는 의미를 덧붙이지 않는다.

RM-07 VPN 연결 확인과 장애 접수
VPN 사용에 문제가 있다는 연락을 받으면 담당자는 연결이 되지 않는 상황인지, 연결 상태가 화면
에 잘못 표시되는 상황인지, 접속하려는 문서를 찾지 못하는 상황인지 구분하여 기록한다. 서로 다
른 문제를 하나의 장애로 묶으면 회사 지급 기기의 확인과 VPN 연결 확인이 뒤섞일 수 있으므로 
어떤 항목을 확인했는지 남긴다. 통상적인 상태 확인으로 문제를 파악할 수 없을 때에는 발생 시점
과 화면에 나타난 현상을 확인 가능한 범위에서 기록하고 관련 담당 업무로 연결한다. 다만 장애를
 알렸다는 이유로 RM-03@v4의 회사 VPN 사용 조건이 면제되었다고 안내하지 않으며, 공용 컴퓨
터를 이용해 내부 문서에 접근하도록 임시 우회 방법을 제시하지 않는다. 확인 과정에 필요한 기기
 구분은 RM-06@v4의 기기 정보와 연결하고, 신청자에게 비밀번호나 업무 문서의 실제 내용을 재
택 신청란에 옮겨 적도록 요구하지 않는다. 장애 접수는 기술적인 상태 확인에 관한 기록이며 팀장
 승인이나 근무 장소 등록을 대신하지 않는다.
연결이 복구되었다는 연락을 받으면 복구 확인 시점과 최초 장애 접수 시점을 구분하고, 어느 문제
가 해결되었는지 기록한다. 다른 문제가 남아 있다면 전체 장애가 해소된 것처럼 표시하지 않는다.
 재택 신청 화면의 오류와 VPN 연결 장애가 동시에 발생했을 때에는 각각의 처리 내역을 서로 연
결하되 하나의 완료 표시로 합치지 않는다. 기기 연결 정보의 정정만 끝난 상태에서 실제 접속까지
 확인했다고 안내하거나, 접속이 되었다는 사실만으로 예정된 재택 날짜가 승인되었다고 알리지 않
는다.
