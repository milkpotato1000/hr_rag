 정책 자료로 사용하지 않고, 요약과 원문이 다르면 원래 기록과 신청자의 설명을 대조한다. 접수된
 시점, 내용이 정정된 시점, 검토를 위해 전달된 시점은 서로 구분하여 기록하며 TR-01@v4의 승
인 기한과 승인 주체를 유지한다.
팀장의 검토 결과를 받으면 어떤 신청과 어떤 일정에 대한 결과인지 확인한다. 승인 또는 추가 확
인 요청이 여러 날짜의 신청과 함께 전달된 경우에는 각 결과의 적용 대상을 식별하고 다른 출장에 
같은 결과를 복사하지 않는다. 승인 내용에서 확인되지 않은 방문지나 날짜는 자동으로 승인 범위
에 포함하지 않으며, 승인 기록과 현재 신청 내용이 다르면 그 차이를 확인 중인 사항으로 남긴다. 
추가 확인이 필요한 경우에는 이미 확인한 내용과 아직 필요한 설명을 구분하여 안내하고, 원래 요
청이 유실되지 않도록 보완 내용과 연결한다. 신청자가 검토 중에 일정을 변경하면 변경 전후를 함
께 전달하여 어느 버전을 대상으로 검토하는지 분명히 한다. 내용 확인 담당자가 바뀌어도 팀장 승
인 주체를 임의로 바꾸지 않으며, 업무 인계는 승인 권한의 이전으로 표시하지 않는다. 일정표에 연
차나 재택근무 문의가 포함되어 있으면 TR-02@v4에 따라 별도 항목으로 구분하고, 출장 승인 결
과를 그 항목들의 결과로 전파하지 않는다.
처리 결과를 신청자에게 안내할 때에는 요청을 식별할 수 있는 정보, 확인된 출장 일정, 승인 기록
과의 관계, 남아 있는 확인 사항을 함께 적는다. 접수 확인이나 자료 보완 안내만 이루어진 경우에
는 승인 완료라는 표현을 사용하지 않는다. 통지 내용의 날짜가 신청 내용과 다르다는 연락을 받으
면 최초 제출본과 정정 이력, 팀장 검토 결과를 순서대로 대조하여 차이가 생긴 지점을 확인한다. 
단순한 안내 오입력은 수정한 내용을 명시해 다시 안내하고, 실제 신청 일정이 바뀐 경우에는 변경 
요청과 기존 승인 내용의 관계를 확인한다. 통지 수신 여부가 확인되지 않을 때에는 이미 보낸 안
내 기록을 찾아 재전달 여부를 기록하되, 같은 승인 결과를 여러 번 별도 승인으로 계산하지 
않는다. 신청자가 답변 일부에만 이견을 제시하면 그 항목을 특정하여 확인하고 다른 항목의 처리 
상태까지 임의로 되돌리지 않는다. 최종 안내에는 확인을 마친 범위를 적어 비용이나 다른 제도까
지 모두 승인되었다고 오해하지 않도록 한다.
TR-05 방문 순서와 세부 일정의 변경
신청 후 방문 순서나 이동 일정이 달라지면 담당자는 신청자가 변경하려는 항목을 기존 일정과 대
응시킨다. 방문지 표기의 오입력을 바로잡는 것인지 실제 방문 장소를 바꾸는 것인지 구분하고, 변
경 전후의 날짜와 장소를 같은 기록에서 확인할 수 있게 한다. 일정표 파일이 새로 전달되었다는 
이유만으로 그 안의 모든 항목을 변경 요청으로 간주하지 않으며, 신청자가 바꾸려는 부분을 확인
한다. 여러 방문지 중 일부만 변경하려는 경우에는 나머지 일정을 유지하는지 확인하여 전체 출장 
취소나 새 신청으로 잘못 처리하지 않는다. 변경된 설명이 아직 협의 중이면 잠정 문의로 표시하고
 확정된 신청 내용에 바로 덮어쓰지 않는다. 기존 신청이 TR-04@v4의 검토 단계에 있으면 정정
된 내용을 해당 요청과 연결하여 전달하고, 이미 승인 결과가 있는 경우에는 변경된 부분과 승인 기
록의 관계를 별도로 확인한다. 담당자는 일정 변경을 안내받았다는 사실만으로 새 날짜가 승인되
었다고 표시하지 않는다.
여러 사람이 서로 다른 일정표를 전달한 경우에는 파일을 받은 순서만으로 최종본을 결정하지 않
고 신청자의 현재 요청과 각 자료의 작성 시점을 대조한다. 동일한 파일 이름을 사용하더라도 내용
이 다른 경우에는 변경된 항목을 구분하여 기록한다. 신청자가 이전 일정으로 돌아가겠다고 알리
면 과거 파일을 조용히 복원하지 않고 현재 요청의 변경 이력을 남긴다. 일정 정리가 끝난 뒤에는
