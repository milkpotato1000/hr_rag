RM-08 승인 날짜의 변경과 신청 철회
재택 날짜 변경 요청을 받으면 원래 승인 또는 검토 대상 날짜와 변경하려는 날짜를 연결한다. 같
은 주 안의 날짜 변경인지 대상 주 자체가 달라진 것인지 먼저 구분하고, RM-02@v4의 주간 횟수
와 승인 기한을 각각 확인할 수 있도록 기록한다. 이미 다른 재택 신청이 있는 주로 날짜를 옮기려
는 경우에는 관련 신청들을 찾아 중복 여부를 대조하되, 서로 다른 주의 일수를 임의로 합산하여 하
나의 주간 한도로 안내하지 않는다. 신청자가 후보 날짜를 문의한 단계에서는 문의와 실제 변경 의
사를 구별한다. 변경 의사가 확인되면 원래 요청을 유지한 채 변경 요청을 연결하여 팀장에게 전달
할 내용을 정리하고, 담당자의 연결 작업이 끝났다는 사실을 변경 승인으로 표시하지 않는다. 날짜 
변경과 함께 주소 변경을 알렸다면 RM-05@v4의 등록 정보 처리와 별도로 연결하여 두 변경의 현
재 상태가 각각 보이게 한다.
신청 철회를 요청한 경우에는 대상 날짜와 요청을 확인하고, 다른 날짜의 승인을 함께 취소하지 않
도록 범위를 구분한다. 철회가 접수되었지만 화면에 반영되지 않은 상태와 실제 기록 정리가 끝난 
상태를 따로 안내한다. 단순 중복 신청을 정리하려는 경우에는 정상 신청이 어느 기록인지 확인한 
뒤 중복 표시를 붙이며, 중복을 제거했다는 안내가 모든 재택근무 신청의 철회를 뜻하지 않도록 설
명한다. 이전 주의 철회 처리를 현재 주의 승인 여부에 자동으로 적용하지 않는다.
RM-09 알림 누락과 담당 업무의 인계
팀장의 결과가 기록되어 있으나 신청자가 알림을 받지 못했다고 문의하면 담당자는 요청의 식별 
정보, 기록된 결과, 발송된 알림의 대상을 비교한다. 알림의 수신 여부를 확인하는 과정에서 승인 
결과 자체를 새로 작성하지 않고, 기존 결과가 어떤 요청에 관한 것인지 먼저 확인한다. 통상적으로
는 확인된 기록을 같은 요청에 연결하여 안내하지만 알림 시스템 장애로 발송 이력이 확인되지 않
는 경우에는 현재 확인할 수 있는 결과와 알림 확인의 한계를 구별해 전달한다. 이 경우에도 새 안
내가 원래 승인 시점을 대신하지 않도록 원래 기록과 연결한다. 다른 사람의 요청에 관한 메시지가
 잘못 연결된 것으로 보이면 해당 신청의 결과를 그대로 적용하지 않고 잘못된 연결을 정정한다. 
기록의 전달 오류와 날짜 변경은 RM-08@v4의 변경 처리와 구별하여 안내하고, 메시지를 다시 보
냈다는 이유로 별도 재택근무일을 생성하지 않는다.
담당자가 자리를 비우거나 업무를 인계하는 경우에는 현재 신청 목록과 미확인 항목을 함께 넘긴
다. 접수된 신청을 단순히 새 담당자 이름으로 다시 등록하지 않고 원래 요청의 식별 관계를 유지
한다. 신청자가 이미 답한 기기·주소 관련 질문은 확인된 기록을 인계하여 반복 문의를 줄이고, 실
제로 확인하지 않은 값은 이전 담당자가 확인했다고 추정해 완료 표시를 붙이지 않는다. 새 담당자
가 설명을 보완할 때에는 추가 확인한 부분과 기존 확인 사항을 구별해 남긴다.

지를 먼저 특정한다. 신청자에게 표시된 근무일, 승인 내역의 날짜, 집계 화면의 기준 시점을 구별
하여 기록하고, 합계 수치만 비교해 오류 여부를 정하지 않는다. 조회 시점 차이로 최근 변경이 아
