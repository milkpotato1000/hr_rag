# 청킹을 관찰하는 순서

이 실습은 동일한 가상 PDF를 읽어 얻은 38,582자 canonical에서 청크 경계만 바꿉니다. 실제 회사 규정이나 법률 자문이 아닙니다. 긴 본문, 절차, 예외, 조항 참조를 가진 23쪽 규정집입니다. 가상 자료 안내는 원문에 있는 위치에만 남아 있고 모든 청크에 반복해서 붙이지 않습니다.

## 1. PDF와 추출 텍스트부터 대조하기

원문 영역에서 생일 특별휴가 → BD-01을 선택하세요. PDF의 줄바꿈, 제목, 페이지 footer가 추출 결과에도 남습니다. 파서가 만든 줄바꿈과 청킹 경계를 구분하세요. 원문 범위는 Unicode 문자 [start,end)이며 PDF 좌표가 아닙니다. 청크에서 원문 위치를 누르면 해당 페이지의 텍스트 범위를 강조합니다.

## 2. 같은 크기에서 오버랩만 바꾸기

고정400/0과 고정400/80의 저장 결과를 비교하세요. 청크 수, 평균 길이, 중복 비율을 보고 조건 문장이 경계에서 나뉘는지 확인합니다. 고정 방식은 창을 size-overlap만큼 이동합니다. 나머지 방식은 먼저 분할한 뒤 앞 청크의 시작을 넘지 않는 범위에서 왼쪽으로 최대80자 확장합니다. 노란 영역은 중복된 왼쪽 문맥입니다.

오버랩은 누락을 줄일 수 있지만 색인 크기·임베딩 입력·검색 결과의 중복도 늘릴 수 있습니다. 여러 청크에 같은 조건이 반복돼도 근거 회수율은 한 번만 계산합니다.

## 3. 경계를 정하는 기준 바꾸기

- 고정 크기: 200/400/800자. 원문의 문장 의미를 고려하지 않습니다.
- 재귀: 최대400자 안에서 문단 → 문장 → 공백 경계를 우선하고, 없으면 잘라냅니다.
- 제목/섹션: 실제 본문 제목 시작에서 분리합니다. 긴 조항은 재귀로 나눕니다. 목차 문자열을 본문 제목으로 취급하지 않습니다. 짧은 조항을 임의로 합치지 않습니다.
- 임베딩 의미: 문장/문단 후보 단위의 BGE-M3 인접 코사인 거리와 길이 조건으로 경계를 고릅니다. 의미 기반이라는 이름만으로 더 정확하다고 가정하지 않습니다.
- LLM: Qwen3:4b가 경계 후보 ID를 선택하고 Python이 원문을 그대로 자릅니다. 모델의 요약문을 청크로 저장하지 않습니다. 최대800자, 선호200~400자이지만 실제로 매우 짧게 분리할 수 있습니다. 선호 길이 위반을 조용히 합쳐 감추지 않습니다.

## 4. 같은 질문·검색기로 A/B 비교하기

각 실행의 BM25 또는 Dense 색인을 준비한 뒤 A/B를 선택하세요. 먼저 “생일 휴가의 자격과 신청 기한, 사용 기간을 함께 알려 주세요.”로 비교합니다. 입사3개월·수습제외·연1일·생일달·3영업일전·팀장승인이 필요한 원문 위치가 어디에 있는지 확인하세요. 이 실습은 답변을 생성하지 않으므로 답변 누락과 검색 누락을 혼동하지 않습니다.

다음으로 “생일휴가 시스템 장애로 접수 확인이 안 되면 어떤 임시 기록을 남기며 승인 면제가 되나요?”를 선택하세요. 절차와 예외가 서로 다른 청크에 있을 수 있습니다. top5 전체가 필요한 근거를 함께 덮는지 관찰하세요. 검색 점수가 높아도 필요한 모든 조건을 찾았다는 뜻은 아닙니다.

K=5와 K=20을 비교한 뒤 문자 예산400/800/1600을 비교합니다. 같은 K에서 큰 청크가 유리한 이유가 단순히 더 많은 원문을 가져왔기 때문인지 확인하세요. 문자 예산은 top20 순서에서 통째로 담을 수 있는 청크만 선택하며, 안 맞으면 다음 청크를 살핍니다. 겹친 문자도 비용에 포함합니다. 실제 LLM 전달 문맥이 아닌 시뮬레이션입니다.

## 5. 지표를 해석하기

주 지표는 필수 fact 회수율입니다. 한 fact의 모든 필수 span을 여러 청크의 합집합이 덮어도 성공입니다. 대체 근거는 OR, 한 근거 집합 내부 span은 AND입니다. 다른 대체 집합의 일부를 섞어 성공으로 처리하지 않습니다. 전체 필수 근거를 모두 회수한 질문 비율과 부분 coverage도 구분합니다.

Precision/Recall/MRR/nDCG는 보조 지표입니다. 청킹을 바꾸면 관련 청크의 분모도 바뀝니다. MRR이 높아도 다른 필수 근거는 누락될 수 있습니다. 정답이 없는 임의 질문과 문서 범위 밖 질문은 N/A이며 0점으로 간주하지 않습니다.

tuning26개에서 고른 후보를 고정한 후 holdout12개를 확인합니다. holdout을 보고 재선정하지 않습니다. 작은 합성 세트에 대한 결과이므로 실제 회사 문서 전체에서의 우수성으로 일반화하지 않습니다. 검색 결과는 향후 사람 승인 정답을 대신하지 않습니다.

## 6. 실행과 비용

‘저장 결과 보기’는 성공 산출물 재생이며 새 모델 호출이 아닙니다. ‘새로 실행’은 새 invocation입니다. LLM overlap80은 같은 llm0 경계의 파생 결과로 호출0회입니다. 독립 LLM 반복은 overlap0의 새로운 추론 세 번으로 측정합니다. 화면 이동/새로고침은 작업을 취소하지 않고, 서버 재시작은 미완료 작업을 INTERRUPTED로 남깁니다.

계획의 사전 probe까지 포함한 영구 ledger가 LLM219회/7200초, 임베딩32000item/1800초, 검색2328회의 상한을 지킵니다. 미확정 timeout 이후 자동 재호출하지 않습니다. 로컬 호출량·토큰·시간을 비용으로 보고 금액은 추정하지 않습니다. 예산을 초기화하거나 늘리는 새 실험은 계획 검토 대상입니다.
